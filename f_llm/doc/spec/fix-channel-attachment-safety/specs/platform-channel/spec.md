# Spec Delta

## MODIFIED Requirements

### Requirement: 电子邮件发送

系统 SHALL 基于 `f_email` 实现邮件通道的发送：按账号配置的 SMTP 主机与凭据发信，支持携带附件（以本地文件路径给出），返回结果 MUST 指明是否成功及失败原因。附件路径 MUST 落在允许根目录内、MUST 是普通文件、MUST NOT 是符号链接；未配置允许根目录时 MUST 拒绝带附件的发送。

#### Scenario: 成功发送

- **WHEN** 对已配置账号发送一封含收件人、标题、正文、若干附件的邮件，且附件都在允许根目录内
- **THEN** 通道调用 SMTP 发送并把成功结果返回给调用方，附件随信投递

#### Scenario: 发送失败

- **WHEN** SMTP 拒绝或网络异常
- **THEN** 返回失败结果并携带错误信息，不抛出未捕获异常给流程

#### Scenario: 附件文件不存在

- **WHEN** 指定的附件路径不存在或不可读
- **THEN** 该次发送返回失败并指明是哪个文件，不发出缺附件的邮件

#### Scenario: 附件越出允许根目录

- **WHEN** 附件路径不在 `llm_channelSendRoots`（或其回落 `llm_fileSandboxPath`）之内
- **THEN** 发送被拒绝并返回明确原因，SMTP 不被调用

#### Scenario: 未配置允许根目录

- **WHEN** 既没有 `llm_channelSendRoots` 也没有 `llm_fileSandboxPath`，而消息带附件
- **THEN** 发送被拒绝，错误说明「附件目录未配置」，而不是静默发出无附件邮件

### Requirement: 电子邮件接收（含附件）

系统 SHALL 基于 `f_email` 实现邮件通道的接收：按数量拉取最近邮件，返回标识、发件人、标题、正文、接收时间与附件清单；调用方给出下载目录时 MUST 把附件落盘到该目录并在结果中给出路径；接收 MUST NOT 改变服务端的已读状态。落盘文件名 MUST 只保留单一文件名部分（不含任何目录段），落盘目标 MUST 位于下载目录之内，同名冲突 MUST 顺延且 MUST NOT 覆盖已有文件。

#### Scenario: 拉取最近邮件

- **WHEN** 对已配置账号请求最近 N 封邮件
- **THEN** 返回不超过 N 条消息，每条含标识、发件人、标题、正文与接收时间

#### Scenario: 附件元数据

- **WHEN** 邮件带 2 个附件且未指定下载目录
- **THEN** 结果中列出两个附件的文件名与大小，不落盘

#### Scenario: 附件落盘

- **WHEN** 指定下载目录且附件可读
- **THEN** 附件被写入该目录，结果中给出本地路径，原文件名冲突时顺延为 `-2` 且不覆盖已有文件

#### Scenario: 附件名含路径穿越

- **WHEN** 远端附件名是 `../../etc/passwd` 或含 `\` 分隔符
- **THEN** 落盘只使用最后一段文件名，且最终路径仍在下载目录内

#### Scenario: 附件不可写

- **WHEN** 下载目录不存在或不可写
- **THEN** 该封邮件的附件标记为未下载并携带原因，正文与其它邮件照常返回

#### Scenario: 不置已读

- **WHEN** 拉取邮件后再次拉取
- **THEN** 邮件的已读状态与拉取前一致

## ADDED Requirements

### Requirement: 附件落盘的并发安全

同一进程内多路同时落盘 MUST 串行化「选择文件名 + 创建文件」这一对动作，保证任一附件不被另一路覆盖。

#### Scenario: 并发写入同名附件

- **WHEN** 两路收信同时把同名附件写入同一目录
- **THEN** 得到两个不同文件名，两份内容都在，先写者不被覆盖
