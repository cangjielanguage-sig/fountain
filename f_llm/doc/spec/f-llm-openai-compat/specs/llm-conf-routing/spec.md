# Spec Delta

## Purpose

用一张配置描述「哪个平台的哪个模型」，进程内只装载一次并按周期刷新；同一个统一模型名可以由多个平台提供，请求按权重分配流量，出问题的平台在连续失败后自动临时下线并在冷却后恢复。

## ADDED Requirements

### Requirement: 平台配置模型

每条配置 SHALL 描述一个平台上的一个模型：平台标识、统一模型名、平台模型名、访问地址、鉴权凭据、温度、是否强制思考、附加配置、启用开关、权重。

#### Scenario: 必填字段缺失
- **WHEN** 某条配置的平台标识、平台模型名或访问地址为空
- **THEN** 装载时丢弃该条并记录一条告警，其它配置正常可用

#### Scenario: 附加配置落库为 JSON
- **WHEN** 一条配置的附加配置含 `{"tokenThreshold":"80000","thinking":"toggle"}`
- **THEN** 写入数据库的列值是合法 JSON 对象文本，读回后按字符串键值对还原

### Requirement: 装载过滤

系统 SHALL 只装载 `enabled = true` 且 `weight > 0` 的配置；`weight <= 0` 与停用等价，不得参与调度。

#### Scenario: 权重为零等同停用
- **WHEN** 某平台配置 `enabled = true`、`weight = 0`
- **THEN** 该平台不出现在任何候选列表里，也不产生告警

#### Scenario: 权重为负
- **WHEN** 某平台配置 `weight = -1`
- **THEN** 该平台不被装载

### Requirement: 配置只装载一次并按周期刷新

系统 SHALL 在首次使用时装载全部配置，此后按配置的刷新周期整体替换快照；刷新 SHALL NOT 阻塞或中断在途请求，刷新失败 SHALL 保留旧快照。

#### Scenario: 周期内只查一次库
- **WHEN** 刷新周期为 60 秒，周期内连续发起 10 次调用
- **THEN** 配置来源只被查询 1 次

#### Scenario: 刷新后新配置生效
- **WHEN** 刷新周期过后又发起一次调用，且数据库里新增了一个平台
- **THEN** 新平台参与本次调度

#### Scenario: 刷新失败保留旧快照
- **WHEN** 配置来源抛异常
- **THEN** 调用继续使用刷新前的配置成功完成，并记录一条错误日志

### Requirement: 权重调度

同一统一模型名的多个平台 SHALL 按权重比例分配流量，权重为相对份额而非绝对次数。

#### Scenario: 三比一分配
- **WHEN** 两个平台权重分别为 3 和 1，发起大量调用
- **THEN** 流量比例接近 3:1（允许统计误差）

#### Scenario: 轮询算法
- **WHEN** 调度算法配置为轮询，两个平台权重均为 1
- **THEN** 相邻两次调用落在不同平台

### Requirement: 连续失败临时下线

系统 SHALL 按平台配置粒度统计连续可重试失败；达到阈值后该平台在冷却期内不参与调度，冷却到期自动恢复。状态 SHALL 只保存在内存，不修改持久化配置。

#### Scenario: 达到阈值后跳过
- **WHEN** 某平台连续 5 次可重试失败，阈值为 5
- **THEN** 后续调用不再选择该平台，直到冷却结束

#### Scenario: 冷却到期自动恢复
- **WHEN** 冷却时间结束
- **THEN** 该平台重新出现在候选列表里，失败计数清零

#### Scenario: 成功一次即清零
- **WHEN** 某平台累计 4 次失败后成功一次
- **THEN** 失败计数归零，不会在下次失败时触发下线

#### Scenario: 参数错误不计入
- **WHEN** 某平台返回 400
- **THEN** 该次失败不增加失败计数

### Requirement: 饱和阈值按平台计算

饱和 token 阈值 SHALL 作为单条配置的属性读取，不得跨平台取最小值或最大值；值为 0 表示该平台不限制。

#### Scenario: 各平台阈值独立
- **WHEN** A 平台阈值为 80000、B 平台为 200000，本次选中 A
- **THEN** 是否饱和按 A 的 80000 判断

#### Scenario: 阈值为零不裁剪
- **WHEN** 选中的平台阈值为 0，且上下文远超该模型常见上限
- **THEN** 不因饱和触发裁剪
