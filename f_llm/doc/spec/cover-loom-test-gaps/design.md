# Design

## Context

R5 的 5 条缺口是审查在「测试覆盖矩阵」里逐条对出来的，产品代码本身没有缺陷（本轮 5 条用例首次运行即全绿）。

## Decisions

### D1. 只加用例，不改产品代码

补测的价值在于「钉住现有语义」，若顺手改代码就分不清「测试发现问题」还是「测试迁就实现」。

### D2. `memoryCall` 用全链路断言，而不是「不含 failed」

旧断言只能证明「没报错」，证明不了「删的是对的那条」。alter：add 拿到 id → remove 得 `true` → 再 remove 得 `false`。

### D3. 附件失败用「目标其实是文件」触发

比构造权限错误更稳定（不依赖 umask/root）；绝对路径用例同时验证「净化 + 落盘」端到端，而不只是 `bareName` 单测。

### D4. 并发竞态不补自动化

原因：`auto-*` 命名是 check-then-act，要稳定复现必须注入同步点（生产代码加钩子）或用线程压测（flaky）。批次 8 已用固定时钟覆盖「撞名顺延」这条**确定性**分支；真正的并发窗口留作已知限制，写在 `todo.md`。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| `testSaveFailsWhenTargetIsAFile` 依赖「文件系统不允许把文件当目录」 | Linux/Windows 都成立；用例已在本机通过 |
| 新增用例拉长全量时间 | 5 条均为内存/临时目录操作，毫秒级 |
