# Design

## Decisions

### D1. 用「已处理素材的最大 at」而不是「now - 安全窗口」

安全窗口（例如 `now - 3600`）能缓解，但仍然是猜测：素材积压超过窗口时照样丢。
用已处理的最大 `at` 是**精确**的——水位线只承诺「这个时间点之前的都看过了」。

**替代**：把 `load` 改成游标分页（按 `at` 递增取）。否决——需要改存储查询契约（memory.list 不支持按 at 过滤），
改动面远大于收益；批大小 + 精确水位线已经能保证不丢。

### D2. 只前进不后退

并发或乱序素材（同一个 `at` 被两轮各取一次）可能让 `advanced` 小于当前水位；加 `>` 判断避免把水位拉回去。

### D3. 没有时间戳时回落到 now

知识文档 `at = 0`（存储里没有写入时间），本身由「已消费 docId」去重，不依赖水位线；
此时保留旧的按轮次推进，避免水位线永远停在 0 导致每轮全量重扫。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 素材 `at` 与真实时间不同源（测试/定时任务传 0 或固定值） | `at == 0` 走 now 分支；固定值场景水位线停在该值，下一轮仍取 `> 该值` 的素材，不会丢 |
| `advanced` 落后于真实处理进度 | 只影响「下一轮多看几条」，宁可重复也不漏 |

## 迁移

无。
