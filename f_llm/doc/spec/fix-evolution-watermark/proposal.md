# Proposal

## Why

R4 的最后一条是真丢数据：

- `SkillEvolutionJob.load` 每轮最多取 `limit=500` 条素材；
- `run` 结束时无条件 `state.markRun(now)`——水位线直接推到「当前时间」。

于是当新增素材超过 500 条时，**多出来的部分 at 更小、下一轮 `since` 更大，被永久过滤掉**，
既不会被处理，也不会报错。

## What Changes

- 水位线改为推进到「本轮真正处理过的最大 `at`」（取成功经验 / 失败经验 / 知识候选的最大值），
  并且**只前进不后退**；没有任何带时间戳的素材时，仍按 `now` 推进（保持原行为）。
- 单轮 `limit` 的语义从「可能造成永久跳过」变成「本轮批大小」：剩下的下一轮还能取到。
- 补 1 条用例：`at = 10/20/30`、`now = 5000` → 水位线是 **30** 而不是 5000。

## Capabilities

### Modified Capabilities
- `loom-flow`：演进水位线 MUST 只覆盖真正处理过的素材。

## Impact

- 代码：`src/loom/SkillEvolutionJob.cj`（一处推进逻辑）。
- 行为：素材少于单轮上限时与原来等价（都推到最后一条的 `at`）；超量时不再丢样本。
- 测试：新增 1 条；全量基线 655。
