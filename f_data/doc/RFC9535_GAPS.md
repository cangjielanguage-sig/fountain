## ⚠️ 部分覆盖 (Partial)

| 特性 | 差距 | 影响 |
|------|------|------|
| **`count()` filter 比较** | 路径级 `$.count()` 可用但 filter 内 `count(@.*) > 5` 不支持 | 无法在 filter 中计数比较 |
| **`value()` filter 比较** | 路径级 `$.value()` 可用但 filter 内 `value(@.name) == X` 不支持 | 无法转换 nodelist 为值比较 |
| **`length()` filter 函数** | 当前 `@.name size N` 支持但不支持 `length(@.name)` 语法 | 路径级 `$.length()` 可用 |
| **字符串逃逸** | `\uXXXX` 等由 cangjieLex 处理，未专项测试 | 可能隐式支持 |
| **重复节点** | 理论上 flatMap 链式迭代器保留重复，无专项测试 | 需验证 |

## ❌ 未覆盖 (Missing)

| 优先级 | 特性 | 说明 | 工作量 |
|--------|------|------|--------|
| **P1** | **标准化路径 (Normalized Paths)** | RFC 要求为匹配节点生成唯一路径 `$['name'][0]` | 大 — 需新增路径跟踪机制 |
| **P2** | **filter 内 count/value 比较** | `count(@.*) > 5` 和 `value(@) == X` | 中 — 需解析函数+比较组合 |
| **P2** | **null 在集合运算中** | `in [null]` 不支持 | 小 — 加 IDENTIFIER("null") case |
| **P3** | **I-JSON 数字范围校验** | 整数需在 `[-(2^53)+1, (2^53)-1]` | 小 — 加边界检查 |
| **P3** | **对象/数组结构相等** | `==` 比较 array/object 结构 | 中 — 递归结构比较 |
| **P3** | **复杂函数表达式** | 嵌套函数、函数返回值参与比较 | 大 — 需重构 filter 表达式引擎 |
| **P3** | **`length()` 函数语法** | 支持 `length(@.name)` 语法 | 小 — 别名 |

## 测试覆盖缺口

| 场景 | 原因 |
|------|------|
| 重复节点 `$[0,0]` | 无测试 |
| 字符串逃逸 `'\n'` `'\u0041'` | 无测试 |
| 切片 `[1:1]` (start==end) | 无测试 |
| 对象成员顺序不确定性 | DataObject 未在 path 测试中覆盖 |

## 架构限制

1. **节点无位置信息** — `DataPathNode.get()` 只返回 `Data` 值，不携带路径信息。实现标准化路径需要修改整个接口链。
2. **Filter 表达式引擎** — 当前是宏+parseExpr 的组合，函数调用返回值的比较需要扩展表达式解析能力。
3. **数据模型差异** — RFC 基于 JSON 值，当前基于 `f_data.Data` 类型系统，`DataNone` vs absent 的语义差异可能导致细微行为不同。
