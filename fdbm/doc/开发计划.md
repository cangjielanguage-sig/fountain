# fdbm 开发计划（**TDD**）

> 依据 `fdbm/doc/详细设计.md`。开发方式：**每个公共成员先写失败用例（红）→ 最小实现（绿）→ 重构**；每个 Step 结束 `cjpm test` 全绿再进入下一步。
> 用例文件与被测包同包（`*_test.cj`）；`@Test` / `@TestCase` / `@Assert`（`std.unittest`）。

## 通用约定

- **测试替身**：
  - `FakeNodeAccessor`（`src/resources/fake_accessor_test.cj`）：实现 `NodeAccessor`，用 `f_mockdb` 建真实 `DatabasePool`，**记录**每次下推的 SQL、参数、使用的池名与广播次数——执行器/路由用例的主断言源；
  - `FakeBootScript`：临时目录里的 `boot.sh` 文本，用于 `BootScriptWriter` 用例；
  - **协议/会话用例必须走回环连接**：`f_net.SocketBuffer` 没有公开构造（主构造器需要真 `TcpSocket`），因此 `FdbmHandler`/`SessionRegistry` 不能靠"桩造 buffer"驱动；用例在进程内起 `Server<DataAny>`（端口先用 `TcpServerSocket(bindAt: 0)` 探空闲端口）+ `Client<DataAny>`，用真实连接取得 `SocketBuffer`。真正的协议语义断言仍是"发请求 → 收响应载荷"。
- **`f_mockdb` 的已知边界**（用例设计必须遵守）：只有进程级单一驱动、URL 仅被记录（**没有多节点/多库隔离**——"哪个库收到 SQL"只能由记录器断言）；夹具线程隔离且**没有真事务**，`Transaction` 只做状态机与文本断言（`begin/commit` 是否下发由记录器断言）；`DatabasePool` 借用时执行 `checkSql`，夹具必须让任何 SQL 都返回至少一行，否则连接被判无效。
- **平台限定**：优雅停止（`kill -15`）用例只在 Linux/macOS 执行（`f_base.ExitCallbacks` 在 Windows 是空实现），Windows 用 `fboot shutdown <pid>` 或跳过该用例。
- **提交**：每个 Step 一个提交；提交前统一 LF。
- **DoD**：① 该 Step 用例全绿；② 详细设计 §13"必须固化的不变量"在对应 Step 有用例；③ 与设计文档出现偏差时同提交改文档。

## 阶段 5：`fountain::fdbm.route`

### Step 5.1 七种 `PartitionAlgorithm`

| 公共成员 | 先行用例 | 实现要点 / 验收 |
| --- | --- | --- |
| `StepPartition(name/partition)` | ① 步长 1000、id=1/999/1000/1001 → 库 0/0/1/1；② 越界 id（`0`/`-1`/`N*step+1`）→ `ROUTE_FAILED`（有效域 `[1, N*step]`，不回绕）；③ 构造空库列表、`step<=0`、`N*step` 溢出 → `PARTITION_CONFIG`；④ 非整数键（`'abc'`）→ `ROUTE_FAILED`（不猜测）；⑤ `'1001'` 与 `1001` 得到同一库（键规范化） | — |
| `HashPartition` / `Crc16Partition` / `Crc32Partition` / `Crc64Partition` / `MurmurPartition`（`name/partition`） | ① 同一 key 多次调用结果稳定；② 分布均匀性：10000 个 key → 每库占比 ∈ [0.5/N, 1.5/N]（N=4）；③ 整数与字符串 key 均可；④ 不满足 `Hashable`（hash 版）或 `ToString` 的 key → `ROUTE_FAILED` | CRC 用 `crc16/32/64` 顶级函数（`f_util`）；Murmur 用 `murmurHash` 取低 64 位 |
| `SubstringPartition(name/partition)` | ① `start=0,length=2` 时 `'AB-123'` 与 `'AB-456'` 同库；② `length=0` 从 `start` 取到末尾；③ 多字节字符按 Unicode 码点切分，不出现半个字符；④ 前导零、大小写不折叠；⑤ `start` 已不小于字符数 → `ROUTE_FAILED`；⑥ 五种 hash 与手工计算一致且跨实例稳定 | `toRuneArray()` 切片 → `String(Array<Rune>)`；`hashCode`/CRC/Murmur 取模前规范为非负 |
| `PartitionAlgorithmFactory.create` | 七个名字 → 正确实现类；`std`/`hash` 都映射 `HashPartition`；`substr` 必须带合法 `SubstringSpec`；未知 / 缺参数 → `PARTITION_CONFIG` | — |

### Step 7.1 `DbdSession` / `PinnedConnection` / `QueryCursor`

| `QueryCursor.next()` | ① **无预读（构造不取行）**：构造后立即断言物理 `next()` 调用次数为 **0**；② 3 行结果集连续 `next()` 序列为 `true,true,true,false`（**含第一次也推进**，物理 `next()` 恰好被调用 4 次，不跳行）；③ 空结果集首次 `next()` 返回 `false`（物理 `next()` 调用 1 次）；④ 耗尽后重复调用仍 `false` 且不再调用物理 `next()` | 无预读：推进即物理 `next()`（设计 §9.1 规则 1；跨段切换发生在 `next()` 内） |

| 多段串联（广播合并） | 两库各 2 行 → 服务端 `next()` 序列 `true,true,true,true,false`（行序=库序，段间不丢不重）；**前段为空**：A 段 0 行 + B 段 2 行 → 连续推进仍能读到 B 段的 2 行（**不跨段预取**，故不存在 `hasData` 概念）；任一段打开失败 → 整个查询失败（`ERROR`）且已打开的段全部关闭 | 设计 §9.1 规则 4 |

| `QueryCursor.close()` / `isClosed()` | 关闭后归还连接（假 accessor 断言 `PooledConnection.close()` 被调用）；幂等 | — |
