# fdbm 详细设计

> 需求来源：`.autocode/dbware.md`；共用代码来自 `f_dbd`（`fountain::f_dbd.common` / `.exception`）；参照实现：`f_rpc`（f_net 服务端用法）、`f_orm`（连接池与驱动加载）、`f_store`（缓存）、`f_concurrent.LoadBalance`（权重选择）。
> 版本基线：1.3.16。本文给出**包级定义、各包顶级声明、每个顶级声明的公共成员及调用关系**。

---

## 1. 模块定位与总览

`fdbm` 是可执行模块，是"数据库中间件"本体：

- 监听 TCP（默认 8112），接收来自 `f_dbd` 的 **CONSUME** 请求，按 **RESP**（成功）/ **ERROR**（失败）回应。
- 解析 SQL（INSERT / UPDATE / DELETE / SELECT / JOIN / SHOW / DDL / export / 会话控制），完成**水平分库路由、读写分离、负载均衡、全局表广播、ID 生成、分库缓存**。
- 通过 `f_dbpool.DatabasePool` 管理到物理库的连接；物理驱动从部署目录的 `driver/` 子目录动态加载（`std.reflect.PackageInfo.load`），且**必须只有一个驱动**。

### 1.1 数据流

```
f_dbd ──CONSUME(SqlPayload)──► FdbmServer(handler)
                                 │ decodeStrict 判别请求种类
                                 ▼
                          ExecutorDispatcher
             ┌───────────────┼────────────────┬──────────────┐
             ▼               ▼                ▼              ▼
        SqlParser      PartitionRouter    GlobalTableRouter  IdGenerator
             │               │                │              │
             └──────► 物理库名（RoutePlan） ◄──┘              │
                                 │                           │
                                 ▼                           │
                        DatabaseResources ──► DatabasePool（每物理库一个池）
                                 │            └─ Connection（读写权重选择）
                                 ▼
                          物理驱动（唯一）──► 物理数据库
                                 │
             ┌───────────────────┴────────────────────┐
             ▼                                        ▼
  QueryCursor（挂会话，逐行/逐列读）        UpdateResultPayload
             │
             ▼
      RESP(QueryResultServerPayload / 单元格 / DataBool) ──► f_dbd
```

## 2. 包结构

| 包 | 目录 | 职责 | 依赖（模块内） |
| --- | --- | --- | --- |
| `fountain::fdbm` | `src/main.cj` | 进程入口：注册子命令、启动 `App` | server |

| `fountain::fdbm.resources` | `src/resources/` | 物理节点/物理库模型、连接池构建、读写节点选择（`NodeAccessor`） | config / exception |
| `fountain::fdbm.route` | `src/route/` | 分库算法、分库规则、路由计划、分库缓存、全局表 | config / resources / exception |
| `fountain::fdbm.idmaker` | `src/idmaker/` | ID 生成器接口与 UUID / Snowflake / Sequence 实现 | resources / exception |
| `fountain::fdbm.sql` | `src/sql/` | 词法/语法解析、AST、参数绑定、会话控制语句 | exception |
| `fountain::fdbm.execute` | `src/execute/` | 语句执行器族、服务端游标、会话状态 | sql / route / resources / idmaker |
| `fountain::fdbm.server` | `src/server/` | `FdbmServer`、请求分发、会话注册表、驱动加载、优雅停止 | 全部 |

依赖方向自上而下无环；`sql` 不依赖 `route`（路由只读 AST），`execute` 是唯一的"粘合层"。

**可见性约定**：fdbm 是可执行模块，除需求明确要求可扩展的两个接口（`PartitionAlgorithm`、`IdGenerator`，声明为 `public`）外，其余顶级声明一律 `protected`（模块内可见，测试同模块可访问）。

## 3. `fountain::fdbm.config`

### 3.1 配置项总表

| 配置项 | 类型/默认 | 语义 |
| --- | --- | --- |
| `fdbm_port` | `UInt16` / `8112` | 监听端口 |
| `fdbm_db` | `name0@host1:port;name2@host2:port;...` | 物理节点清单；分号分隔，`@` 前是**中间件节点名**（非数据库名） |
| `fdbm_db_driver_<node>` | `String` / 无默认（必填） | 该节点的物理驱动名（`DriverManager` 中的名字） |
| `fdbm_db_database_<node>` | 逗号分隔 / 必填 | 该节点承载的物理库名；重名=参与负载均衡，不同名=参与水平分库 |
| `fdbm_db_username_<node>` / `fdbm_db_password_<node>` | `String` | 该节点凭据 |
| `fdbm_db_logicalDatabase_<logical>` | 逗号分隔 | 逻辑库 → 物理库列表；未配置的逻辑库视为包含全部物理库 |
| `fdbm_databasePool*` | 见 §3.4 | 物理库连接池参数 |
| `fdbm_loadbalance` | `random` / `roundrobin` | 节点选择算法 |
| `fdbm_loadbalance_weight_<node>` | `w,1;r;2` | 节点级读写权重（`w`=写权重、`r`=读权重；`w`/`r` 单独出现表示权重 1） |
| `fdbm_loadbalance_weight_<node>__<database>` | 同上 | 节点下**某个物理库**的读写权重（优先于节点级） |
| `fdbm_partition_step` | `Int64` / `1000_0000` | 步长分库的步长 |
| `fdbm_partition__<table>` | `'<logical>,<algorithm>,<column>'` | 某表的分库规则；`__` 后无表名报错退出 |
| `fdbm_global__<table>` | `'<logical>'` | 全局表所在的逻辑库 |
| `fdbm_idmaker` | `uuid,1` / `snowflake` / `sequence` | ID 生成器与参数（uuid 的版本号） |
| `fdbm_cache` | `Bool` / `true` | 是否开启分库缓存 |
| `fdbm_cache_expire` | `Duration` / 空=永久 | 缓存过期时间（`Duration.toString()` 格式，如 `1d`） |
| `fdbm_cache_size` | `Int64` / `0`=不限制 | 缓存 KEY 数量上限 |
| `fdbm_cachePath` | `String` / `<工作目录>/cache` | f_store 落地目录（**新增**，f_store 必须有路径） |
| `fdbm_driverDir` | `String` / `<工作目录>/driver` | 物理驱动动态库目录（**新增**，需求只描述"部署路径下的 driver 子目录"） |
| `fdbm_bootScript` | `String` / `<工作目录>/boot.sh` | 启动脚本路径（`export` 语句的落盘目标） |
| `fdbm_sessionSweepInterval` | `Duration` / `30s` | 断连会话巡检周期（**新增**，f_net 无断连回调） |
| `fdbm_shutdownTimeout` | `Duration` / `30s` | 优雅停止时等待在途请求的上限（**新增**） |
| `fdbm_checkDuration` | `Duration` / `30s` | 服务端 TCP 有效性检查周期（**新增**；`f_net.Server` 的 `checkDuration!` 必填，无默认值） |
| `fdbm_unavailableChecked` | `Int64` / `3` | 连续检查失败次数阈值（**新增**，传给 `Server` 的 `unavailableChecked`） |
| `fdbm_sequenceDatabase` | `String` / 逻辑库的第一个物理库 | `sequence` ID 生成器的分配库（**新增**，见 §7） |

> 全部经 `fountain::f_config.Config` 读取，因此天然支持环境变量、`--key=value` 命令行与 `Config.set` 三种来源；sm4 等加密配置与 `f_config` 一致（见 `fdemo/boot.sh` 的 `build` 函数）。
>
> **心跳与长语句（重要取舍）**：`f_net.Server` 在读循环里 `executors.call{...}.get{}` 是**阻塞**的，单条语句执行期间读不到客户端的心跳 ACK，连续 `fdbm_unavailableChecked` 次检查失败就会主动断开连接。因此 `fdbm_checkDuration` 默认取 **30s**（≈ 单条语句 90s 上限），超过该量级的语句必须调大该值；广播 DDL、逐行 INSERT…SELECT、大结果集首包都会受这条约束影响（列入 §12）。
>
> **默认值口径**：与 f_dbd 侧统一，取需求**示例值**为准（需求中"# 默认是…"注释与示例冲突按笔误处理，见 f_dbd 文档 §6.1 的登记）。

### 3.2 `FdbmConfig`（`protected struct`）

```cangjie
protected struct FdbmConfig {
    public static func getPort(): UInt16
    public static func getNodes(): Array<DatabaseNodeConfig>
    public static func getPool(): PoolConfig
    public static func getLoadBalance(): LoadBalanceConfig
    public static func getPartitions(): Array<PartitionRuleConfig>
    public static func getGlobalTables(): Array<GlobalTableConfig>
    public static func getIdMaker(): IdMakerConfig
    public static func getCache(): CacheConfig
    public static func getDriverDir(): String
    public static func getBootScript(): String
    public static func getSessionSweepInterval(): Duration
    public static func getShutdownTimeout(): Duration

    /** 启动期一次性校验：任一失败即记 ERROR 并结束进程（见 §13 启动自检清单） */
    public static func validate(confs: FdbmSettings): Unit

```

| 成员 | 语义 | 调用方 |
| --- | --- | --- |
| 各 `get*` | 单项或整块配置解析；解析失败抛 `FdbmException(CONFIG)`（含配置项名与原始值） | `FdbmServer` 初始化 |

### 3.3 配置模型类型

```cangjie
protected class DatabaseNodeConfig {          // 一个物理节点
    public let name: String                   // name0
    public let host: String
    public let port: UInt16
    public let driverName: String
    public let databases: Array<String>
    public let username: String
    public let password: String
    public func url(database: String): String // '<driver>://user:pwd@host:port/database'（凭据 % 编码）
}

protected class PoolConfig {                  // 连接池参数（fdbm_databasePool*）
    public let initSize: Int64                // 1
    public let minSize: Int64                 // 1
    public let maxSize: Int64                 // 1
    public let checkOnCreation: Bool          // false
    public let checkOnBorrowing: Bool         // true
    public let checkOnReturning: Bool         // false
    public let idleTimeout: Duration          // 0
    public let connectionLife: Duration       // 86400s
    public let checkInterval: Duration        // 300s
    public let connectTimeout: Duration       // 50ms
    public let maxWaiting: Duration           // 30000ms
    public let checkSql: String               // 'select 1'
}

protected class LoadBalanceConfig {
    public let algorithm: String              // 'random' | 'roundrobin'
    public func weight(node: String, database: String): NodeWeight   // 先查 database 级，再查节点级，缺省 1/1
}
protected class NodeWeight {
    public let write: Int64                   // 0 表示该节点/库不参与写
    public let read: Int64                    // 0 表示不参与读
    public func canWrite(): Bool
    public func canRead(): Bool
}

protected class PartitionRuleConfig {
    public let database: String               // 逻辑库名（config 值第 1 段）
    public let table: String                  // `__` 后的表名
    public let algorithm: String              // hash | std | crc16 | crc32 | crc64 | murmur | step
    public let column: String                 // 分库列名
}
protected class GlobalTableConfig {
    public let database: String               // 逻辑库名
    public let table: String
}
protected class CacheConfig {
    public let enabled: Bool
    public let expire: ?Duration
    public let size: Int64                    // 0=不限制
    public let path: String
}
protected class IdMakerConfig {
    public let kind: String                   // 'uuid' | 'snowflake' | 'sequence'
    public let arg: ?String                   // uuid 版本号等
}
```

### 3.4 连接池参数默认值说明

`PoolConfig` 取需求给出的默认值（`initSize=1`、`minSize=1`、`maxSize=1`、`checkOnReturning=false`、`connectionLife=86400s`、`connectTimeout=50ms`、`maxWaiting=30000ms`），构造 `DatabasePool` 时**显式传参**（`f_dbpool` 自身不读任何配置）。

### 3.5 `BootScriptWriter`（`export` 落盘）

```cangjie
protected class BootScriptWriter {
    public init(path: String)
    public func set(key: String, value: String): Unit   // Config.set(key, value) + 登记待写
    public func flush(): Unit                           // 原子写回脚本
}
```

- `set`：先 `Config.set([(key, value)])`（内存立刻生效，`f_config` 的 `REFRESHER` 机制可联动），再登记 `key → 最新的 export 行`。
- `flush`：定位脚本中的标记区块 `# ==== fdbm managed exports (do not reorder) ====`：
  - 区块内已有 `export <key>=...` → 整行替换；
  - 没有 → 在区块末尾追加 `export <key>=<value>`；
  - 文件中没有标记区块（首次启动的老脚本）→ 在文件末尾追加标记区块。
- 写回是**原子**的：写 `boot.sh.tmp` → 复制原文件权限位 → `rename` 覆盖；同时保留其余内容（注释、`start`/`stop` 函数）不动。
- 值中含换行或非安全字符时按 shell 单引号转义（`'` → `'\''`）。
- 语义：仅"未来的进程启动"会带上新值；当前进程只靠 `Config.set` 生效（与需求"修改配置项，并把配置项落到启动脚本中"一致）。

## 4. `fountain::fdbm.exception`

```cangjie
public class FdbmException <: BaseException {
    public prop code: DbdErrorCode            // 复用 f_dbd.common 的错误码，回包时直接映射 DbdErrorPayload
    public init(code: DbdErrorCode, message: String)
    public init(code: DbdErrorCode, message: String, caused: Exception)
    public init(code: DbdErrorCode, caused: Exception)
}
```

- 所有 fdbm 内部失败统一抛 `FdbmException`；`server` 层捕获后回 `Message.error(id, DbdErrorPayload(code, message, sqlState))`。
- 物理库的 `SqlException` 一律包成 `FdbmException(DB_ERROR, ..., caused)`，并透传 `sqlState`。

## 5. `fountain::fdbm.resources`

```cangjie
protected interface NodeAccessor {                       // 供测试注入假实现
    func selectRead(database: String): Connection
    func selectWrite(database: String): Connection
    func selectAllWrite(database: String): Array<Connection>
    func databases(): Array<String>
    func contains(database: String): Bool
    func readNodes(database: String): Array<String>      // 读节点池名（日志/测试用）
}

protected struct DatabaseResources <: NodeAccessor & Resource {
    // 键是物理库名；不同节点上同名物理库对应同一个 LoadBalance（负载均衡、读写分离）
    private let readNodes: HashMap<String, LoadBalance<Int64, Unit, Connection>>
    private let writeNodes: HashMap<String, LoadBalance<Int64, Unit, Connection>>
    private let pools: Array<DatabasePool>               // 与节点×库一一对应
    private let names: Array<String>                     // 全部物理库名（去重）

    public init(nodes: Array<DatabaseNodeConfig>, pools: PoolConfig, weights: LoadBalanceConfig)

    /** 从该物理库的读节点中按权重取一个连接（无读节点 → FdbmException(ROUTE_FAILED)） */
    public func selectRead(database: String): Connection
    /** 从该物理库的写节点中按权重取一个连接（无写节点 → FdbmException(ROUTE_FAILED)） */
    public func selectWrite(database: String): Connection
    /** 该物理库的全部写节点连接（全局表广播写用），调用方负责归还 */
    public func selectAllWrite(database: String): Array<Connection>
    public func databases(): Array<String>
    public func contains(database: String): Bool
    public func readNodes(database: String): Array<String>
    public func close(): Unit                            // 幂等：关全部池（不等待内部任务）
    /** 优雅停止用：逐池 `DatabasePool.closeAndAwait(timeout!)`，返回是否全部按期终止 */
    public func closeAndAwait(timeout!: Duration): Bool
    public func isClosed(): Bool
}
```

| 关键点 | 说明 |
| --- | --- |
| 池的粒度 | **每 `<host:port> + <physical database>` 一个 `DatabasePool`**（需求原文），池项 = 一条物理连接 |
| 权重语义 | 一个物理库同时配读写权重 ⇒ 同时进 `readNodes` 与 `writeNodes`；只配 `r` ⇒ 只进读；只配 `w` ⇒ 只进写 |
| 只读/只写库 | 由 `NodeWeight.canRead/canWrite` 决定是否注册进对应 LoadBalance |
| 配置错误 | `fdbm_loadbalance_weight_<node>_`（节点名后只有下划线）在 `FdbmConfig.validate` 阶段报 `FdbmException(CONFIG)` 并**结束进程** |
| 连接归还 | `select*` 返回的是 `PooledConnection`，调用方 `close()` 即归还——**且 `close()` 非幂等**（重复归还抛 `ConnectionException`），执行器必须在 `finally` 中恰好归还一次（除非游标持有到关闭）；池耗尽等待超时同样表现为 `ConnectionException`（映射 `TIMEOUT`） |
| 取连接的写法 | 统一走 `pool.connect()`（内部 `getConnection(timeout: connectTimeout).getOrThrow`）；`connectTimeout`/`maxWaiting` 的语义按 `f_dbpool`：`connectTimeout` 是取连接的超时，`maxWaiting` 只在调用方传 `Duration.Max` 时生效——fdbm 取连接使用前者 |
| 池关停（优雅停止专用） | `DatabasePool` 现提供 `closeAndAwait(timeout!)`：先 `pool.close()`，再 `awaitTermination(timeout)` 等内部任务收尾，最后幂等关闭 `Datasource`；源码注释明确"**宿主必须先归还全部借用者**再 await" ⇒ fdbm 的顺序必须是"关会话/游标（归还连接）→ 逐池 `closeAndAwait`"。`timeout` 必须为正且有限（`Duration.Zero`/`Duration.Max` 会被 `IllegalArgumentException` 拒绝）；普通 `close()` 不等待内部任务，仅用于非优雅场景 |
| 泛型实参修正 | 需求草图写 `LoadBalance<Int64, DatabasePool, Connection>`；`LoadBalance<W, D, R>` 的 `D` 是"被选中函数 `(D) -> R` 的入参类型"，与节点对象无关。本设计用 `<Int64, Unit, Connection>`，每节点注册 `{_ => pool.connect()}`，选择语义完全一致（与 f_dbd 文档 §6.4 同一处修正） |
| 负载算法接线（照 f_concurrent/f_net 的实测口径） | `LoadBalance<Int64, Unit, Connection>(0, algo)`：`random` → `Int64Weight(1, Σw)`；`roundrobin` → `RoundRobin<Int64>(step: 1, min: 1, max: Σw)`。**取值区间必须落在权重桶内部**——`min = 0` 或 `origin = min` 会永远命中第一个节点（仓库既有实测记录），用例固定"只有 node1 有权重 → 100 次全落 node1" |

## 6. `fountain::fdbm.route`

### 6.1 分库算法

```cangjie
public interface PartitionAlgorithm {
    prop name: String
    func partition<K>(key: K): String        // 返回物理数据库名
}
```

| 实现类 | `name` | 算法 | 依赖 |
| --- | --- | --- | --- |
| `public class StepPartition <: PartitionAlgorithm` | `'step'` | 整数 ID 按 `step` 分段：`dbs[(id - 1) / step]`（越界按取模回绕并记 WARN） | 无 |
| `public class HashPartition <: PartitionAlgorithm` | `'hash'` | `key.hashCode()` 取模 | `stdlib` |
| `public class Crc16Partition <: PartitionAlgorithm` | `'crc16'` | `crc16(key.toString())` 取模 | `f_util` 顶级 `crc16` |
| `public class Crc32Partition <: PartitionAlgorithm` | `'crc32'` | `crc32(...)` 取模 | `f_util` |
| `public class Crc64Partition <: PartitionAlgorithm` | `'crc64'` | `crc64(...)` 取模 | `f_util` |
| `public class MurmurPartition <: PartitionAlgorithm` | `'murmur'` | `murmurHash(data: key.toString())` 取模（`UInt128` → 取低 64 位） | `f_util` |

- 统一构造函数：`public init(databases: Array<String>)`（`StepPartition` 为 `init(databases, step: Int64)`；`HashPartition` 为 `init(databases, hashAlgorithm: String)` 以支持 `std`/`hash` 别名）。
- **泛型入参的运行时判定**：接口方法 `partition<K>(key: K)` 对 `K` 无约束（需求原文），实现内部把 `key` 装箱为 `Any`：`HashPartition` 要求 `is Hashable`（否则 `FdbmException(ROUTE_FAILED)`）；CRC/Murmur 走 `key.toString()`（对 `is ToString` 判定，不满足同样报错）。
- **键的规范化（唯一口径）**：路由层在调用算法前把分库键规范化为"**能无损解析为 `Int64` 就用 `Int64`（满足需求的 `ID.hashCode()`），否则用 `String`**"——即 `123` 与 `'123'` 归一为同一键，避免同一逻辑值因 SQL 字面量写法不同而落到不同分片；`StepPartition` 拿到的字符串若无法解析为 `Int64` → `FdbmException(ROUTE_FAILED)`（不猜测、不回绕）。
- 构造期校验：`databases` 非空（`FdbmException(PARTITION_CONFIG)`）。
- `protected struct PartitionAlgorithmFactory { public static func create(name: String, databases: Array<String>, step: Int64): PartitionAlgorithm }`：把配置里的算法名映射到实现类；未知算法名 → `FdbmException(PARTITION_CONFIG)`。

### 6.2 分库规则与路由

```cangjie
protected class PartitionRule {                     // fdbm_partition__<table> 解析结果
    public let database: String                     // 逻辑库
    public let table: String
    public let column: String
    public let algorithm: PartitionAlgorithm
}

protected class RoutePlan {
    public prop kind: RouteKind                     // Single | Broadcast | Unroutable
    public prop databases: Array<String>            // kind=Single 时长度 1
}
protected enum RouteKind { | Single | Broadcast | Unroutable }

protected class PartitionRouter {
    public init(rules: Array<PartitionRule>, cache: ?PartitionCache)

    /** 语句级路由：从 AST 中抽取分库列等值/IN 条件 → Single；全局表 → Broadcast；抽不到 → Unroutable */
    public func route(statement: SqlStatement, currentDatabase: String): RoutePlan
    /** 值级路由：查缓存 → 未命中用算法计算并写缓存 */
    public func routeByValue(rule: PartitionRule, value: String): String
    public func rule(database: String, table: String): ?PartitionRule
    public func isPartitioned(database: String, table: String): Bool
    public func close(): Unit
}
```

| 成员 | 语义与规则 |
| --- | --- |
| `route` | 单表语句：从 WHERE（INSERT 为 values/set 中该列）取分库列的**字面量集合**；恰好 1 个值 → `Single`；多个值（`IN`）→ 多库（`Single` 时须同库，否则 `Unroutable`）；取不到 → `Unroutable`（执行器按表规则决定"是否报错"）。JOIN：所有表的路由结果必须收敛到同一物理库（含全局表）→ `Single`；否则 `Unroutable`（错误信息给出两张表的库名）。 |
| `routeByValue` | 缓存键 `'<logical>.<table>.<column>:<value>'`，命中后**校验物理库存在**（`NodeAccessor.contains`）：存在→返回；不存在→删缓存并重算（需求"缓存中存在但数据库不存在则从缓存中删除"）。 |
| `Unroutable` 时的行为 | `UPDATE`/`DELETE` 缺分库列条件 → 报错（`ROUTE_FAILED`，错误文案提示补分库列）；`SELECT` 允许 → 广播到该逻辑库全部物理库并由执行器**合并结果**（见 §9.4，本期实现：`SELECT` 无分库条件时按库逐个查询、顺序合并，`hasData` 语义与单库一致） |

## 9. `fountain::fdbm.execute`

### 9.1 会话与游标

```cangjie
protected class DbdSession {
    public let id: String                       // '<remoteAddress>#<序号>'，日志用
    public let buffer: SocketBuffer             // f_net 连接（会话键）
    public var cursor: ?QueryCursor             // 当前打开的服务端游标（至多一个）
    public var pinned: ?PinnedConnection         // 事务期间 pin 住的写连接
    public var database: String                 // 当前逻辑库
    public func close(): Unit                    // 关闭游标、归还 pin 连接、回收资源（幂等）
}

protected class PinnedConnection {               // 事务状态
    public let connection: Connection
    public var transactionOpen: Bool
    public func close(): Unit                    // 归还连接
}

protected class CursorSegment <: Resource {      // 一个物理库上的结果集段
    public let statement: Statement              // 物理语句（保持结果集有效）
    public let result: QueryResult
    public let connection: Connection            // 借出的物理连接，段关闭时归还
    public func close(): Unit
}

protected class QueryCursor <: Resource {        // 服务端游标：单库=一段；广播查询=按库序多段串联
    public let columnInfos: Array<ColumnInfoImpl>
    public let hasData: Bool                     // 构造时跨段预取第一行的结果（true=第一行已就绪）
    public func next(): Bool                     // 段内推进；当前段耗尽切换到下一段（行序=库序）
    public func cell(index: Int64, bufSize: Int64): Data   // 列读；流列按 bufSize 分块
    public func close(): Unit                    // 关闭全部段并归还全部连接
    public func isClosed(): Bool
}
```

- **广播合并的唯一形态**：`SELECT` 无分库条件（`Unroutable`）时，`SelectExecutor` 为每个物理库建一个 `CursorSegment`，按库序串联成一个 `QueryCursor`；对客户端仍然只有"一个游标 + 首包 + 逐行/逐列读"，无需扩展协议。

游标规则（与 f_dbd 文档 §3.5/§5.6/§7.3 对齐）：

1. **构造即预取第一行**：`QueryCursor` 构造时调用一次物理 `result.next()`，结果即 `hasData`；因此客户端的**首次** `next()` 不需要发请求（f_dbd 本地返回 `true`），之后的 `NEXT_ROW` 才真正推进物理游标——预取与推进必须成对，否则会跳行。
2. 新语句到达先关旧游标；`CLOSE_CURSOR` **恒回 `DataNone`（幂等）**——包括空结果集、以及已经被新语句关掉的游标；只有"列读 / NEXT_ROW"在无游标时才回 `ERROR(CURSOR_STATE)`。
3. 连接断开由 §10.3 的巡检回收。
4. 多段游标：行序 = 库序；任一段在**打开阶段**失败 → 整个查询失败（`ERROR`），已打开的段全部关闭（不做部分成功）。`hasData` 跨段预取（多段都为空才是 `false`）。

### 9.2 执行结果与分发

```cangjie

    public prop cursor: ?QueryCursor             // select（含空结果集；游标持有结果集与连接）
    public prop columns: Array<ColumnInfoImpl>   // select 的列信息（即使 hasData=false）
    public prop hasData: Bool                    // 首包 QueryResultServerPayload.hasData（= cursor.hasData；广播合并时=各库之和）

    public init(router: PartitionRouter, globals: GlobalTableRouter,
                resources: NodeAccessor, idMakers: IdMakers,
                bootScript: ?BootScriptWriter, config: FdbmConfig)
    /** 唯一入口：完整 SQL 文本 → 执行结果（内部：parse → bind → route → 分发执行器） */
    public func execute(session: DbdSession, sql: String, params: Array<DataAny>): ExecutionOutcome

```

| 执行器（`protected class`，均 `public func execute(session, statement): ExecutionOutcome`） | 职责 |
| --- | --- |
| `SelectExecutor` | 路由 → `selectRead` 借连接 → `prepareStatement(sql).query()` → 组装 `QueryCursor`（连接由游标持有到关闭）；`Unroutable` 时按 §6.2 的广播合并规则执行 |
| `InsertExecutor` | `insert into ... select ...` 拆解为逐行 INSERT（需求）；分库列缺失时用 `IdGenerator` 生成并回填；`values` 多行按行分组路由（逐行执行、同一事务内） |
| `UpdateExecutor` | 路由（JOIN 收敛规则同 SELECT）；无分库列条件 → `ROUTE_FAILED`；执行前按需求校验缓存中的分库键是否仍指向存在的物理库 |
| `DeleteExecutor` | **先查受影响行的分库键**（`select <column> from t where ...`）→ 逐库执行删除 → 删除缓存条目（需求原文顺序） |
| `ShowExecutor` | `show databases` 返回逻辑库清单；`show tables` 按驱动方言取表清单（见 §9.5） |
| `DdlExecutor` | `create table` / `alter table` 广播到该逻辑库全部物理库；全部成功才算成功（失败：已执行的库不回滚，回 `DB_ERROR` 并列出成功/失败库名——列为限制） |
| `ExportExecutor` | `export k=v` → 校验配置项名合法 → `BootScriptWriter.set/flush` |
| `SessionCtlExecutor` | 会话控制语句：pin/解 pin 写连接，透传执行；未 pin 时对 `commit`/`rollback` 报 `TX_STATE` |

### 9.3 事务与 pin

- `begin`/`start transaction`：若会话未 pin → `selectWrite(database)` 取连接并 pin；随后所有语句（含 SELECT）都走该连接（**read-your-writes**），直到 `commit`/`rollback`。
- `savepoint` / `rollback to` / `release`：透传到 pin 连接。
- `commit`/`rollback`：执行后解 pin 并归还连接。
- 未 pin 的普通语句：每次借还（读走 `selectRead`、写走 `selectWrite`），实现读写分离。

### 9.4 全局表与广播

| 操作 | 行为 |
| --- | --- |
| 读全局表 | 走 `selectRead`（任一副本） |
| 写全局表（INSERT/UPDATE/DELETE） | 广播到该逻辑库的**全部**物理库（`selectAllWrite`）；每库独立事务，全部成功才算成功；部分成功 → `DB_ERROR` 并列出成功/失败库（无两阶段提交，列为限制） |
| 与分片表 JOIN | 全局表可参与任意分片的 JOIN（广播副本保证本地可见） |

### 9.5 SHOW 与方言

- `show databases`：返回 `fdbm_db_logicalDatabase_*` 与节点配置推导出的逻辑库集合（按名称排序）。
- `show tables [db] [like '...']`：由驱动名决定查询方式（**唯一方言相关处**）：
  - `mysql`：`show tables`（可带 `like`）；
  - `postgres` / `opengauss`：`select table_name from information_schema.tables where table_schema='public'`（`like` 转成 `table_name like ...`）；
  - 其它驱动：报 `UNSUPPORTED_SQL`，错误信息中给出"未支持的驱动名"。
- 结果复用 `QueryCursor` 通道返回（列名统一为 `table_name`）。

## 10. `fountain::fdbm.server`

### 10.1 `FdbmServer <: Resource`

```cangjie
protected class FdbmServer <: Resource {
    public init(settings: FdbmSettings)
    public func start(): Unit          // 阻塞：bind → 注册 handler → 等信号优雅退出
    public func stop(): Unit           // 优雅停止（幂等，见 §10.4）
    public func isClosed(): Bool
}
```

启动顺序（全部失败都在**接受连接之前**报错退出）：

1. `FdbmConfig.validate`（跨项校验；清单见 §11）：`fdbm_partition` 后无 `__<表名>` → 报错退出；`fdbm_loadbalance_weight_<node>_`（只有下划线）→ 报错退出；逻辑库/分区/权重引用的物理库或节点不存在 → 报错退出。
2. `DriverLoader.load(driverDir)` → 唯一 `Driver`；逐节点 `driver.open(url, opts)` 建 `Datasource`。
3. `DatabaseResources`（建池，`initSize` 条连接在池构造时建立）。
4. `PartitionRouter`（建规则 + `PartitionCache`）、`GlobalTableRouter`、`IdMakers`、`BootScriptWriter`。
5. `SessionRegistry`、`InFlight`、`Server<DataAny>(bufferQueueSize!: …, bindAt: port, checkDuration!: fdbm_checkDuration, executors!: …, unavailableChecked!: fdbm_unavailableChecked, defaultResp: {id => Message.error(id, data: DbdErrorPayload(INTERNAL, 'no response'))}, checker: 心跳探测消息)`。`checkDuration`/`checker` 在 f_net 中**无默认值**，必须显式传；`defaultResp` 保证"executor 返回 `None`"这条 f_net 兜底路径同样回 `ERROR`（而不是静默不回包）。
6. `ExitCallbacks.toExitGracefully()` + `atExit(stop)`（响应 SIGTERM/SIGINT，需求"响应 kill -15"）。
7. `server.start(handler)`（阻塞）。

### 10.2 请求处理

```cangjie
protected struct FdbmHandler {
    /** f_net Server 的 executor：判别请求种类 → 执行 → 组织响应；任何异常都回 ERROR（不静默） */
    public static func handle(context: ServerContext, buffer: SocketBuffer, message: Message): Message
}
protected class ServerContext {                  // 依赖容器
    public let sessions: SessionRegistry
    public let dispatcher: ExecutorDispatcher
    public let inFlight: InFlight
    public let logger: AbstractLogger
}
```

判别与响应规则（与 f_dbd 文档 §7 一一对应）：

| 请求 | 处理 |
| --- | --- |
| 前置校验 | `message.command` 必须是 `CONSUME`，否则 `ERROR(PROTOCOL)`（PING/ACK 已由 f_net 内部处理，不会到这里） |
| `decodeStrict<SqlPayload>` 命中 | `dispatcher.execute(session, sql, params)` → `RESP`：`QueryResultServerPayload` / `UpdateResultPayload` |
| `decodeStrict<QueryResultColumnPayload>` 命中 | `index>=0` → 单元格 `Data`；`NEXT_ROW` → `DataBool`；`CLOSE_CURSOR` → `DataNone`（**幂等**，无游标也成功）；`index>=0`/`NEXT_ROW` 而无游标 → `ERROR(CURSOR_STATE)` |
| 两者都不命中 | `ERROR(PROTOCOL)`（记 WARN，附命令与载荷类型） |
| 任意异常 | `FdbmException` → `ERROR(DbdErrorPayload)`；`SqlException` → `DB_ERROR` 并透传 `sqlState` |

### 10.3 `SessionRegistry` 与 `InFlight`

```cangjie
protected class SessionRegistry <: Resource {
    public init(sweepInterval: Duration, context: ServerContext)
    public func of(buffer: SocketBuffer): DbdSession      // 取或建
    public func remove(buffer: SocketBuffer): Unit
    public func closeAll(): Unit                          // 停止时全量回收
    public func isClosed(): Bool
}

protected struct InFlight {                               // 在途请求计数（优雅停止用）
    public static func enter(): Unit
    public static func leave(): Unit
    public static func await(timeout: Duration): Bool     // 归零返回 true，超时返回 false（记 WARN）
    public static func count(): Int64
}
```

- `SessionRegistry.of` 在首次见到某 `SocketBuffer` 时创建会话（键即连接对象，不需要断连回调）。
- **巡检线程**：周期 `fdbm_sessionSweepInterval` 扫描 `buffer.isClosed()` 的会话并 `close()`（归还有 pin 的连接、关闭游标），从表里移除；f_net 未提供断连回调，这是唯一的回收路径（列为约束）。

### 10.4 优雅停止（`stop()`）

1. `server.close()`：停止接受新连接（f_net `TcpServerSocket` 关闭后 accept 循环退出）。
2. `InFlight.await(shutdownTimeout)`：等待已接收请求执行完成并回包（超时记 WARN 后继续）。
3. `sessions.closeAll()`：关闭全部游标、归还 pin 连接。
4. `resources.closeAndAwait(timeout: fdbm_shutdownTimeout)`：先 `pool.close()` 再逐池 `awaitTermination` 等内部任务收尾（**必须在步骤 3 归还全部借用者之后**，否则与源码注释的约束冲突）；未按期终止则记 WARN 并继续收尾。
5. `router.close()`（`PartitionCache`/`Store` 关闭，`syncWAL` 后关闭）。
6. 记 INFO 日志，进程退出（由 `ExitCallbacks` 的 handler `exit(0)` 完成）。

### 10.5 驱动加载与子命令

```cangjie
protected struct DriverLoader {
    /** 扫描目录下 *.so/.dll/.dylib → PackageInfo.load → DriverManager.drivers() 校验唯一性 */
    public static func load(driverDir: String): Driver
}

protected class FdbmCommand <: SubCommand {       // 子命令名 'server'
    public prop command: String                   // 'server'
    public func exec(args: Array<String>): Int64
}
```

- **子命令名是 `'server'` 而不是 `'fdbm'`**：`App.boot()` 用 `args[0]` 作为分发键，`fdbm server` 的分发键就是 `'server'`；若注册成 `'fdbm'`，该命令永远不可达（`f_app/README.md` 明确"args[0] 是子命令名"）。
- `fdbm` 可执行文件的 `main`（无参时补默认子命令，避免 `args[0]` 越界）：

```cangjie
main(args: Array<String>): Int64 {
    SubCommandMediator.register(FdbmCommand())
    let argv = if (args.isEmpty()) { ['server'] } else { args }
    App(argv, dynamic: false).boot()      // 子命令：server；内置：version / help
}
```

- `fdbm server`：`FdbmServer(FdbmSettings.load()).start()`（阻塞，正常退出返回 0）；`exec` 内部 `try/catch` 启动自检异常 → 记 ERROR 并 `return 1`（**显式退出码**，不依赖未捕获异常）。
- `fdbm version` / `fdbm help`：走 `f_app` 内置命令。
- 驱动唯一性：`DriverManager.drivers().size == 1` 且与各节点 `fdbm_db_driver_<node>` 一致，否则 `FdbmException(NO_DRIVER)` 并结束进程（需求"如果有两个驱动要报错并结束进程"）。

### 10.6 `boot.sh`（模块内交付）


## 12. 关键设计决策与取舍

| 决策 | 理由 | 代价/限制 |
| --- | --- | --- |
| 会话 = TCP 连接（`SocketBuffer`），一连接一游标 | payload 无标识字段；服务端状态最少 | 同连接多语句交错读不支持（打开新游标即关旧游标） |
| 连接借还粒度：语句级，游标/事务例外 | 读写分离要求每次按语句选节点；事务必须固定连接 | 长游标会占住连接，池 `maxSize` 需 ≥ 并发长查询数 |
| SELECT 无分库条件时广播合并 | 需求"尽量使用简单 SQL"下仍要可用 | 多库结果按库顺序串行合并；`order by`/`limit` 语义仅在单库下严格（多库时按分片顺序拼接，列为限制） |
| 全局表写广播、无 2PC | 需求只要求"每个物理库有一副副本" | 部分失败需人工/重试（错误信息列出成功与失败的库） |
| `show tables` 按驱动方言分支 | 没有统一的跨库元数据接口 | 只支持 mysql / postgres(opengauss) 两种方言（数据库兼容性要求正好是两个） |
| 事务隔离级别属性不下发 | fdbm 不做方言转换 | 见 f_dbd 文档 §9（同一决策） |
| 缓存容量靠 fdbm 计数（超限停写） | `f_store` 无容量/淘汰 API | 缓存只增不减（除非过期/一致性删除）；列为后续优化点 |
| `LoadBalance` 用 `<Int64, Unit, Connection>` | `D` 是函数入参类型，不是节点类型 | 与需求草图字面不同（已在 §5 说明） |
| `export` 落盘重写 `boot.sh` 标记区块 | 需求明确要求落盘 | 只影响下一次启动；标记区块位置固定；可写键限于 `FdbmConfig` 白名单 |
| 心跳检查周期默认 30s | `f_net.Server` 在语句执行期间读不到心跳 ACK，阈值过小会误杀长语句 | 单条语句超过约 `3 × fdbm_checkDuration` 会被断链；超长语句需调大该值（§3.1 说明） |
| 优雅停止仅在 POSIX 生效 | `f_base.ExitCallbacks` 在 Windows 是空实现（`@When[os == "Windows"]`） | Windows 下用 `fboot shutdown <pid>`（`process.terminate()`）代替 `kill -15`；服务端部署以 Linux 为准 |
| 连接即会话 + f_net 静默重建 | 会话/游标/事务 pin 全部键在 TCP 连接上 | 重建后服务端视为新会话 → 客户端的游标/事务操作得到 `CURSOR_STATE`/`TX_STATE`（fail-fast；与 f_dbd 文档 §7.4 同一约定） |

## 13. 测试策略（TDD 分层）

| 层 | 范围 | 手段 |
| --- | --- | --- |
| 配置单测 | `FdbmConfig` 每一项解析/默认值/非法值；`BootScriptWriter` 重写与转义 | 纯内存；非法值断言抛 `FdbmException(CONFIG)` |
| 解析器单测 | 词法/语法、`SqlRenderer` 往返、`ParameterBinder`、`PartitionKeyExtractor` | 表驱动；不支持语法断言 `UNSUPPORTED_SQL` |
| 路由单测 | 六种 `PartitionAlgorithm` 的分桶分布与边界；`PartitionRouter`（Single/Broadcast/Unroutable）；缓存命中/失效/删除 | 用假 `NodeAccessor` + 临时目录 `f_store` |
| 执行器单测 | 每个执行器在假 `NodeAccessor`（记录 SQL 与参数）+ `f_mockdb` 驱动下的行为；ID 回填；DELETE 的三步顺序 | `f_mockdb` 作为物理库；断言下推 SQL、参数、广播次数 |
| 协议单测 | `FdbmHandler` 的请求判别/响应组装/错误回包；游标三操作；会话控制 | 直接调用 handler（构造 `SocketBuffer` 桩或走回环 `f_net.Server`） |
| 集成测试 | fdbm 进程 + f_mockdb 型物理库 + 真实 f_dbd 客户端：查询/更新/事务/分库/全局表/SHOW/export | 起真实进程（本地回环端口） |
| 端到端 | `fdemo` + 真实 mysql/postgres 双节点（分库+读写分离+全局表） | 手工/CI 脚本，验证 `fountain_sequence`、缓存落盘与重启恢复 |
| 优雅停止 | SIGTERM 下等 in-flight、归还连接、关闭 Store、退出码 0 | 脚本：起进程 → 发 SIGTERM → 校验日志/退出码/pid 文件 |

**必须固化的不变量**

1. 任何请求都有响应（`RESP` 或 `ERROR`）；异常不得穿透 handler。
2. 新语句必先关闭旧游标；`CLOSE_CURSOR` 幂等。
3. 事务内所有语句落到同一物理连接；`commit`/`rollback` 后连接归还。
4. 写语句无分库条件 → 拒绝执行（不广播、不猜测）。
5. 缓存写与删：只有"确认该值确实落在某物理库"才写缓存；DELETE 先删库记录再删缓存；缓存指向不存在库时必须失效。
6. 启动自检清单（§11）每一条都有对应负例测试。
