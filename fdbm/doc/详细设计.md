# fdbm 详细设计

> 需求来源：`.autocode/dbware.md`；共用代码来自 `f_dbd`（`fountain::f_dbd.common` / `.exception`）；可扩展接口来自 `f_dbm`（`PartitionAlgorithm` / `IdGenerator`）；参照实现：`f_rpc`（f_net 服务端用法）、`f_orm`（连接池与驱动加载）、`f_store`（缓存）、`f_concurrent.LoadBalance`（权重选择）。
> 版本基线：1.3.16。本文给出**包级定义、各包顶级声明、每个顶级声明的公共成员及调用关系**。

---

## 1. 模块定位与总览

`fdbm` 是可执行模块，是"数据库中间件"本体：

- 监听 TCP（默认 8112），接收来自 `f_dbd` 的 **CONSUME** 请求，按 **RESP**（成功）/ **ERROR**（失败）回应。
- 解析 SQL（INSERT / UPDATE / DELETE / SELECT / JOIN / SHOW / DDL / export / 会话控制），完成**水平分库路由、读写分离、负载均衡、全局表广播、ID 生成、分库缓存**。
- 通过 `f_dbpool.DatabasePool` 管理到物理库的连接；物理驱动从部署目录的 `driver/` 子目录动态加载（`std.reflect.PackageInfo.load`），且**必须只有一个驱动**。

### 1.1 数据流

```
f_dbd ──CONSUME(SqlPayload)──► FdbmServer(handler)
                                 │ decodeStrict 判别请求种类
                                 ▼
                          ExecutorDispatcher
             ┌───────────────┼────────────────┬──────────────┐
             ▼               ▼                ▼              ▼
        SqlParser      PartitionRouter    GlobalTableRouter  IdGenerator
             │               │                │              │
             └──────► 物理库名（RoutePlan） ◄──┘              │
                                 │                           │
                                 ▼                           │
                        DatabaseResources ──► DatabasePool（每物理库一个池）
                                 │            └─ Connection（读写权重选择）
                                 ▼
                          物理驱动（唯一）──► 物理数据库
                                 │
             ┌───────────────────┴────────────────────┐
             ▼                                        ▼
  QueryCursor（挂会话，逐行/逐列读）        UpdateResultPayload
             │
             ▼
      RESP(QueryResultServerPayload / 单元格 / DataBool) ──► f_dbd
```

## 2. 包结构

`fdbm` 依赖独立动态库模块 **`f_dbm`（`fountain::f_dbm`）**：后者只声明可扩展接口 `PartitionAlgorithm`、`IdGenerator` 及 `IdGenerator` 的配套异常，不含任何实现。`fdbm` 单向依赖 `f_dbm`；`f_dbm` 不依赖 `fdbm` / `f_dbd`。

| 包 | 目录 | 职责 | 依赖（模块内） |
| --- | --- | --- | --- |
| `fountain::fdbm` | `src/main.cj` | 进程入口：加载配置并启动 `FdbmServer`（**无子命令**，可执行文件直接运行） | config / server |
| `fountain::fdbm.config` | `src/config/` | 全部配置项解析与校验、`export` 落盘 | exception |
| `fountain::fdbm.exception` | `src/exception/` | `FdbmException`（统一携带 `DbdErrorCode`） | — |
| `fountain::fdbm.resources` | `src/resources/` | 物理节点/物理库模型、连接池构建、读写节点选择（`NodeAccessor`） | config / exception |
| `fountain::fdbm.route` | `src/route/` | 分库算法实现（接口在 `f_dbm`）、分库规则、路由计划、分库缓存、全局表 | config / resources / exception |
| `fountain::fdbm.idmaker` | `src/idmaker/` | ID 生成器实现（接口与异常在 `f_dbm`）、UUID / Snowflake / Sequence | resources / exception |
| `fountain::fdbm.custom` | `src/custom/` | 扫描 `custom/`、`PackageInfo.load`、`InitializerCollection.initialize()`、收集 `PartitionAlgorithm` / `IdGenerator` | f_app / f_dbm / f_log / exception |
| `fountain::fdbm.sql` | `src/sql/` | 词法/语法解析、AST、参数绑定、会话控制语句 | exception |
| `fountain::fdbm.execute` | `src/execute/` | 语句执行器族、服务端游标、会话状态 | sql / route / resources / idmaker |
| `fountain::fdbm.server` | `src/server/` | `FdbmServer`、请求分发、会话注册表、驱动加载、优雅停止 | 全部 |

依赖方向自上而下无环；`sql` 不依赖 `route`（路由只读 AST），`execute` 是唯一的"粘合层"。

**可见性约定**：fdbm 是可执行模块，跨模块扩展点只有 `f_dbm` 的 `PartitionAlgorithm` / `IdGenerator`；fdbm 内部顶级声明原则上 `protected`（模块内可见，测试同模块可访问），实现类即使声明为 `public` 也不会被其他模块 import（fdbm 不是库）。

## 3. `fountain::fdbm.config`

### 3.1 配置项总表

| 配置项 | 类型/默认 | 语义 |
| --- | --- | --- |
| `fdbm_port` | `UInt16` / `8112` | 监听端口 |
| `fdbm_db` | `name0@host1:port;name2@host2:port;...` | 物理节点清单；分号分隔，`@` 前是**中间件节点名**（非数据库名） |
| `fdbm_db_driver_<node>` | `String` / 无默认（必填） | 该节点的物理驱动名（`DriverManager` 中的名字） |
| `fdbm_db_database_<node>` | 逗号分隔 / 必填 | 该节点承载的物理库名；重名=参与负载均衡，不同名=参与水平分库 |
| `fdbm_db_username_<node>` / `fdbm_db_password_<node>` | `String` | 该节点凭据 |
| `fdbm_db_logicalDatabase_<logical>` | 逗号分隔 | 逻辑库 → 物理库列表；未配置的逻辑库视为包含全部物理库 |
| `fdbm_databasePool*` | 见 §3.4 | 物理库连接池参数 |
| `fdbm_loadbalance` | `random` / `roundrobin` | 节点选择算法 |
| `fdbm_loadbalance_weight_<node>` | `w,1;r;2` | 节点级读写权重（`w`=写权重、`r`=读权重；`w`/`r` 单独出现表示权重 1） |
| `fdbm_loadbalance_weight_<node>__<database>` | 同上 | 节点下**某个物理库**的读写权重（优先于节点级） |
| `fdbm_partition_step` | `Int64` / `1000_0000` | 步长分库的步长 |
| `fdbm_partition_substr__<table>` | `'<start>,<length>,<hash>'` / 无 | `substr` 分库的子串参数：`start` 从 0 起（按 Unicode 码点）、`length`（`0`=到末尾）、`hash` ∈ `std`/`hash`/`crc16`/`crc32`/`crc64`/`murmur`；算法为 `substr` 时**必填**，其他算法配置该键 → WARN 并忽略（**新增**） |
| `fdbm_partition__<table>` | `'<logical>,<algorithm>,<column>'` | 某表的分库规则；`__` 后无表名报错退出 |
| `fdbm_global__<table>` | `'<logical>'` | 全局表所在的逻辑库 |
| `fdbm_idmaker` | `uuid,1` / `snowflake` / `sequence` | ID 生成器与参数（uuid 的版本号） |
| `fdbm_cache` | `Bool` / `true` | 是否开启分库缓存 |
| `fdbm_cache_expire` | `Duration` / 空=永久 | 缓存过期时间（`Duration.toString()` 格式，如 `1d`） |
| `fdbm_cache_size` | `Int64` / `0`=不限制 | 缓存 KEY 数量上限 |
| `fdbm_cachePath` | `String` / `<工作目录>/cache` | f_store 落地目录（**新增**，f_store 必须有路径） |
| `fdbm_driverDir` | `String` / `<工作目录>/driver` | 物理驱动动态库目录（**新增**，需求只描述"部署路径下的 driver 子目录"） |
| `fdbm_customDir` | `String` / `<工作目录>/custom` | 自定义扩展动态库目录（`PartitionAlgorithm` / `IdGenerator` 实现，**新增**） |
| `fdbm_bootScript` | `String` / `<工作目录>/boot.sh` | 启动脚本路径（`export` 语句的落盘目标） |
| `fdbm_sessionSweepInterval` | `Duration` / `30s` | 断连会话巡检周期（**新增**，f_net 无断连回调） |
| `fdbm_shutdownTimeout` | `Duration` / `30s` | 优雅停止时等待在途请求的上限（**新增**） |
| `fdbm_checkDuration` | `Duration` / `30s` | 服务端 TCP 有效性检查周期（**新增**；`f_net.Server` 的 `checkDuration!` 必填，无默认值） |
| `fdbm_unavailableChecked` | `Int64` / `3` | 连续检查失败次数阈值（**新增**，传给 `Server` 的 `unavailableChecked`） |
| `fdbm_sequenceDatabase` | `String` / 逻辑库的第一个物理库 | `sequence` ID 生成器的分配库（**新增**，见 §7） |

> 全部经 `fountain::f_config.Config` 读取，因此天然支持环境变量、`--key=value` 命令行与 `Config.set` 三种来源；sm4 等加密配置与 `f_config` 一致（见 `fdemo/boot.sh` 的 `build` 函数）。
>
> **心跳与长语句（重要取舍）**：`f_net.Server` 在读循环里 `executors.call{...}.get{}` 是**阻塞**的，单条语句执行期间读不到客户端的心跳 ACK，连续 `fdbm_unavailableChecked` 次检查失败就会主动断开连接。因此 `fdbm_checkDuration` 默认取 **30s**（≈ 单条语句 90s 上限），超过该量级的语句必须调大该值；广播 DDL、逐行 INSERT…SELECT、大结果集首包都会受这条约束影响（列入 §12）。
>
> **默认值口径**：与 f_dbd 侧统一，取需求**示例值**为准（需求中"# 默认是…"注释与示例冲突按笔误处理，见 f_dbd 文档 §6.1 的登记）。

### 3.2 `FdbmConfig`（`protected struct`）

```cangjie
protected struct FdbmConfig {
    public static func getPort(): UInt16
    public static func getNodes(): Array<DatabaseNodeConfig>
    public static func getPool(): PoolConfig
    public static func getLoadBalance(): LoadBalanceConfig
    public static func getPartitions(): Array<PartitionRuleConfig>
    public static func getGlobalTables(): Array<GlobalTableConfig>
    public static func getIdMaker(): IdMakerConfig
    public static func getCache(): CacheConfig
    public static func getDriverDir(): String
    public static func getCustomDir(): String
    public static func getBootScript(): String
    public static func getSessionSweepInterval(): Duration
    public static func getShutdownTimeout(): Duration

    /** 启动期一次性校验：任一失败即记 ERROR 并结束进程（见 §13 启动自检清单）；自定义扩展名参与算法/ID 生成器合法性校验 */
    public static func validate(confs: FdbmSettings, customAlgorithms: Array<String>, customIdGenerators: Array<String>): Unit
}
```

| 成员 | 语义 | 调用方 |
| --- | --- | --- |
| 各 `get*` | 单项或整块配置解析；解析失败抛 `FdbmException(CONFIG)`（含配置项名与原始值）。`getPartitions` 同时读取 `fdbm_partition_substr__<table>` 并挂到 `PartitionRuleConfig.substr` | `FdbmServer` 初始化 |
| `validate` | 跨项校验：驱动唯一性、逻辑库→物理库引用完整性、权重表引用完整性、`fdbm_partition` 无表名报错、分区算法名（内置 ∪ 自定义）合法、`substr` 表的子串参数齐全且合法、`fdbm_idmaker`（内置 ∪ 自定义）参数合法 | `FdbmServer.start()` 在 `CustomLoader.load` 之后调用 |

### 3.3 配置模型类型

```cangjie
protected class DatabaseNodeConfig {          // 一个物理节点
    public let name: String                   // name0
    public let host: String
    public let port: UInt16
    public let driverName: String
    public let databases: Array<String>
    public let username: String
    public let password: String
    public func url(database: String): String // '<driver>://user:pwd@host:port/database'（凭据 % 编码）
}

protected class PoolConfig {                  // 连接池参数（fdbm_databasePool*）
    public let initSize: Int64                // 1
    public let minSize: Int64                 // 1
    public let maxSize: Int64                 // 1
    public let checkOnCreation: Bool          // false
    public let checkOnBorrowing: Bool         // true
    public let checkOnReturning: Bool         // false
    public let idleTimeout: Duration          // 0
    public let connectionLife: Duration       // 86400s
    public let checkInterval: Duration        // 300s
    public let connectTimeout: Duration       // 50ms
    public let maxWaiting: Duration           // 30000ms
    public let checkSql: String               // 'select 1'
}

protected class LoadBalanceConfig {
    public let algorithm: String              // 'random' | 'roundrobin'
    public func weight(node: String, database: String): NodeWeight   // 先查 database 级，再查节点级，缺省 1/1
}
protected class NodeWeight {
    public let write: Int64                   // 0 表示该节点/库不参与写
    public let read: Int64                    // 0 表示不参与读
    public func canWrite(): Bool
    public func canRead(): Bool
}

protected class PartitionRuleConfig {
    public let database: String               // 逻辑库名（config 值第 1 段）
    public let table: String                  // `__` 后的表名
    public let algorithm: String              // hash | std | crc16 | crc32 | crc64 | murmur | step | substr
    public let column: String                 // 分库列名
    public let substr: ?SubstringSpec         // 仅 algorithm == 'substr' 时非空
}
protected class SubstringSpec {               // fdbm_partition_substr__<table>
    public let start: Int64                   // 0 起（Unicode 码点）
    public let length: Int64                  // 0 = 从 start 到末尾
    public let hash: String                   // std|hash | crc16 | crc32 | crc64 | murmur
}
protected class GlobalTableConfig {
    public let database: String               // 逻辑库名
    public let table: String
}
protected class CacheConfig {
    public let enabled: Bool
    public let expire: ?Duration
    public let size: Int64                    // 0=不限制
    public let path: String
}
protected class IdMakerConfig {
    public let kind: String                   // 'uuid' | 'snowflake' | 'sequence'
    public let arg: ?String                   // uuid 版本号等
}
```

### 3.4 连接池参数默认值说明

`PoolConfig` 取需求给出的默认值（`initSize=1`、`minSize=1`、`maxSize=1`、`checkOnReturning=false`、`connectionLife=86400s`、`connectTimeout=50ms`、`maxWaiting=30000ms`），构造 `DatabasePool` 时**显式传参**（`f_dbpool` 自身不读任何配置）。

### 3.5 `BootScriptWriter`（`export` 落盘）

```cangjie
protected class BootScriptWriter {
    public init(path: String)
    public func set(key: String, value: String): Unit   // 校验白名单 + Config.set(key, value) + 登记待写
    public func flush(): Unit                           // 按功能分块重写标记区块
    public func normalize(): Bool                       // 启动时调用：不合规则自动整理并覆盖，返回是否写回

**分块规则（块顺序固定，空块不输出）**

| 顺序 | 块标题 | 匹配键（精确 / 前缀） | 块注释 |
| --- | --- | --- | --- |
| 1 | 服务与进程 | `fdbm_port`、`fdbm_bootScript`、`fdbm_driverDir`、`fdbm_customDir`、`fdbm_checkDuration`、`fdbm_unavailableChecked`、`fdbm_sessionSweepInterval`、`fdbm_shutdownTimeout` | 监听端口、启动脚本、驱动/自定义扩展目录、心跳与优雅停止 |
| 2 | 物理节点与凭据 | `fdbm_db`；前缀 `fdbm_db_driver_`、`fdbm_db_database_`、`fdbm_db_username_`、`fdbm_db_password_` | 节点清单，以及每节点的驱动、物理库与凭据 |
| 3 | 逻辑库映射 | 前缀 `fdbm_db_logicalDatabase_` | 逻辑库 → 物理库列表；未配置的逻辑库包含全部物理库 |
| 4 | 连接池 | 前缀 `fdbm_databasePool` | 每物理库一个池；未出现的键取 §3.4 默认值 |
| 5 | 负载均衡与读写权重 | `fdbm_loadbalance`；前缀 `fdbm_loadbalance_weight_` | 节点选择算法与读写权重；库级优先于节点级 |
| 6 | 分库与全局表 | `fdbm_partition_step`；前缀 `fdbm_partition__`、`fdbm_partition_substr__`、`fdbm_global__` | 分库规则、子串参数与全局表；表名写在 `__` 后 |
| 7 | ID 生成 | `fdbm_idmaker`、`fdbm_sequenceDatabase` | 生成器类型/参数与 sequence 分配库 |
| 8 | 分库缓存 | `fdbm_cache`、`fdbm_cache_expire`、`fdbm_cache_size`、`fdbm_cachePath` | 开关、过期、容量与 f_store 落地目录 |
| 9 | 其他 | 未命中以上规则的键 | 前向兼容；未知键保留在此块 |

- 匹配顺序从上到下，**首个命中即归属**；前缀匹配要求完整前缀（如 `fdbm_db_driver_`），避免 `fdbm_db` 抢走 `fdbm_db_driver_name0`。
- `set` 先校验 `FdbmConfig` 白名单（§11），非法键直接 `FdbmException(CONFIG)`，不调用 `Config.set`、不写脚本。
- 块内键按 **key 字节序** 升序排列；同一前缀的节点/库/表键自然相邻。块顺序固定，保证同一组键值多次 `flush` 输出一致。

**逐键注释**

- 每个 `export` 前输出一行 `# <注释>`；块标题与块说明见上表。
- 固定键的注释取 §3.1 的“语义”列（如 `fdbm_port` → `监听端口`）。
- 动态键按后缀生成：

| key 模式 | 注释模板 |
| --- | --- |
| `fdbm_db_driver_<node>` | `节点 <node>：物理驱动名` |
| `fdbm_db_database_<node>` | `节点 <node>：承载的物理库（逗号分隔）` |
| `fdbm_db_username_<node>` | `节点 <node>：用户名` |
| `fdbm_db_password_<node>` | `节点 <node>：密码（敏感，勿提交仓库）` |
| `fdbm_db_logicalDatabase_<logical>` | `逻辑库 <logical> → 物理库列表` |
| `fdbm_databasePool<Suffix>` | `连接池：<Suffix>`（已知后缀用中文说明，如 `InitSize` → `初始连接数`） |
| `fdbm_loadbalance_weight_<node>` | `节点 <node>：读写权重（w,1;r,2）` |
| `fdbm_loadbalance_weight_<node>__<db>` | `节点 <node> / 库 <db>：读写权重（优先于节点级）` |
| `fdbm_partition__<table>` | `表 <table>：分库规则 <logical>,<algorithm>,<column>` |
| `fdbm_partition_substr__<table>` | `表 <table>：子串分库参数 <start>,<length>,<hash>` |
| `fdbm_global__<table>` | `表 <table>：全局表所在逻辑库` |
| 其他 | `未归类：<key>` |

**flush 渲染规则**

1. 解析现有标记区块（旧标记 `# ==== fdbm managed exports (do not reorder) ====` 或新标记）为 `key → value`；同键后出现者覆盖前者。
2. 用本次 `set` 的键值覆盖/追加；`set` 未涉及的已有键保留。
3. 按上表分块，块内排序，生成块标题、块说明、逐键注释与 `export` 行；空块不输出。
4. 用新标记 `# ==== fdbm managed exports (auto-generated; do not edit) ====` 整体替换原区块（旧标记同时迁移）；文件中没有标记区块时在末尾追加。
5. 值按 shell 单引号转义（`'` → `'\''`）；注释不包含值，避免泄露密码。
6. 原子写回：`boot.sh.tmp` → 复制原文件权限位 → `rename`；区块外的内容（`start`/`stop`/`status`、其他注释）原样保留。
7. **幂等**：同一组 key/value 连续 `flush` 两次，输出字节一致；不写时间戳。
8. 区块由 fdbm 独占：区块内非生成格式的行（手工添加的 export/注释）在重写时丢弃并记 WARN；需要长期保留的内容应放在区块外。
9. 语义：仅“未来的进程启动”会带上新值；当前进程只靠 `Config.set` 生效（与需求“修改配置项，并把配置项落到启动脚本中”一致）。

**启动时自动整理（`normalize()`）**

- **时机**：`FdbmServer.start()` 的初始化阶段（§10.1 第 6 步），在接受连接之前调用；只读写 `fdbm_bootScript` 指向的文件，不影响已加载的运行时配置。
- **输入**：只整理脚本中已有的顶层（行首无缩进）`export fdbm_*` 行——标记区块内（旧/新标记均可）+ 区块外的旧格式导出（一次性迁移）；缩进在其他函数/条件里的 `export` 原样保留。
- **不补默认值**：不把默认值、环境变量或 `--key=value` 的临时覆盖写进脚本；脚本值以脚本自身为准，避免把临时覆盖持久化。
- **判定**：按上述分块/排序/注释规则渲染规范区块，与文件中现有区块逐字节比较；一致 → 不写回（返回 `false`）。
- **重写**：
  - 用规范区块替换原区块；没有区块时插入到第一条旧格式 `export fdbm_*` 的位置（没有则追加到文件末尾）。
  - 旧格式 `export fdbm_*` 行一次性移入新区块并删除原行；其他 export（如 `LD_LIBRARY_PATH`）、注释、`start`/`stop` 函数原样保留。
  - 非白名单的 `fdbm_*` 行不纳入整理：区块外的原样保留，区块内的按 `flush` 第 8 条丢弃并记 WARN（只记键名，不含值）。
  - 同一键同时出现在区块内外时，区块内优先，记 WARN。
  - 原子写回、保留权限（同 `flush`）。
- **失败**：文件不存在、不可读/不可写、解析异常 → 记 ERROR/WARN 并返回 `false`，**不阻塞启动**（服务继续用已加载配置）；下次启动再试。
- **幂等**：整理后的脚本再次启动时逐字节一致，不产生写回。
- **安全**：日志只出现键名，不打印值（尤其 `fdbm_db_password_*`）。

| 关键点 | 说明 |
| --- | --- |
| 池的粒度 | **每 `<host:port> + <physical database>` 一个 `DatabasePool`**（需求原文），池项 = 一条物理连接 |
| 权重语义 | 一个物理库同时配读写权重 ⇒ 同时进 `readNodes` 与 `writeNodes`；只配 `r` ⇒ 只进读；只配 `w` ⇒ 只进写 |
| 只读/只写库 | 由 `NodeWeight.canRead/canWrite` 决定是否注册进对应 LoadBalance |
| 配置错误 | `fdbm_loadbalance_weight_<node>_`（节点名后只有下划线）在 `FdbmConfig.validate` 阶段报 `FdbmException(CONFIG)` 并**结束进程** |
| 连接归还 | `select*` 返回的是 `PooledConnection`，调用方 `close()` 即归还——**且 `close()` 非幂等**（重复归还抛 `ConnectionException`），执行器必须在 `finally` 中恰好归还一次（除非游标持有到关闭）；池耗尽等待超时同样表现为 `ConnectionException`（映射 `TIMEOUT`） |
| 取连接的写法 | 统一走 `pool.connect()`（内部 `getConnection(timeout: connectTimeout).getOrThrow`）；`connectTimeout`/`maxWaiting` 的语义按 `f_dbpool`：`connectTimeout` 是取连接的超时，`maxWaiting` 只在调用方传 `Duration.Max` 时生效——fdbm 取连接使用前者 |
| 池关停（优雅停止专用） | `DatabasePool` 现提供 `closeAndAwait(timeout!)`：先 `pool.close()`，再 `awaitTermination(timeout)` 等内部任务收尾，最后幂等关闭 `Datasource`；源码注释明确"**宿主必须先归还全部借用者**再 await" ⇒ fdbm 的顺序必须是"关会话/游标（归还连接）→ 逐池 `closeAndAwait`"。`timeout` 必须为正且有限（`Duration.Zero`/`Duration.Max` 会被 `IllegalArgumentException` 拒绝）；普通 `close()` 不等待内部任务，仅用于非优雅场景 |
| 泛型实参修正 | 需求草图写 `LoadBalance<Int64, DatabasePool, Connection>`；`LoadBalance<W, D, R>` 的 `D` 是"被选中函数 `(D) -> R` 的入参类型"，与节点对象无关。本设计用 `<Int64, Unit, Connection>`，每节点注册 `{_ => pool.connect()}`，选择语义完全一致（与 f_dbd 文档 §6.4 同一处修正） |
| 负载算法接线（照 f_concurrent/f_net 的实测口径） | `LoadBalance<Int64, Unit, Connection>(0, algo)`：`random` → `Int64Weight(1, Σw)`；`roundrobin` → `RoundRobin<Int64>(step: 1, min: 1, max: Σw)`。**取值区间必须落在权重桶内部**——`min = 0` 或 `origin = min` 会永远命中第一个节点（仓库既有实测记录），用例固定"只有 node1 有权重 → 100 次全落 node1" |

## 6. `fountain::fdbm.route`

### 6.1 分库算法

```cangjie
// 接口声明在 fountain::f_dbm（见 f_dbm 模块）；fdbm 只保留实现
// public interface PartitionAlgorithm {
//     prop name: String
//     func partition<K>(key: K): String        // 返回物理数据库名
// }
```

> **接口位置**：`fountain::f_dbm.PartitionAlgorithm`；fdbm 通过 `import fountain::f_dbm.*` 使用。以下实现类与 `PartitionAlgorithmFactory` 都在 fdbm 内。

| 实现类 | `name` | 算法 | 依赖 |
| --- | --- | --- | --- |
| `protected class StepPartition <: PartitionAlgorithm` | `'step'` | 整数 ID 按 `step` 分段：`dbs[(id - 1) / step]`；**有效数据域 `[1, N*step]`，越界抛 `FdbmException(ROUTE_FAILED)`**（不静默回绕，否则范围路由无法保持单调） | 无 |
| `protected class HashPartition <: PartitionAlgorithm` | `'hash'` | `key.hashCode()` 取模 | `stdlib` |
| `protected class Crc16Partition <: PartitionAlgorithm` | `'crc16'` | `crc16(key.toString())` 取模 | `f_util` 顶级 `crc16` |
| `protected class Crc32Partition <: PartitionAlgorithm` | `'crc32'` | `crc32(...)` 取模 | `f_util` |
| `protected class Crc64Partition <: PartitionAlgorithm` | `'crc64'` | `crc64(...)` 取模 | `f_util` |
| `protected class MurmurPartition <: PartitionAlgorithm` | `'murmur'` | `murmurHash(data: key.toString())` 取模（`UInt128` → 取低 64 位） | `f_util` |
| `protected class SubstringPartition <: PartitionAlgorithm` | `'substr'` | 取字符串 `key` 的 `[start, start+length)` 子串，再按 `hash` 计算并取模（**新增**） | `f_util`（CRC/Murmur） |

- **范围路由（仅 `step`）**：`StepPartition` 额外提供
  `public func partitionRange(lo: ?Int64, loInclusive: Bool, hi: ?Int64, hiInclusive: Bool): Array<String>`：
  - **开区间按整数域收紧**：`> lo` → 下界 `lo + 1`，`< hi` → 上界 `hi - 1`（`lo == Int64.Max` 或 `hi == Int64.Min` → 空区间）；`>=`/`<=` 原样；`None` 表示**无界**；`BETWEEN a AND b` 由解析器展开为 `>= a AND <= b`（闭区间）。
  - 截到分片空间 `[1, N*step]`，再映射为**连续**分片下标 `start = (lo - 1) / step`、`end = (hi - 1) / step`，返回 `databases[start..=end]`。
  - **返回值**：非空数组 = 命中的分片；**空数组 = 可判定但条件无解**（如 `id > 100 and id < 50`、整段越界），与“无法判定”严格分开——“无法判定”由 `extractRange` 返回 `None` 表达（边界不是可无损解析为 `Int64` 的字面量、含 `OR`/`NOT`），路由器据此得到 `Unroutable`；把“空”误当成“不可判定”会导致无解条件被无谓广播。
- **范围路由的边界口径**：`step` 分片的**有效数据域就是 `[1, N*step]`**（构造期确定）。范围先截到该域再映射连续下标——域外值在写入时已被拒绝（`ROUTE_FAILED`），所以 `id > N*step` / `id < 1` 可确定为 `Empty`，不需要、也不允许广播。若业务 ID 会超过 `N*step`，必须调大 `step` 或增加物理库，而不是依赖回绕。`N*step` 溢出 `Int64`、`step <= 0` → `PARTITION_CONFIG`。
- **只有 `step` 能算范围**：`hash`/`crc16`/`crc32`/`crc64`/`murmur`/`substr` 与自定义算法没有单调性，范围条件一律 `Unroutable`。路由层用 `match (rule.algorithm) { case p: StepPartition => p.partitionRange(...); case _ => /* Unroutable */ }` 判定；**不给 `PartitionAlgorithm` 增加范围方法**，避免逼迫全部自定义实现表态（后续若确有需要，可在 `f_dbm` 增加可选的 `RangePartitionAlgorithm`）。
- **子串分库（`substr`，2026-10-17 用户拍板）**：`protected class SubstringPartition <: PartitionAlgorithm`，构造参数来自 `fdbm_partition_substr__<table>`（§3.1）：
  - **索引口径**：`key` 先按 `ToString` 取字符串（不满足 → `ROUTE_FAILED`）；`start` 从 **0** 起，单位是 **Unicode 码点**（`key.toString().toRuneArray()` 切片后再 `String(Array<Rune>)` 还原），不会把多字节字符截成半个；`length == 0` 表示从 `start` 到末尾，`length < 0` / `start < 0` → `CONFIG`。
  - **越界**：子串右端超过字符串长度时截到末尾（允许最后一个分片短）；截断判断用 `length > count - start`（避免 `start + length` 溢出）；`start` 已不小于字符数 → 空子串 → 运行时 `FdbmException(ROUTE_FAILED)`，**不把短键静默聚到同一个库**。
  - **哈希**：`hash` 取 `std`/`hash` → `substring.hashCode()`；`crc16`/`crc32`/`crc64`/`murmur` → `f_util` 顶级函数，输入为子串的 UTF-8 字节。取模前统一规范为非负：`((h % n) + n) % n`（`hashCode()` 可能为负；CRC/Murmur 为无符号值）。
  - **大小写与前导零敏感**：不做任何折叠/归一。路由层的“能无损解析为 `Int64` 才归一”按**往返相等**判定——`'00123'` 的往返结果是 `'123'`，因此保持字符串，前导零照常参与子串与哈希。
  - 只支持等值/`IN` 路由；范围条件见上一条，`Unroutable`。

- 统一构造函数：`init(databases: Array<String>)`（`StepPartition` 为 `init(databases, step: Int64)`；`HashPartition` 为 `init(databases, hashAlgorithm: String)` 以支持 `std`/`hash` 别名）。
- **泛型入参的运行时判定**：接口方法 `partition<K>(key: K)` 对 `K` 无约束（需求原文）；实现内**直接对 `key` 做模式匹配**：`HashPartition` 用 `match (key) { case h: Hashable => ...; case _ => throw FdbmException(ROUTE_FAILED) }`，CRC/Murmur 用 `case s: ToString => s.toString()`，不满足同样报错。
  - **不需要先装箱为 `Any`**：`is` + 直接调用成员不会对 `K` 智能转换（`x is Hashable` 后 `x.hashCode()` 仍编译报错：`not found for generic type 'K' in its upper bounds`），但 `match (key) { case h: Hashable => h.hashCode() }` 本身合法，运行时按实际类型分派；显式 `Any` 只是多余的装箱。
  - 1.3.0 编译器实测：`func f<K>(x: K) { match (x) { case h: Hashable => h.hashCode(); case _ => 0 } }` 可直接编译；`x is Hashable` 后调用 `x.hashCode()` 则编译失败。
- **键的规范化（唯一口径）**：路由层在调用算法前把分库键规范化为"**能无损（`String -> Int64 -> String` 往返相等）解析为 `Int64` 就用 `Int64`（满足需求的 `ID.hashCode()`），否则用 `String`**"——即 `123` 与 `'123'` 归一为同一键，但 `'00123'` 保持字符串；`StepPartition` 拿到的字符串若无法解析为 `Int64` → `FdbmException(ROUTE_FAILED)`（不猜测、不回绕）。
- 构造期校验：`databases` 非空（`FdbmException(PARTITION_CONFIG)`）。
- `protected struct PartitionAlgorithmFactory { public static func create(name: String, databases: Array<String>, step: Int64, substr: ?SubstringSpec, custom: HashMap<String, PartitionAlgorithm>): PartitionAlgorithm }`：先查 `custom`，再查内置实现（`substr` 要求 `substr` 非空且参数合法）；未知算法名、`substr` 缺参数 → `FdbmException(PARTITION_CONFIG)`。自定义实例必须自包含（构造参数由开发者在 `Initializer.initialize()` 中准备，fdbm 不注入 `databases/step/substr`）。

### 6.2 分库规则与路由

```cangjie
protected class PartitionRule {                     // fdbm_partition__<table> 解析结果
    public let database: String                     // 逻辑库
    public let table: String
    public let column: String
    public let algorithm: PartitionAlgorithm
}

protected class RoutePlan {
    public prop kind: RouteKind                     // Single | Multi | Broadcast | Empty | Unroutable
    public prop databases: Array<String>            // Single=1；Multi=2..N（按逻辑库配置的物理库顺序）；Broadcast=全部物理库；Empty/Unroutable=空
}
protected enum RouteKind { | Single | Multi | Broadcast | Empty | Unroutable }

protected class PartitionRouter {
    public init(rules: Array<PartitionRule>, cache: ?PartitionCache,
                custom: HashMap<String, PartitionAlgorithm>)

    /** 语句级路由：等值/IN/范围（> >= < <= BETWEEN，仅 step）→ Single/Multi；
     *  全部为全局表 → Broadcast（逻辑库全部物理库）；全部未分库 → Single；
     *  有分片表但抽不到条件 → Unroutable；条件可证无解 → Empty */
    public func route(statement: SqlStatement, currentDatabase: String): RoutePlan
    /** 值级路由：查缓存 → 未命中用算法计算并写缓存 */
    public func routeByValue(rule: PartitionRule, value: String): String
    public func rule(database: String, table: String): ?PartitionRule
    public func isPartitioned(database: String, table: String): Bool
    /** 删除缓存条目（DELETE 三步顺序的第三步） */
    public func invalidate(rule: PartitionRule, value: String): Unit
    public func close(): Unit
}
```

| 成员 | 语义与规则 |
| --- | --- |
| `route` | 单表语句：从 WHERE（INSERT 为 values/set 中该列）抽取分库列条件，按以下顺序合并：① **等值/`IN`** 的字面量集合逐个 `routeByValue` 并去重；② **范围**（`>`/`>=`/`<`/`<=`/`BETWEEN`，仅 `step`）经 `partitionRange` 展开为连续分片集合，`extractRange` 返回 `None` → `Unroutable`、展开为空集 → `Empty`；③ 两者同时出现时用范围**过滤**等值集合（精确，过滤后为空 → `Empty`）。结果 1 个库 → `Single`、多个 → `Multi`；**全部表都是全局表** → `Broadcast`（逻辑库全部物理库，读由执行器只取一个副本）；**全部表都未分库** → `Single`（逻辑库首个物理库）；有分片表但抽不到条件 → `Unroutable`（执行器按语句类型决定"广播还是报错"）。`OR`/`NOT` 包裹的分库条件不做展开（含 `id > 1 OR id > 100` 这类可合并情形也保守处理）→ `Unroutable`。JOIN：**同一分库维度**（同 `column`、同算法、同分片空间）的多个分片表取库集合**交集**（空 → `Empty`，1 个 → `Single`，多个 → `Multi`；全局表不参与约束）；不同维度时仍要求各表收敛到同一个物理库，否则 `Unroutable`（错误信息给出两张表的库名）。 |
| `routeByValue` | 缓存键 `'<logical>.<table>.<column>:<value>'`，命中后**校验物理库存在**（`NodeAccessor.contains`）：存在→返回；不存在→删缓存并重算（需求"缓存中存在但数据库不存在则从缓存中删除"）。 |
| `Multi` 时的行为 | 执行器按 `plan.databases` 的顺序逐库执行同一份下推 SQL：`SELECT` 每库一段 `CursorSegment`、按库序串成**一个** `QueryCursor`（与广播同一合并路径，§9.4）；`UPDATE`/`DELETE` 逐库执行并把 `rowCount` **求和**；任一分片执行失败 → 整体 `ERROR`（已执行的分片不回滚，列为限制）。 |
| `Empty` 时的行为 | 条件可证无解（如 `id > 100 and id < 50`）：`SELECT` 仍借**第一个**物理库执行一次以取得列信息，结果必为 0 行；`UPDATE`/`DELETE` 直接返回 `rowCount=0`，**不借连接、不下推**。 |
| `Unroutable` 时的行为 | `UPDATE`/`DELETE` 缺分库列条件（或范围条件无法判定）→ 报错（`ROUTE_FAILED`，错误文案提示补分库列/改用可判定的范围）；`SELECT` 允许 → 广播到该逻辑库全部物理库并由执行器**合并结果**（见 §9.4，本期实现：`SELECT` 无分库条件时按库逐个查询、顺序合并；**不预取行**，合并语义与单库一致：首次 `NEXT_ROW` 才开始取行） |

### 6.3 `PartitionCache`

```cangjie

- **`BETWEEN` 不引入新 AST 节点**：解析时等价展开为 `BinaryExpression(And, Gte(col, a), Lte(col, b))`，路由与渲染共用同一套比较表达式；`a > b` 由 `partitionRange` 判为空区间。
- **`extractRange` 的保守规则**：只处理 `AND` 连接、且直接作用于分库列的 `>`/`>=`/`<`/`<=`（操作数顺序先归一：`100 < id` ≡ `id > 100`；各边界取最紧的一条：下界取最大、上界取最小）；同一列出现多个范围条件时求**交集**。遇到 `OR`/`NOT` 包裹的节点、非字面量、无法无损解析为 `Int64` 的值 → 返回 `None`（交由路由器按 `Unroutable` 处理）。**可以放宽为更大范围，但绝不能把结果缩小到可能漏行的子集**：因此忽略 `!=` 等非区间条件、保留其余 AND 条件原样下推是安全的。

- **AST 字段命名偏差（实现登记）**：`where` 是仓颉关键字，各语句类的过滤条件属性统一命名为 `condition`（语义与本节 `where` 相同）；其余字段名与本节一致。
- 解析器为**手写词法 + 递归下降**，不引入第三方依赖：token 化（标识符、数字、字符串、`?`、运算符、标点）→ 递归下降产出 AST。
- 标识符大小写不敏感（保留原始拼写用于下推 SQL）；字符串字面量支持单/双引号与 `''` 转义。
- 下推给物理库的 SQL **原样重建**（AST → SQL 渲染由 `SqlRenderer` 完成，见下），不做方言转换（需求：fdbm 不负责 SQL 方言转换）。

### 9.1 会话与游标

```cangjie

protected class CursorSegment <: Resource {      // 一个物理库上的结果集段

    public let result: QueryResult
    public let connection: Connection            // 借出的物理连接，段关闭时归还

    public let columnInfos: Array<ColumnInfoImpl>
    private var cells = HashMap<Int64, Data>()    // 当前行的**单元格缓冲**：惰性填充，随行失效（见「当前行缓冲」）
    private var streams = HashMap<Int64, InputStream>()    // 当前行的流列句柄：每列最多一个，**每行每列只打开一次**
    public func next(): Bool                     // 执行一次物理 next()；段内推进，当前段耗尽切换下一段（行序=库序）；推进前清空 cells 与 streams
    public func cell(index: Int64, bufSize: Int64): Data
    // 列读：命中 cells 直接应答；未命中时普通列走 `SqlTypes.readData`，
    // 流列首次调用 `SqlTypes.readStream(result, index)` 打开并缓存句柄，
    // 之后每次调用用 `SqlTypes.readChunk(stream, bufSize)` 读下一块（bufSize<=0 → DEFAULT_STREAM_CHUNK）
    // （流列判据见 §9.6：驱动自报 InputStream，归一后 tn ∈ {InputStream, std.io.InputStream}）
    public func close(): Unit                    // 关闭全部段并归还全部连接
    public func isClosed(): Bool
}
```

- **多库合并的唯一形态**：`SELECT` 的 `Broadcast`（无分库条件）与 `Multi`（范围路由命中多个分片）共用同一条路径——`SelectExecutor` 为 `plan.databases` 中的每个物理库建一个 `CursorSegment`，按库序串联成一个 `QueryCursor`；对客户端仍然只有"一个游标 + 首包 + 逐行/逐列读"，无需扩展协议。

**当前行缓冲（2026-10-17 用户拍板，与 `openspec` 变更 `implement-f-dbd-driver-and-fdbm-server` 的 D3 一致）**

- **惰性填充**：`cells` / `streams` 在**首次**请求某列时才写入——普通列走 `SqlTypes.readData` 读一次后缓存，流列走 `SqlTypes.readStream` 打开一次后把 `InputStream` **句柄**（不是数据）缓存起来。
- **生命周期随行**：`next()` 推进（含跨段切换）与 `close()` 时**整表清空**；因此缓冲里永远只有当前行的数据，不会跨行串值。
- **为什么必须有**：客户端不缓存（f_dbd §3.10 规则 8），同一单元格重复 `get` 会重复请求；缓冲让重复请求退化成一次内存查表。
- **流列只缓存句柄**：同一行同一列的多次块请求复用**同一个** `InputStream`（对真流式驱动，重复 `get<InputStream>` 等于重复取列值）；句柄同样随行失效。不采用"`NEXT_ROW` 时整行预读"——宽表无谓开销，且大对象无法整行物化。

**会话的默认逻辑库（实现口径，2026-10-18）**

- f_dbd 只把 `database` 放在 URL 里做元信息，协议**没有**"连接时声明逻辑库"的报文（`SqlPayload`
  只有 `sql` / `params`）。因此 `SessionRegistry` 建会话时取 `FdbmSettings.defaultDatabase`：
  只配置了一个逻辑库时取它，否则取第一个节点的第一个物理库。
- 该偏差的边界：多逻辑库部署下，客户端 URL 里的 database **不参与**服务端路由；需要访问其它逻辑库时
  用限定表名（`<logical>.<table>`）或 `show tables <logical>`。后续若引入握手报文，应改这里而不是
  改执行器。

游标规则（与 f_dbd 文档 §3.5/§3.6/§3.6.1/§3.10/§5.5/§7.3 对齐）：

1. **无预读**（2026-10-17 用户拍板）：`QueryCursor` 构造时**不**调用物理 `result.next()`、不预取任何行；首包只描述列信息。客户端的**每次** `next()`（**含第一次**）都会发 `NEXT_ROW`，服务端收到后执行一次物理 `result.next()`、按结果回 `DataBool`，并**重建（清空）当前行缓冲**。`hasData` 与"预取—推进成对"的旧口径已废止，因此不存在首行跳过/重复。
2. 新语句到达先关旧游标；`UNSUBSCRIBE` 按 `payload.qid` 匹配，**无游标 / 已关闭 / qid 不匹配 → 直接回 `ACK`（幂等，不得关闭其它游标）**，匹配才走"清空缓冲 → 读尽物理结果集 → `close()` → 归还连接 → 回 `ACK`"且**无论中途是否抛异常都回 ACK**（详见 §10.2）。只有"列读 / NEXT_ROW"在无游标时才回 `ERROR(CURSOR_STATE)`。
3. 连接断开由 §10.3 的巡检回收。
4. 多段游标：行序 = 库序；任一段在**打开阶段**失败 → 整个查询失败（`ERROR`），已打开的段全部关闭（不做部分成功）。**不跨段预取**：段切换发生在 `next()` 内部（当前段耗尽才推进下一段），因此 A 段为空时仍能读到 B 段的行——这是"无预读"的直接推论，也是 `hasData` 概念被取消的原因。
5. **流列句柄（`streams`）**：同一行同一列的多次块请求复用同一个 `InputStream` 句柄，**绝不重复打开**（对真流式驱动，重复 `get<InputStream>` 等于重复取列值）；`next()` 推进与 `close()` 时清空整个表（物理驱动在结果集前进时回收流，之后不再对其 `read`）。

                bootScript: ?BootScriptWriter, config: FdbmConfig)
    /** 唯一入口：完整 SQL 文本 → 执行结果（内部：parse → bind → route → 分发执行器） */
    public func execute(session: DbdSession, sql: String, params: Array<DataAny>): ExecutionOutcome
}
```

| 执行器（`protected class`，均 `public func execute(session, statement): ExecutionOutcome`） | 职责 |
| --- | --- |
| `SelectExecutor` | 路由 → 对 `Single`/`Multi` 的每个库 `selectRead` 借连接 → `prepareStatement(sql).query()` → 按库序组装多段 `QueryCursor`（连接由游标持有到关闭）；`Broadcast` 走同一路径（库集合=全部物理库）；`Empty` 只借第一个库执行以取列信息（结果必为 0 行）；`Unroutable` 时按 §6.2 的广播合并规则执行。列信息**必须**经 `SqlTypes.canonicalName` 归一成 B 组名后写入 `ColumnInfoImpl.tn`（§9.6） |
| `InsertExecutor` | `insert into ... select ...` 拆解为逐行 INSERT（需求）；分库列缺失时用 `IdGenerator` 生成并回填；`values` 多行按行分组路由（逐行执行、同一事务内） |
| `UpdateExecutor` | 路由（JOIN 收敛规则同 SELECT）；`Single`/`Multi` 逐库执行并把 `rowCount` 求和；`Empty` 直接返回 0、不借连接；`Unroutable`（无分库列条件或范围不可判定）→ `ROUTE_FAILED`；执行前按需求校验缓存中的分库键是否仍指向存在的物理库 |
| `DeleteExecutor` | **先在 `plan.databases` 范围内查受影响行的分库键**（`select <column> from t where ...`）→ 逐库执行删除并累加 `rowCount` → 删除缓存条目（需求原文顺序）；`Empty` 直接返回 0 |
| `ShowExecutor` | `show databases` 返回逻辑库清单；`show tables` 按驱动方言取表清单（见 §9.5） |
| `DdlExecutor` | `create table` / `alter table` 广播到该逻辑库全部物理库；全部成功才算成功（失败：已执行的库不回滚，回 `DB_ERROR` 并列出成功/失败库名——列为限制） |
| `ExportExecutor` | `export k=v` → 校验配置项名合法 → `BootScriptWriter.set/flush` |
| `SessionCtlExecutor` | 会话控制语句：pin/解 pin 写连接，透传执行；未 pin 时对 `commit`/`rollback` 报 `TX_STATE` |

### 9.3 事务与 pin

- `begin`/`start transaction`：若会话未 pin → `selectWrite(database)` 取连接并 pin；随后所有语句（含 SELECT）都走该连接（**read-your-writes**），直到 `commit`/`rollback`。
- `savepoint` / `rollback to` / `release`：透传到 pin 连接。
- `commit`/`rollback`：执行后解 pin 并归还连接。
- 未 pin 的普通语句：每次借还（读走 `selectRead`、写走 `selectWrite`），实现读写分离。

### 9.4 全局表与广播

| 操作 | 行为 |
| --- | --- |
| 读全局表 | 走 `selectRead`（任一副本） |
| 写全局表（INSERT/UPDATE/DELETE） | 广播到该逻辑库的**全部**物理库（`selectAllWrite`）；每库独立事务，全部成功才算成功；部分成功 → `DB_ERROR` 并列出成功/失败库（无两阶段提交，列为限制） |
| 与分片表 JOIN | 全局表可参与任意分片的 JOIN（广播副本保证本地可见） |

### 9.5 SHOW 与方言

- `show databases`：返回 `fdbm_db_logicalDatabase_*` 与节点配置推导出的逻辑库集合（按名称排序）。
- 驱动名来自 `NodeAccessor.driver(database)`（实现侧在 `DatabaseResources` 构造时按节点记录），
  `ShowExecutor` 只按这个名字分支，不自行推断。
- `show tables [db] [like '...']`：由驱动名决定查询方式（**唯一方言相关处**）：
  - `mysql`：`show tables`（可带 `like`）；
  - `postgres` / `opengauss`：`select table_name from information_schema.tables where table_schema='public'`（`like` 转成 `table_name like ...`）；
  - 其它驱动：报 `UNSUPPORTED_SQL`，错误信息中给出"未支持的驱动名"。
- 结果复用 `QueryCursor` 通道返回（列名统一为 `table_name`）。

### 9.6 列类型归一（物理 `typeName` → 仓颉类型名）

**职责**：fdbm 在构造列信息时，把物理驱动 `ColumnInfo.typeName` 经 `SqlTypes.canonicalName`（共用代码，`fountain::f_dbd.common`）归一成 **仓颉类型名**，写入 `ColumnInfoImpl.tn`；列读时也用这个名字作为 `typeName` 调 `SqlTypes.readData`/`readStream`。⇒ **线上（`tn` 与列读请求）永远只出现仓颉类型名**，客户端 f_dbd 不需要认识 `Sql*` 抽象名与方言拼写。

**识别与归一表**（`Sql*` 抽象名、方言拼写 → 仓颉类型名；仓颉类型名自身原样通过）：

| 输入类别 | 取值 | 归一后（仓颉类型名） |
| --- | --- | --- |
| std `Sql*` 抽象名 | `SqlChar` / `SqlVarchar` / `SqlClob` | `String` |
| | `SqlBinary` / `SqlVarBinary` / `SqlBlob` | `Array<Byte>` |
| | `SqlDecimal` / `SqlBool` / `SqlByte` / `SqlSmallInt` / `SqlInteger` / `SqlBigInt` / `SqlReal` / `SqlDouble` / `SqlDate` / `SqlTime` / `SqlTimeTz` / `SqlTimestamp` / `SqlInterval` | `Decimal` / `Bool` / `Int8` / `Int16` / `Int32` / `Int64` / `Float32` / `Float64` / `DateTime` / `DateTime` / `DateTime` / `DateTime` / `Duration` |
| | `SqlNullable*` 变体 | 去掉 `Nullable` 段后按上表 |
| PostgreSQL / openGauss | `bool`；`int2`；`int4`；`int8`；`float4`；`float8`；`numeric` / `money`；`date` / `time` / `timetz` / `timestamp` / `timestamptz` / `timestamp with time zone`；`interval` | `Bool`；`Int16`；`Int32`；`Int64`；`Float32`；`Float64`；`Decimal`；`DateTime`；`Duration` |
| | `char` / `bpchar` / `varchar` / `character varying` / `text` / `clob` / `json` / `jsonb` / `xml` / `uuid` | `String`（文本整块） |
| | `bytea` / `binary` / `varbinary` / `blob` / `bit` / `varbit` / `image` | `Array<Byte>` |
| | 网络/几何/全文检索（`inet`、`cidr`、`macaddr`、`point`、`line`、`lseg`、`box`、`path`、`polygon`、`circle`、`tsvector`、`tsquery`） | `String`（**未知兜底**，记 WARN） |
| MySQL / MariaDB | `TINYINT`；`TINYINT(1)`；`SMALLINT`；`MEDIUMINT` / `INT` / `INTEGER`；`BIGINT`；带 `UNSIGNED` 的整型 | `Int8`；`Bool`；`Int16`；`Int32`；`Int64`；对应 `UInt*` |
| | `FLOAT` / `DOUBLE` / `DECIMAL` / `NUMERIC` / `BIT` / `BOOL` / `BOOLEAN` | `Float32` / `Float64` / `Decimal` / `Decimal` / `Bool` / `Bool` / `Bool` |
| | `CHAR` / `VARCHAR` / `NVARCHAR` / `TINYTEXT` / `TEXT` / `MEDIUMTEXT` / `LONGTEXT` / `ENUM` / `SET` / `JSON` | `String`（文本整块） |
| | `BINARY` / `VARBINARY` / `TINYBLOB` / `BLOB` / `MEDIUMBLOB` / `LONGBLOB` | `Array<Byte>` |
| | `DATE` / `TIME` / `DATETIME` / `TIMESTAMP` / `YEAR` | `DateTime` / `DateTime` / `DateTime` / `DateTime` / `Int32` |
| | `GEOMETRY`、`POINT` 等 | `String`（**未知兜底**，记 WARN） |

- **判定顺序**：① 精确匹配（大小写不敏感）；② 去掉长度/精度后缀 `(...)` 再匹配（`varchar(64)`、`decimal(10,2)`；`TINYINT(1)` 例外——先按 `Bool` 匹配）；③ 精确匹配长名（`tinyint unsigned`、`timestamp with time zone`、`character varying`）→ ④ 短名 → ⑤ 前缀匹配（`varchar2`、`character`）→ ⑥ 仍未命中：`String` + WARN（原始 `typeName` 入日志）。
- **`InputStream` 只由驱动自报决定**：只有物理驱动自己报 `InputStream` / `std.io.InputStream`（即报出的是仓颉类型名）时才归一为流，并按 `SqlTypes.readStream`（打开一次）+ `readChunk`（按块读）处理；**所有"二进制/大对象"的方言与 `Sql*` 名（`bytea`、`*BLOB`、`SqlBlob`…）都归一成 `Array<Byte>` 整块读取**——不猜驱动能力（这是保守口径，代价是可能放弃某些驱动本可提供的流式能力）。
- **驱动能力实测（`f_orm/README.md:1521-1531`，2026-10-06）**：`postgres` / `pgsql` 驱动**不支持** `get<InputStream>`（直接抛 `SqlException`）；`mysqlclient-ffi` 把 BLOB 映射为 `Array<Byte>`（以流请求抛 `data type error`）；`mariadb-driver` / `opengauss-driver` 给出的是**内存副本**（`copyTo` 到 `ByteBuffer`，与结果集生命周期无关）。⇒ 大对象建议"别放 BLOB 列（放对象存储，库里存 key/sha256）或服务端分块查"（同该 README 结论）。
- **落地核对**：接入新驱动时先跑一条 `select`，把物理 `columnInfos[i].typeName`、`SqlTypes.canonicalName` 的输出、以及是否出现 WARN 一起打日志确认；`fdbm_driverDir` 下**只能有一个驱动**（见 §10.5）。

## 10. `fountain::fdbm.server`

### 10.1 `FdbmServer <: Resource`

```cangjie
protected class FdbmServer <: Resource {
    // driver 省略时从 fdbm_driverDir 加载；显式传入供进程内嵌/用例使用
    public init(settings: FdbmSettings, source!: ConfigSource = EnvConfigSource(),
                driver!: ?Driver = None)
    public func start(): Unit          // 阻塞：bind → 注册 handler → 等信号优雅退出
    public func stop(): Unit           // 优雅停止（幂等，见 §10.4）
    public func close(): Unit          // 等价 stop()
    public func isClosed(): Bool
}
```

启动顺序（`normalize()` 的脚本整理失败只记 ERROR、不阻塞启动；其余失败都在**接受连接之前**报错退出）：

1. `CustomLoader.load(FdbmConfig.getCustomDir())`：扫描 `custom/` 下全部动态库并 `PackageInfo.load`；加载完后调用 `InitializerCollection.initialize()`，把返回的 provider 逐个取出并按 `PartitionAlgorithm` / `IdGenerator` 模式匹配，得到 `CustomExtensions`。
2. `FdbmConfig.validate(settings, custom.partitionNames, custom.idGeneratorNames)`（跨项校验；清单见 §11）：`fdbm_partition` 后无 `__<表名>` → 报错退出；`fdbm_loadbalance_weight_<node>_`（只有下划线）→ 报错退出；逻辑库/分区/权重引用的物理库或节点不存在 → 报错退出；分区算法/ID 生成器名不在内置 ∪ 自定义集合 → 报错退出。
3. `DriverLoader.load(driverDir)` → 唯一 `Driver`；逐节点 `driver.open(url, opts)` 建 `Datasource`。
4. `DatabaseResources`（建池，`initSize` 条连接在池构造时建立）。
5. `PartitionRouter`（建规则 + `PartitionCache`，传入 `custom.partitions`）、`GlobalTableRouter`、`IdMakers`（传入 `custom.idGenerators`）、`BootScriptWriter`。
6. `BootScriptWriter.normalize()`：脚本的配置区不符合 §3.5 分块规范时自动整理并覆盖；失败记 ERROR/WARN，不阻塞启动。
7. `SessionRegistry`、`InFlight`、`ServerContext`（含 `custom`）、`Server<DataAny>(bufferQueueSize!: …, bindAt: port, checkDuration!: fdbm_checkDuration, executors!: …, unavailableChecked!: fdbm_unavailableChecked, defaultResp: {id => Message.error(id, data: DbdErrorPayload(INTERNAL, 'no response'))}, checker: 心跳探测消息)`。`checkDuration`/`checker` 在 f_net 中**无默认值**，必须显式传；`defaultResp` 保证"executor 返回 `None`"这条 f_net 兜底路径同样回 `ERROR`（而不是静默不回包）。
8. `ExitCallbacks.toExitGracefully()` + `atExit(stop)`（响应 SIGTERM/SIGINT，需求"响应 kill -15"）。
9. `server.start(handler)`（阻塞）。

### 10.2 请求处理

```cangjie
protected struct FdbmHandler {
    /** f_net Server 的 executor：判别请求种类 → 执行 → 组织响应；任何异常都回 ERROR（不静默） */
    public static func handle(context: ServerContext, buffer: SocketBuffer, message: Message): Message
}
protected class ServerContext {                  // 依赖容器
    public let sessions: SessionRegistry
    public let dispatcher: ExecutorDispatcher
    public let inFlight: InFlight
    public let custom: CustomExtensions            // 自定义 PartitionAlgorithm / IdGenerator
    public let logger: AbstractLogger
}
```

判别与响应规则（与 f_dbd 文档 §7 一一对应）：

| 请求 | 处理 |
| --- | --- |
| 前置校验 | `message.command` 必须是 `CONSUME` 或 `UNSUBSCRIBE`，否则 `ERROR(PROTOCOL)`（PING/ACK 已由 f_net 内部处理，不会到这里） |
| `decodeStrict<SqlPayload>` 命中 | `dispatcher.execute(session, sql, params)` → `RESP`：`QueryResultServerPayload` / `UpdateResultPayload` |
| `decodeStrict<QueryResultColumnPayload>` 命中 | `index>=0` → 单元格 `Data`（无游标 → `ERROR(CURSOR_STATE)`）；`NEXT_ROW` → `DataBool`（无游标 → `ERROR(CURSOR_STATE)`，**不**回 `DataBool(false)`）。**不存在任何表示"关闭"的负索引哨兵** |
| `command == UNSUBSCRIBE` | 载荷按 `decodeStrict<QueryResultClosePayload>` 解 → 按 `qid` 定位会话游标（**无游标 / 已关闭 / qid 不匹配 → 直接回 `ACK`，幂等**）；命中则"清空当前行缓冲 → 循环 `next()` 读尽物理结果集 → `close()` → 归还物理连接 → 回 `ACK`"，**中途异常只记 ERROR 并照常回 `ACK`**（避免客户端卡在 `close()`） |
| `CONSUME` 下两种载荷都不命中 | `ERROR(PROTOCOL)`（记 WARN，附命令与载荷类型） |
| 任意异常 | `FdbmException` → `ERROR(DbdErrorPayload)`；`SqlException` → `DB_ERROR` 并透传 `sqlState` |

- **`qid` 的来源**：创建 `QueryCursor` 时把该次查询 CONSUME 的 `Message.id.toString()` 记为游标的 `qid`（与 f_dbd §3.6.1 同源——客户端取的是同一条 RESP 的 `Message.id`）。当前仍是"一会话一游标"，`qid` 用于校验与日志；多游标扩展时即定位键。
- **关闭后**：游标已关闭的列读 / `NEXT_ROW` 一律 `ERROR(CURSOR_STATE)`（f_dbd §7.3 第 2 步）。

### 10.3 `SessionRegistry` 与 `InFlight`

```cangjie
protected class SessionRegistry <: Resource {
    public init(sweepInterval: Duration, defaultDatabase: String)
    public func of(buffer: SocketBuffer): DbdSession      // 取或建
    public func remove(buffer: SocketBuffer): Unit
    public func closeAll(): Unit                          // 停止时全量回收
    public func isClosed(): Bool
}

protected struct InFlight {                               // 在途请求计数（优雅停止用）
    public static func enter(): Unit
    public static func leave(): Unit
    public static func await(timeout: Duration): Bool     // 归零返回 true，超时返回 false（记 WARN）
    public static func count(): Int64
}
```

- `SessionRegistry.of` 在首次见到某 `SocketBuffer` 时创建会话（键即连接对象，不需要断连回调）。
- **巡检线程**：周期 `fdbm_sessionSweepInterval` 扫描 `buffer.isClosed()` 的会话并 `close()`（归还有 pin 的连接、关闭游标），从表里移除；f_net 未提供断连回调，这是唯一的回收路径（列为约束）。

### 10.4 优雅停止（`stop()`）

1. `server.close()`：停止接受新连接（f_net `TcpServerSocket` 关闭后 accept 循环退出）。
2. `InFlight.await(shutdownTimeout)`：等待已接收请求执行完成并回包（超时记 WARN 后继续）。
3. `sessions.closeAll()`：关闭全部游标、归还 pin 连接。
4. `resources.closeAndAwait(timeout: fdbm_shutdownTimeout)`：先 `pool.close()` 再逐池 `awaitTermination` 等内部任务收尾（**必须在步骤 3 归还全部借用者之后**，否则与源码注释的约束冲突）；未按期终止则记 WARN 并继续收尾。
5. `router.close()`（`PartitionCache`/`Store` 关闭，`syncWAL` 后关闭）。
6. 记 INFO 日志，进程退出（由 `ExitCallbacks` 的 handler `exit(0)` 完成）。

### 10.5 驱动/自定义扩展加载

```cangjie
protected struct DriverLoader {
    /** 扫描目录下 *.so/.dll/.dylib → PackageInfo.load → DriverManager.drivers() 校验唯一性 */
    public static func load(driverDir: String): Driver
}
```

- **可执行文件即命令**（2026-10-17 用户拍板）：fdbm 的 `cjpm.toml` 是 `output-type = "executable"`，构建产物直接运行；在模块目录执行 `cjpm install` 后，可执行文件安装到 `$HOME/.cjpm/bin`（`envsetup` 已把该目录加入 `PATH`），命令行执行 **`fdbm`** 即启动服务。**不注册 `f_app.SubCommand`、不解析子命令、不再依赖 `f_app.App`**。
  - 动态依赖：`cjpm install` 会把 `f_app`/`f_base`/`f_dbm` 等库装到 `$HOME/.cjpm/libs/fdbm`，运行前需把该目录加入 `LD_LIBRARY_PATH`（Windows 为 `PATH`，macOS 为 `DYLD_FALLBACK_LIBRARY_PATH`），或按本节末的部署约定把库放到可执行文件同目录。
- `main`（无参数）：

```cangjie
main(): Int64 {
    try {
        FdbmServer(FdbmSettings.load()).start()   // 阻塞：初始化 → 监听 → 等信号优雅退出
        return 0
    } catch (e: FdbmException) {
        LoggerFactory.getLogger('fdbm').error('fdbm 启动失败: ${e.message}')
        return 1                                   // 显式退出码，便于 boot.sh/容器判活
    }
}
```

- **`InitializerCollection` 的消费时机**：`FdbmServer.start()` 第 1 步 `CustomLoader.load` 内调用 `InitializerCollection.initialize()`；fdbm 没有 `App.run/load`，不存在集合被提前消费的问题，且全进程只消费一次。
- 不再提供 `version`/`help` 子命令；版本信息由构建产物、部署包或脚本读取（`f_version`），不占用进程入口。
- 驱动唯一性：加载后 `DriverManager.drivers()` 里**不同的驱动实例只能有一个**（真实驱动常注册多个别名，如 `postgres`/`postgresql`/`pg`，只要别名解析到同一实例即可）；且必须包含各节点 `fdbm_db_driver_<node>` 配置的名字，否则 `FdbmException(NO_DRIVER)` 并结束进程（需求"如果有两个驱动要报错并结束进程"）。2026-10-18 真库联调按此后口径修正。
- **`f_dbm` 动态库随 fdbm 部署**：`libf_dbm.so`（或平台对应 `.dylib`/`.dll`）必须与 `fdbm` 可执行文件同目录，或位于系统库搜索路径（`LD_LIBRARY_PATH` / `DYLD_LIBRARY_PATH` / `PATH`）；它不属于 `driver/` 目录（那里只放物理数据库驱动）。`boot.sh` 的启动目录即部署目录，部署包需同时包含该库。

**自定义扩展加载（`custom/`）**

```cangjie
protected class CustomExtensions {
    public let partitions: HashMap<String, PartitionAlgorithm>
    public let idGenerators: HashMap<String, IdGenerator>
    public func partitionNames(): Array<String>
    public func idGeneratorNames(): Array<String>
}

protected struct CustomLoader {
    /** 加载 customDir 下全部动态库 → InitializerCollection.initialize() → 收集扩展实现 */
    public static func load(customDir: String): CustomExtensions
}
```

- 目录：`fdbm_customDir`，默认 `<工作目录>/custom`，与 `driver/` 同级；目录不存在 → 返回空扩展（INFO），不算错误。
- 加载：扫描 `*.so` / `*.dll` / `*.dylib`，按文件名排序；逐个 `PackageInfo.load(pathWithoutExtension)`。**全部加载完**后才调用 `InitializerCollection.initialize()`，保证所有包 `static init` 的注册都已完成。
- 收集：遍历 `initialize()` 返回的 `ArrayList<() -> Initializer>`，对每个 provider 调用一次取得实例；用两轮模式匹配分别收集 `PartitionAlgorithm` 与 `IdGenerator`（同一实例可同时命中两者）。
- 注册：开发者的动态库必须在包 `static init` 中调用 `InitializerCollection.register(This())`；否则 `initialize()` 看不到它。
- 命名冲突：`CustomLoader` 拒绝**自定义之间**的重名；与内置（分区算法 `step/hash/crc16/crc32/crc64/murmur`、ID 生成器 `uuid/snowflake/sequence`）重名由 `FdbmConfig.validate` 拒绝 → `FdbmException(PARTITION_CONFIG | CONFIG)`，启动失败；**不允许覆盖内置实现**。
- 异常：任一动态库加载失败，或任一 `Initializer.initialize()` 抛异常 → 包装为 `FdbmException(CONFIG)`，启动失败（不静默跳过）。
- 初始化契约：`Initializer.initialize()` 在 fdbm 的资源、驱动、服务创建**之前**执行；自定义实现只能读 `Config`、准备自身状态，不得依赖 `DatabaseResources` / `SessionRegistry` / `FdbmServer`。fdbm 不调用 `Initializer.start()`。
- `custom/` 库中注册的**所有** `Initializer` 都会被 `initialize()` 执行；非扩展实现也会产生副作用，因此 custom 目录只应放扩展库。
- 开发方式：类同时实现 `PartitionAlgorithm & Initializer` 或 `IdGenerator & Initializer`，编译为动态库放入 `custom/`。两个接口都有 `name` 属性，同时实现时只有一个 `name`，其值即扩展名，也是 `Initializer` 的唯一标识。

```cangjie
// 自定义分区算法（自定义 ID 生成器同理：IdGenerator & Initializer）
class MyPartition <: PartitionAlgorithm & Initializer {
    static init() {
        InitializerCollection.register(MyPartition())
    }
    private init() {}
    public prop name: String { get() { 'myhash' } }   // 扩展名 + Initializer 名
    public func partition<K>(key: K): String { /* ... */ }
    public func initialize(): Unit { /* 读 Config，准备自身状态；不得依赖 fdbm 资源 */ }
}
```

- 自定义库链接 `f_dbm` / `f_app`；部署时这两个库必须与 fdbm 在同一库搜索路径（通常就是部署目录）。
- `f_app` 的 `InitializerCollection.initialize()` 已改为 `public static func initialize(): ArrayList<() -> Initializer>`；fdbm 调用一次后集合被清空，后续不应重复调用。

## 12. 关键设计决策与取舍

| 决策 | 理由 | 代价/限制 |
| --- | --- | --- |
| 会话 = TCP 连接（`SocketBuffer`），一连接一游标 | payload 无标识字段；服务端状态最少 | 同连接多语句交错读不支持（打开新游标即关旧游标） |
| **不做 `f_app` 子命令，可执行文件直接运行**（2026-10-17 用户拍板） | fdbm 只有一个运行形态；`output-type = "executable"` + `cjpm install` 后 `fdbm` 已在 `PATH`，无需 `SubCommand`/`SubCommandMediator`/`App` 的分发层 | `f_app` 仅保留 `Initializer`/`InitializerCollection`；不提供 `fdbm version/help` 子命令；部署要求 `$HOME/.cjpm/bin` 在 `PATH`（`envsetup` 已加） |
| **可扩展接口下沉到 `f_dbm` 动态库**（2026-10-17 用户拍板） | fdbm 是可执行模块，外部无法 import 其声明；接口放独立动态库后，外部实现只依赖 `f_dbm`，fdbm 单向依赖接口库 | 接口库只声明接口；实现发现/注册由 `custom/` + `InitializerCollection` 负责（见下行） |
| **自定义扩展通过 `custom/` + `InitializerCollection` 发现**（2026-10-17 用户拍板） | 开发者只依赖 `f_dbm` / `f_app`；先加载全部动态库再 `initialize()`，保证所有 `static init` 注册完成；用模式匹配收集，无需反射枚举 | 加载失败阻止启动；自定义实现必须自包含（`initialize()` 阶段没有 fdbm 资源）；`name` 冲突直接拒绝；`InitializerCollection` 只能消费一次 |
| `InitializerCollection.initialize` 改为返回 `ArrayList<() -> Initializer>` | 宿主需要初始化后的实例做模式匹配，而不只是启动函数 | `f_app` 的 `App`/`load` 已同步；fdbm 直接在 `main` 路径中调用 `initialize()`，不经过 `App`，取实例后不调用 `start()` |
| **列类型只在线上出现仓颉类型名**（fdbm 归一，2026-10-14 用户拍板） | 客户端不必认识各方言与 `Sql*` 抽象拼写；`typeName` 直接就是 `get<T>` 的 `T` | fdbm 需维护识别表（§9.6）；`InputStream` 只由驱动**自报**触发，方言大对象名（`bytea`/`*BLOB`）一律按 `Array<Byte>` 整块读，可能放弃个别驱动本可提供的流式能力 |
| 连接借还粒度：语句级，游标/事务例外 | 读写分离要求每次按语句选节点；事务必须固定连接 | 长游标会占住连接，池 `maxSize` 需 ≥ 并发长查询数 |
| **查询不预读、首包只有列信息**（2026-10-17 用户拍板） | 客户端每次 `next()`（含第一次）都真正推进物理游标，服务端没有"已预取但未交付"的隐藏状态，首行不会跳过/重复；打开阶段也不必为拿列信息先读一行 | 空结果集也要一次 `NEXT_ROW` 才得知无行；列读 1+n 次往返的开销不变（见下行） |
| **服务端维护"当前行缓冲"（惰性填充 + 随行失效）**（2026-10-17 用户拍板） | 客户端不缓存，同一单元格重复 `get` 会重复请求；缓冲让重复请求退化成内存查表。流列缓存的是**句柄**——真流式驱动重复 `get<InputStream>` 等于重复取列值 | 宽表上只读少数列也只付少数列的代价，但**不**整行预读（大对象无法整行物化）；缓冲随 `NEXT_ROW`/`UNSUBSCRIBE` 整表清空 |
| **关闭走 `UNSUBSCRIBE(qid)` → `ACK`，不复用列读通道**（2026-10-17 用户拍板） | 关闭是控制面操作；用 `Message.unsubscribe` 语义更准确，也避免把"关闭"混进 `QueryResultColumnPayload` 的列索引（**不存在 `CLOSE_CURSOR` 哨兵**）。`qid` 显式标识目标结果集，为同连接多游标留出扩展位 | 关闭多一次 RTT；需从查询 CONSUME 的 `Message.id` 捕获 `qid`；未匹配时按幂等 `ACK` 处理（不得误关别的游标） |
| **新增 `substr` 分库算法**（2026-10-17 用户拍板） | 业务常用“编码前缀/号段”分库（如订单号前 4 位、账号前 2 位），按子串哈希即可覆盖 `hashCode`/CRC 族/Murmur，无需自定义算法 | 参数按表配置（`fdbm_partition_substr__<table>`），`start` 0 起按 Unicode 码点；短于 `start+1` 的键报 `ROUTE_FAILED`（不静默聚集）；无单调性，范围条件仍 `Unroutable`；大小写与前导零敏感 |
| **`step` 分片支持范围路由**（2026-10-17 用户拍板） | `>`/`>=`/`<`/`<=`/`BETWEEN` 能映射为**连续**分片区间，没必要广播；多库结果复用广播的合并路径 | 只有 `step` 单调可分，其余算法仍 `Unroutable`；`OR`/`NOT`、跨分片键 JOIN 不展开；`[1, N*step]` 是有效数据域，**越界键改为报错而不是回绕**（与早期版本的行为不同，换取范围路由的单调性与正确性）；多库 `order by`/`limit` 语义不严格 |
| SELECT 无分库条件时广播合并 | 需求"尽量使用简单 SQL"下仍要可用 | 多库结果按库顺序串行合并；`order by`/`limit` 语义仅在单库下严格（多库时按分片顺序拼接，列为限制） |
| 全局表写广播、无 2PC | 需求只要求"每个物理库有一副副本" | 部分失败需人工/重试（错误信息列出成功与失败的库） |
| `show tables` 按驱动方言分支 | 没有统一的跨库元数据接口 | 只支持 mysql / postgres(opengauss) 两种方言（数据库兼容性要求正好是两个） |
| 事务隔离级别属性不下发 | fdbm 不做方言转换 | 见 f_dbd 文档 §9（同一决策） |
| 缓存容量靠 fdbm 计数（超限停写） | `f_store` 无容量/淘汰 API | 缓存只增不减（除非过期/一致性删除）；列为后续优化点 |
| `LoadBalance` 用 `<Int64, Unit, Connection>` | `D` 是函数入参类型，不是节点类型 | 与需求草图字面不同（已在 §5 说明） |
| `export` 落盘按功能分块重写 `boot.sh` 配置区；启动时 `normalize()` 自动整理旧脚本 | 需求明确要求落盘；配置项多且按节点/库展开，分块 + 逐键注释才可读、可审；启动时统一整理，避免旧脚本长期停留在未分块格式 | 每次启动多一次脚本读取/可能的写回；旧格式 `fdbm_*` 导出会迁入 managed 区块；整理失败不阻塞启动；区块由 fdbm 独占，手工编辑会被覆盖；可写键限于 `FdbmConfig` 白名单 |
| 心跳检查周期默认 30s | `f_net.Server` 在语句执行期间读不到心跳 ACK，阈值过小会误杀长语句 | 单条语句超过约 `3 × fdbm_checkDuration` 会被断链；超长语句需调大该值（§3.1 说明） |
| 优雅停止仅在 POSIX 生效 | `f_base.ExitCallbacks` 在 Windows 是空实现（`@When[os == "Windows"]`） | Windows 下用 `fboot shutdown <pid>`（`process.terminate()`）代替 `kill -15`；服务端部署以 Linux 为准 |
| 连接即会话 + f_net 静默重建 | 会话/游标/事务 pin 全部键在 TCP 连接上 | 重建后服务端视为新会话 → 客户端的游标/事务操作得到 `CURSOR_STATE`/`TX_STATE`（fail-fast；与 f_dbd 文档 §7.4 同一约定） |
| `category` 取允许清单五项 | 需求草图的 `'Database Middleware'` 不在 cjpm 允许分类清单内 | `Database Framework` / `Distributed` / `Data Encapsulation and Transfer` / `Network` / `Infrastructure`；不给 `Database Driver`（fdbm 是服务端，不是驱动） |

**必须固化的不变量**

1. 任何请求都有响应（`RESP` 或 `ERROR`）；异常不得穿透 handler。
2. 新语句必先关闭旧游标；`UNSUBSCRIBE` 幂等（`qid` 不匹配 / 无游标 / 已关闭 → 直接 `ACK`，且不得关闭其它游标）；命中时的"清空缓冲 → 读尽 → 关闭 → 归还 → ACK"无论中途是否抛异常都回 `ACK`。
3. 事务内所有语句落到同一物理连接；`commit`/`rollback` 后连接归还。
4. 写语句无分库条件 → 拒绝执行（不广播、不猜测）。
5. 缓存写与删：只有"确认该值确实落在某物理库"才写缓存；DELETE 先删库记录再删缓存；缓存指向不存在库时必须失效。
6. 启动自检清单（§11）每一条都有对应负例测试。
7. **查询不预读**：构造 `QueryCursor` 不调用物理 `next()`；每次 `NEXT_ROW`（含第一次）恰好推进一次物理游标并重建当前行缓冲（§9.1 规则 1）。
8. **当前行缓冲随行失效**：同一行内重复列读从缓冲应答（流列句柄只打开一次）；`NEXT_ROW` 推进与 `UNSUBSCRIBE` 关闭都整表清空（§9.1）。
