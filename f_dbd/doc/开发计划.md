# f_dbd 开发计划（**TDD**）

> 依据 `f_dbd/doc/详细设计.md`。开发方式：**每个公共成员先写失败用例（红）→ 最小实现（绿）→ 重构**；每个 Step 结束必须 `cjpm test` 全绿再进入下一步。
> 用例文件与被测包同包（`*_test.cj`），可用 `@Test` / `@TestCase` / `@Assert`（`std.unittest`）。

## 通用约定

- **文件命名**：`src/<pkg>/<Type>_test.cj`；一条不变量一个 `@TestCase`，用例名用中文描述行为。
- **payload 字段规则（硬约束，设计 §3.4 规则 1–5）**：数据字段一律 `private var` **且在声明处带初值**；宏 `props` 会把私有字段改名 `<名字>_` 并生成**原名**的 `mut` 属性（线上键名就是原字段名）。**禁止** `let` 字段（含手写非 mut `prop`）——只能编码、无法解码；**禁止**把初值搬到构造函数——宏改名后构造函数命中的是属性而不是字段，确定初始化过不去。`SqlPayload.params` 曾照草图写成 `let`，已修为 `var`（否则 fdbm 解不出参数）。
- **测试替身**：
  - 协议层用例：进程内起 `f_net.Server<DataAny>` 桩（回环端口，端口先用 `TcpServerSocket(bindAt: 0)` 探空闲端口再传给 `Server`），按 `详细设计.md` §7.1 报文矩阵应答；
  - `SqlTypes.readData/readStream` 需要真实 `QueryResult`：用 `f_mockdb`（`cjpm.toml` 已声明 `[test-dependencies]`）或同包手写最小 `QueryResult` 桩（优先前者，减少重复）。
- **提交**：每个 Step 一个提交；提交前统一 LF（换行符治理）。
- **完成定义（DoD）**：① 该 Step 全部用例绿；② `cjpm build` 无新增 warning；③ 详细设计中的对应"必须固化的不变量"有用例覆盖。

## 阶段 1：`fountain::f_dbd.common`（共用代码，不依赖网络）

### Step 1.1 `SqlPayload`

| 公共成员 | 先行用例（红） | 实现要点 / 验收 |
| --- | --- | --- |
| `init()` / `init(sql)` | 空构造 `sql == ''`、`params` 为空；`init('select 1')` 后 `sql == 'select 1'` | `sql` 默认值 `''`；`params` 为 `let` 空 `ArrayList` |
| `sql`（props） | 属性可读且与构造一致 | `@DataAssist[fields props]` 生成；不可写（无 setter） |
| `params`（props） | 加入 2 个参数后 `params.size == 2` | 同上 |
| `add<T>(param)` | `add<String>('a')`、`add<Int64>(1)` 各一条：末位 `DataAny.data` 分别为 `DataString` / `DataReal` | 委托 `param.toData()`；`Data` 自身也可 `add<Data>(d)` |
| `addNull()` | 末位 `params[i].data is DataNone` | `add(DataAny(DataNone.INSTANCE))` |

**往返用例（本 Step 必做）**：`DefaultCodec().encode(payload).finish()` → `decode<SqlPayload>`，断言 `sql`、`params.size` 与逐个参数的值/类型一致（**这条就是"`params` 必须 `var`"的回归用例**：写成 `let` 时 `params` 会被静默跳过、个数为 0）。**验收**：`SqlPayload` 的字段类型全部满足 `DataFields`（编译期即证明）。

### Step 1.2 `UpdateResultPayload`

| 公共成员 | 先行用例 | 实现要点 / 验收 |
| --- | --- | --- |
| `init()` / `init(rowCount, lastInsertId)` | ① 无参构造后 `rc`/`liid` 为 `0`；② 全参构造后分别等于入参 | 无参构造供解码；全参构造写的是宏生成的 `mut prop rc`/`liid` |
| `rc` / `liid`（`props` 生成的 `mut` 属性） | 可读可写；`toData()` 后的键集合**恰好**是 `{rc, liid}` | **这条是 `@DataExclude[field]` 的回归**：排除一旦失效，键集合会多出 `rowCount`/`lastInsertId`，严格解码会因"找不到可变字段"报错 |
| `rowCount` / `lastInsertId`（手写只读属性） | ① `let r: UpdateResult = UpdateResultPayload(3, 7)` 直接可读两属性（**无适配器**）；② 对它赋值编译期即被拒 | 实现 `UpdateResult`；`@DataExclude[field]` 排除出序列化 |

**往返用例**：`DefaultCodec` 编解码往返后 `rc`/`liid` 不变；**再用 `decodeStrict<UpdateResultPayload>`（严格 flag）走一遍**（严格通过这条钉住"数据字段可解码"，见设计 §3.4 规则 1–6）。

### Step 1.7 `decodeStrict<T>`（顶层函数）

| 公共成员 | 先行用例 | 实现要点 / 验收 |
| --- | --- | --- |
| `decodeStrict<T>(data)` | **四个正例**（`SqlPayload` / `QueryResultColumnPayload` / `QueryResultServerPayload` / `UpdateResultPayload` / `DbdErrorPayload` 各自编解码后都必须命中——其中四类含 `Int64` 字段，是本条的关键）；**交叉负例**（上列任意两类的 `DataObject` 互相喂给对方的 `decodeStrict` → `None`）；`DataNone` → `None`；`DataAny` 包裹一层后仍命中；**越界数值回归**：某字段为越界 `DataReal` 的合法载荷必须命中（`WRAPPING` 语义）且**不得抛出 `OverflowException`** | `convert<T>(data, flag: DEFAULT_DATA_FLAG & !SILENCE)`（仓颉位反是 `!`，无 `~`）+ 捕获 `DataException`；**严禁 `flag: 0`**（`NumberData` 的整数分支要求溢出策略位），**也不得换成 `THROWING`**（越界会抛 `OverflowException` 穿透 `catch (_: DataException)`，见设计 §3.2 第 3 条） |

### Step 1.8 `SqlTypes`（类型映射与转换）

| 公共成员 | 先行用例 | 实现要点 / 验收 |
| --- | --- | --- |
| `readType(typeName)` | **表驱动覆盖设计 §8 三组**：A 组 `SqlVarchar`/`SqlBigInt`/`SqlBlob`/`SqlTimestamp`/`SqlNullableBigInt`；B 组 `Int64`/`String`/`Array<Byte>`/`std.io.InputStream`/`std.time.DateTime`；C 组 `int4`/`float8`/`bytea`/`timestamptz`/`numeric`/`money`/`BIGINT`/`TINYINT(1)`/`TINYINT UNSIGNED`/`timestamp with time zone`/`character varying`/`varchar(64)`/`decimal(10,2)`；**边界**：大小写混合、长度后缀、未知值（`uuid`/`jsonb`/`GEOMETRY`）→ `Unknown` | 判定顺序 = 忽略大小写 → 去 `(...)`（`TINYINT(1)` 先按 Boolean）→ 长名 → 短名 → 前缀；流集合见 §8 末条 |
| `encodeParameter<T>(value)` | 表驱动：§8 支持类型集合逐个断言编码出的 `Data` 子类；不支持类型（如自定义 `class Foo{}`）抛 `DataException` | `Any` 装箱 + `match`：基础类型分支在前、`is ToData` 兜底 |
| `decode<T>(data)` | **B 口径**（越界即报错）：① `DataNone` → `None`；② `DataReal(1)` → `Some(1i64)`/`Some(1i32)`（区间内精确）；③ **越界**：`DataReal(300)` → `Int8`、`DataReal(2^40)` → `Int32` → **抛 `DataException`/`OverflowException`**（用例断言"抛"，并断言**不回绕**：不得返回 `Some(44i8)` 之类的值）；④ **分数值**：`DataReal(3.7)` → `Int64` → 抛异常（不截断）；⑤ **宽松保留**：`DataReal(1)` → `String` → `Some('1')`（`IGNORE_FIELD_TYPE_NOT_MATCH` 在位）；⑥ **不可转换**：`DataString('abc')` → `Int64` → 抛 `DataException`；⑦ 异常面只允许 `DataException`/`OverflowException` 两种 | `convert<T>(data, flag: CELL_READ_FLAG)` + 同时捕获 `DataException`/`OverflowException`；`DbdQueryResult.get` 把 `None` 与两种异常统一转 `DbdException(CONVERSION)` |
| `readData(result, index, typeName)` | 用 f_mockdb 结果集：整数/字符串/NULL/二进制各一条，断言 `Data` 子类与值 | `getOrNull<T>` 判 NULL → `DataNone.INSTANCE`；否则 `T.toData()` |
| `readStream(result, index, size)` | ① 流长度 > size → 返回恰好 size 字节；② 流长度 < size → 返回全部字节（EOF 由后续 0 字节请求表征）；③ 空流 → 空数组 | `get<InputStream>` + 一次 `read`；不缓冲 |
| `SqlReadType` | 每个枚举值 `toString()` | — |

**验收**：映射表与设计文档 §8 一一对应（用例即文档的镜像）。

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| `set<T>` 的运行时类型判定在仓颉中的写法（`Any` 装箱 + `is ToData`）与预期不符 | 阶段 1 Step 1.8 第一件事就是用例验证该写法；不成立时退回 `TypeInfo` 分派（用例不变） |
| 列读的 1+n 次往返导致慢查询 | 阶段 3 用计时用例量化（`fetch` 每行 RTT 次数）；先保证正确性，优化（整行预取）留待 fdbm 阶段按测量决定 |
| 进程内 `f_net.Server` 桩的稳定性 | 桩只做收发与会话脚本化，不引业务逻辑；连接数固定 1 |
