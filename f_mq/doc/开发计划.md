# f_mq 开发计划（TDD）

> 设计见同目录 `详细设计.md`（下称「设计」）；服务端 `fmq` 见 `../../fmq/doc/开发计划.md`。
> 本文按「**每个公共成员声明**」给出 TDD 步骤：先写失败用例（Red）→ 最小实现（Green）→ 重构（Refactor）→ 回归。

## 前置

1. 工作区：本次开发在 worktree `.worktrees/feature-mq`（分支 `feature/mq`）内进行。
2. 已就绪：`f_mq/cjpm.toml`（dynamic + category）、`f_mq/src/f_mq.cj`（占位）。
3. 环境（WSL Ubuntu-24.04）：

```bash
source /mnt/d/docs/work/cangjie/cangjie.sh      # bash -lc 不读 ~/.bashrc，必须显式 source；不要 set -u
cd /mnt/d/docs/work/cangjie/projects/fountain/.worktrees/feature-mq/f_mq
cjpm build && cjpm test
```

4. 用例放置约定：用例文件与实现同目录，命名 `<Type>_test.cj`（对齐 `f_dbpool/src/DatabasePool_test.cj`）；
   用例用 `@TestCase` + `@Expect(...)`。
5. 每步的完成判据：**新增用例全绿 + 本模块全量 `cjpm test` 全绿**；跨模块回归（`fmq`、`frpcdemo`）见 `fmq` 计划。

| `closeIsIdempotent` | 两次 `close()` 不抛；`isClosed()` 为真 |
| `callsAfterCloseThrow` | `publish/subscribe/consume/ack` 都抛 `MQConnectionException` |
| `concurrentCallsDuringClose` | 一个线程 `close`、其它线程持续调用：不崩、不挂（异常被捕获即可） |

**Green**：`closeLock` + 标记；异常统一从 `MQNodePool.clientOf` 抛出。
**Refactor**：统一「已关闭」检查入口。
