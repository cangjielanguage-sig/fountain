# 验证：optimize-helper-table

## 1. 环境

- aarch64 共享 VM（7 核 A53），`taskset -c 0-4`
- 探针：同一份源码 `{ => fn0(1) }`，只改注册函数数量（4 / 204），每档 3 轮取最小、5 万次调用
- 探针在测后删除

## 2. 数据

单位 µs/call。

| 注册函数数 | 改前（两轮） | 改后（两轮） |
| --- | --- | --- |
| 4 | 11.7 / 11.9 | **4.03 / 7.70** |
| 204 | **103 / 197** | **3.97 / 7.60** |
| 差值（204 − 4） | **+91 / +185** | **−0.06 / −0.09** |
| 每项每次调用 | 456 / 925 ns | **≈0** |

**结论**：helper 表构建从 **O(F)/call** 变成 **O(1)/call**。
204 个 helper 时每次调用从 103–197 µs 降到 4.0–7.6 µs（**−96%**），
且不再随注册函数数量增长（差值为 0 在噪声内）。

## 4. 变异

本变更的语义不变，功能用例对「重建 vs 复用」不敏感（两种实现结果相同），
因此**判定依据是 §2 的 A/B 数据**，不设功能变异。这一点在 design §3 已预先说明。
