# 并发矩阵测试：四类并行场景的语义护栏

## Why

f_jit 的并行能力已有若干零散护栏，但没有一条用例按**用户实际使用方式**把并发场景作为整体验收：

- `ParallelCall_test` 只覆盖「同一个已编译单元被多线程调用」，不含编译侧；
- `CompileConcurrency_test` 只覆盖「4 线程编译不同源码」，且是为 A64 审计表竞态而建；
- `CompileCache_test.concurrentPipelineRunsOnce` 用**模拟**函数验证 claim/finish 状态机，
  从未真正并发编译同一源码；
- 「同一闭包」与「不同闭包」的调用只测到 2–4 线程，且无捕获、无 user helper、无错误槽混合。

结果是三类真实场景在回归网里完全空白：**并发编译同一源码**（同键去重）、
**不同单元同名 user helper 的隔离**、**同一包装闭包上的正常/错误混合调用**。

## What Changes

新增 `src/ConcurrencyMatrix_test.cj`，5 个用例：

1. **并发编译同一源码**：6 线程 × 20 次，断言管线累计只跑 1 次、全部调用正确、
   关闭任一实例后其余实例同时进入终态（证明各线程拿到同一个对象）。
2. **并发编译不同源码**：6 线程 × 8 个唯一源码，断言 48 次独立管线、每个单元只执行自己的语义。
3. **并发调用同一闭包**：`callForFn` 包装 + 捕获变量，6 线程混合正常值与除零，
   断言正常值恒为 `x + 1000`、错误线程恒 `DIV_ZERO`、结束后包装仍可用且 `close` 幂等。
4. **并发调用不同闭包**：3 个单元各自注册**同名** `hh`（同一 hid、不同实现），
   6 线程轮转交错调用，断言互不串味且句柄账目回到基线。
5. **附加：编译与调用混合**：1 线程持续编译新单元，4 线程持续调用老单元，断言结果正确。

## Impact

- 只新增测试文件，不改生产代码；
- 5 个用例合计约 70 ms，对全量无感；
- 若任用例在现行实现上变红，说明存在真实并发缺陷，按正确性缺陷单独处理，
  不在本变更内静默改实现。
