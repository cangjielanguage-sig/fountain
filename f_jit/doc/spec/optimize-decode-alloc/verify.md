# 验证：optimize-decode-alloc

## 1. 环境

aarch64 共享 VM，`taskset -c 0-4`；`JitCompiler.compileUnitWith` 同进程 21 次中位数，每臂 3 个进程。

## 2. 数据：未测得收益

| 臂 | 各进程（ms） | 最优配对 |
| --- | --- | --- |
| 改前 | **1.946** / 3.346 / 2.162 | — |
| 改后 | 2.075 / 3.141 / 3.206 | 1.946 → 2.075（**+6.6%**） |

慢模式方向相反（3.346 → 3.141，−6.1%），快模式反而变差 6.6%——两个方向都在本机噪声内
（同臂跨进程本身就有 ±40% 波动）。**本轮无绩效证据**。

改动保留的理由（不含加速宣称）：
1. 每编译少 250 次操作数数组分配（A64 + x86 各一份），是**严格更少的工作**；
2. `X86Lower` 顺带删掉了上一轮引入的 `DecodedInsn` 缓存（连第一次解码都不需要），代码更短；
3. 与 `Assembler.validateFunc` 的既有做法统一（同一条「降低/校验只直读」的路径）。
