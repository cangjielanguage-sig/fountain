# Spec Delta

## ADDED Requirements

### Requirement: 一元逻辑非的三引擎差分回归

每条一元 `!` 用例 SHALL 同时断言两件事：解释器结果等于语言语义的**绝对期望值**；全部可用引擎的结果 / 错误码 / site / 报告文本四元组逐位一致（I7）。覆盖矩阵 SHALL 含比较、布尔字面量、布尔实参、双重取反、`&&` / `||` 与正则 `!~`，取值 SHALL 含 49/50 边界与 Int64 极值。不可用引擎 SHALL 按既有条件跳过并计「无证据」，SHALL NOT 计为通过。

#### Scenario: 报障用例

- **WHEN** 执行 `{ n: Int64 => !(n < 50) }` 且 `n = 49`
- **THEN** 解释器与每个可用后端的结果均为 `0`（`false`）；任一引擎给出非 `0` 即失败

#### Scenario: 边界两侧

- **WHEN** 对同一函数分别取 `n = 48, 49, 50, 51` 与 `Int64.Min` / `Int64.Max`
- **THEN** 结果为 `0, 0, 1, 1, 0, 1`，三引擎逐位相同

#### Scenario: 生产者矩阵

- **WHEN** 对比较、布尔字面量、布尔实参、`!!x`、`x && y`、`x || y`、`re !~ s` 各执行一次取反
- **THEN** 每个生产者的取反结果都等于其真值的逻辑非，且三引擎一致

#### Scenario: 绝对值锚定防「一致地错」

- **WHEN** 任一引擎与解释器一致但解释器本身不等于语义期望
- **THEN** 用例仍失败（不允许以「引擎间一致」替代语义正确）

#### Scenario: 无 `!` 对照不被改动

- **WHEN** 执行 `{ n: Int64 => n < 50 }` 且 `n = 49`
- **THEN** 结果为 `1`，与修复前逐位相同（证明修复未触碰比较语义）

#### Scenario: 非原生跳过

- **WHEN** 本机只有解释器与 AArch64 可用
- **THEN** x86_64 记入跳过统计并保留引擎名，用例只以两侧证据判定
