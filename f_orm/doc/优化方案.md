## 2026-05-05 | 初版审查 | 覆盖范围: f_orm/src/migro/*.cj

### 审查发现

#### [P1] MariaDBSchemaFinder.driverName = 'mysql' 与 MysqlSchemaFinder 冲突
- **文件**: `MysqlSchema.cj:173-178`
- **说明**: 两个 `@Bean` finder 使用相同 driverName，后者覆盖前者。
- **修复**: 改为 `'mariadb'`。✅ 已提交

#### [P1] generateDropTableSql 从未被调用
- **文件**: `SchemaFinderMediator.cj` (原实现)
- **说明**: 接口定义了、两套实现都写了，但 mediator 不生成 DROP TABLE。
- **修复**: 新增 `SchemaFinder.listTables()` 接口 + 两套实现 + mediator 中生成 DROP TABLE。✅ 已提交

#### [P1] Postgres ALTER COLUMN SET/DROP NOT NULL 缺列名
- **文件**: `PostgresSchema.cj:147,149,164,166,175,176`
- **说明**: `alter table t set not null` 不指定列名，PostgreSQL 要求 `ALTER COLUMN col SET NOT NULL`。
- **修复**: 加上 `alter column ${name}`。✅ 已提交

#### [P1] Postgres ALTER 缺失 TYPE 变更
- **文件**: `PostgresSchema.cj:157`
- **说明**: 比较 `column != c` 时只生成了 nullable/default 的 ALTER，没有 ALTER COLUMN ... TYPE。
- **修复**: 增加 `alter column ${column.columnName} type ${column.typeName}`。✅ 已提交

#### [P3] 重命名时 default/extra 用旧列值
- **文件**: `MysqlSchema.cj:120`
- **说明**: CHANGE 语句中 default/extra 来自 `column`（旧列），但 typeName/nullable 来自 `c`（新列）。
- **修复**: 改为统一使用新列 `c` ✅ 已提交

#### [P3] 默认值引号未转义（MySQL + Postgres 共 10 处）
- **文件**: MysqlSchema.cj + PostgresSchema.cj (generateColumn, generateAlterSql, generateCreateSql, generateIndexSql)
- **说明**: `"default '${d}'"` 中若默认值含 `'`，生成的 SQL 语法错误。
- **修复**: 添加 `esc(val)` 辅助函数替换 `'` 为 `''`；修复 Postgres CREATE TABLE 中 `m.default` 未调 `getOrThrow()` 导致输出 `Some(value)` ✅ 已提交

#### [P2] 重复的 HashMap 构造模式
- **文件**: MysqlSchema.cj + PostgresSchema.cj 的 generateAlterSql/IndexSql 共 4 处
- **说明**: `fold(HashMap<...>()){m, i => m[i.name] = i; m}` 重复 4 次
- **修复**: 提取 `indexColumns()` / `indexIndexes()` 静态辅助方法到两个抽象类 ✅ 已提交

#### [P4] SchemaFinder.cj 残留注释块
- **文件**: `SchemaFinder.cj:21-38`
- **说明**: 三个被注释的字段定义块
- **待修复**: 清理

#### [P4] listTables 使用 PO 中 extra 字段
- **文件**: `MysqlSchema.cj:53-61`
- **说明**: 查询 `table_name` 映射到 `tableNameFromDb`，PO 类膨胀
- **待修复**: 可用轻量查询

#### [P4] MigroCommand struct 注册
- **文件**: `SubCommand.cj:21-23`
- **说明**: struct 在 static init 中注册自身，可能被值拷贝
- **待修复**: 考虑改为 class

### 已添加测试
- **文件**: `migro_test.cj` (12 测试用例)
- **覆盖**: MySQL/Postgres DDL 生成全部 4 个方法 (CREATE/DROP/ALTER/INDEX)

## 2026-05-05 | 二次审查 | 覆盖范围: f_orm/src/migro/*.cj (修复验证)

### 审查结论
所有 P0-P3 问题已修复。新增修复:

- **PostgresSchema.cj:182 guard/value 不匹配**: `c.default.isSome()` 守卫 + `column.default.getOrThrow()` 取值不一致。若旧列有默认值而新列无，SET DEFAULT 分支取 `None.getOrThrow()` → 抛异常。已修正守卫为 `column.default.isSome()`。

```
0 P0, 0 P1, 0 P2, 0 P3, 3 P4 (cosmetic)
```
