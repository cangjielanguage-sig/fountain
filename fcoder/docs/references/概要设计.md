
## 必要知识

概要设计（Preliminary Design），在软件工程中又称为总体设计，是软件生命周期中承上启下的关键阶段。它负责将需求分析阶段的“用户想要什么”转化为开发人员可以理解的“系统应该怎么做”的宏观蓝图12。

要胜任概要设计工作，需要构建一个跨越多领域的复合型知识体系。以下是核心的知识维度：

1. 需求分析与抽象思维能力
核心知识：深刻理解《软件需求规格说明书》（SRS）的内容，能够从复杂的业务场景中提炼出核心功能点和非功能性需求（如性能、安全、可扩展性）34。
关键技能：运用抽象与逐步求精的方法，将大问题分解为小问题，将用户需求转化为系统级的逻辑模型45。
2. 软件架构与设计原则
体系结构知识：掌握常见的架构风格，如分层架构、微服务架构、事件驱动架构等，并能根据项目需求选择最合适的顶层结构67。
设计原理：
模块化：将系统划分为独立命名和访问的模块45。
高内聚低耦合：确保模块内部功能高度相关，而模块之间依赖关系尽可能简单，这是评价设计好坏的核心标准78。
设计模式：了解常用的设计模式（如工厂模式、单例模式、观察者模式），以便设计出更灵活、可复用的模块结构。
3. 建模与可视化表达（UML）
统一建模语言（UML）：这是概要设计中最核心的“语言”。必须熟练掌握以下图表910：
结构图：类图（描述静态结构）、组件图（显示模块依赖）、部署图（描述物理部署）。
行为图：用例图（描述功能边界）、时序图（展示对象间交互顺序）。
工具应用：能够使用 StarUML、PlantUML 或 Enterprise Architect 等工具将设计思路可视化。
4. 数据设计与数据库知识
数据结构设计：定义全局性的数据结构，包括数据的特征、结构特性以及数据流。
数据库设计：具备数据库概念模型和逻辑模型的设计能力，能够将实体-关系图（E-R 图）转化为初步的数据库表结构6。
5. 接口设计与人机交互
外部接口：定义系统与外部系统或硬件的交互协议（如 API 接口、通信协议）。
内部接口：明确模块之间的调用关系、参数传递和数据格式6。
用户界面（UI）：虽然不涉及具体 UI 绘制，但需要给出人机交互的逻辑框架和界面流转关系7。
6. 质量保障与文档规范
非功能性设计：考虑系统的可靠性（出错处理、容灾）、可维护性（日志、监控）和性能（响应时间、吞吐量）设计。
文档编写：熟悉《概要设计说明书》的国家标准或企业规范，能够清晰、规范地编写设计文档，包括引言、总体设计、接口设计、数据结构设计等章节。
### 总结知识图谱
|知识领域|具体知识点|产出物示例|
|:-----:|:-------:|:-------:|
|需求理解|SRS 解读、业务抽象|功能列表、约束条件|
|架构设计|架构风格、模块化、设计模式|系统架构图、模块结构图|
|数据设计|数据结构、数据库逻辑模型|E-R 图、数据字典|
|接口设计|API 设计、接口协议|接口说明书、界面原型图|
|质量与规范|可靠性设计、文档标准|《概要设计说明书》|
通过掌握以上知识，设计者能够站在全局高度，为软件系统搭建一个稳定、可扩展且易于实现的逻辑骨架。
