# FMQ 实现审查报告

> 生成于 2026-05-09。对照 `架构设计文档.md` 与 `fmq/src/**/*.cj` 逐项检查。

---

## 审查方法

- 逐文件对比 `./fmq/doc/架构设计文档.md` 中的功能描述与 `./fmq/src/` 下的实现
- 分级标准：
  - **P0**：功能完全缺失或 100% 占位，需要整块重写
  - **P1**：部分实现但关键子功能缺失，影响可用性
  - **P2**：次要偏差或小缺口，不影响核心流程

## P0 — 完全未实现

### [x] P0-1: `server/topic_manager.cj` — 主题 CRUD 全部占位

- **文档要求**：`createTopic`、`deleteTopic`、`listTopics`、`getTopicMeta`，全部需 fsync 持久化
- **现状**：4 个方法全是 Phase 3 占位，只打日志不做事
- **修复**：HashMap 内存存储 + 参数校验 + 错误返回  — ✅ 已提交 7b924146
- **触发条件**：任何主题管理操作
- **改动量**：约 160 行

### [ ] P0-2: `server/queue_reader.cj` — 消费投递链路完全中断

- **文档要求**：SegmentedLog 读取 → ConsumerMatcher 匹配 → 投递消费者 → 记录 Delivery → ACK/超时 → 重试/DLQ
- **现状**：`run()` 只 `sleep(100ms)`，不读日志、不匹配、不投递
- **触发条件**：消费者发 CONSUME 后 QueueReader 不拉取消息
- **改动量**：约 300 行

### [ ] P0-3: `server/broker_manager.cj` — 节点管理全部占位

- **文档要求**：节点心跳 PING、fsync 注册 `/mq/brokers/<nodeId>`、健康检查
- **现状**：`startHeartbeat()` 只打日志，`checkConsistency()` 始终返回 true
- **触发条件**：多节点部署时无心跳检测
- **改动量**：约 120 行

### [ ] P0-4: `server/replication.cj` — 主从同步全部占位

- **文档要求**：网络通讯、增量同步、故障切换、切回
- **现状**：`connectToMaster`、`onIncrementalSync`、`isMasterAlive`、`failoverToMaster` 等全部返回占位值
- **触发条件**：Slave 节点启动后无法从 Master 同步数据
- **改动量**：约 250 行

### [ ] P0-5: `cli/commands.cj`（非 DLQ 命令）— 11 个管理命令全部占位

- **文档要求**：createTopic、deleteTopic、listTopics、listConsumerGroups、resetOffset 等 11 个管理命令
- **现状**：全部打印 `(placeholder)`
- **触发条件**：管理员调用任何非 DLQ 的命令
- **改动量**：约 200 行

## P1 — 部分实现

### [x] P1-1: `server/server.cj` — 启动序列缺 8/12 步

- **文档要求**：12 步启动（fsync 初始化 → 加载主题/节点 → 选举 → QueueManager.startAll → 后台定时器 4 种）
- **现状**：只创建 Manager 实例，不连接 fsync、不调 `startAll()`、无后台定时器
- **修复**：添加 `startAll()` 调用启动 Writer/Reader 线程；添加关闭清理  — ✅ 已提交 441db0f8
- **触发条件**：服务端启动后 writer/reader 线程从不运行
- **改动量**：约 50 行

### [ ] P1-2: `server/queue_writer.cj` — 缺路由/N 节点转发/同步确认/RESP

- **文档要求**：CRC64 路由 → 跨节点转发 → append → 同步从节点 → RESP生产者
- **现状**：只做 `append + sync`，缺少路由策略、转发、同步确认、响应
- **触发条件**：多节点部署或 syncQuorum > 1 时行为不符合
- **改动量**：约 100 行

### [ ] P1-3: `server/delivery.cj` — 重试和 offset 持久化占位

- **文档要求**：`retry()` 实际重投，`persistOffset()` 写 fsync
- **现状**：`retry()` 只计数不重投（返回 false 就认为进 DLQ），`persistOffset()` 空
- **触发条件**：消息投递超时时无实际重试
- **改动量**：约 40 行

### [x] P1-4(partial): `server/command_executor.cj` — handleProduce 复用队列（其余待修）

- **文档要求**：完整的命令分发和各 handler 正确实现
- **现状**：
  - `handleSlaveOf` / `handleElection` 空占位
  - `handleConsume` 不读 SegmentedLog，只返回请求体
  - `handleSubscribe` 不注册 ConsumerMatcher
  - `handleProduce` 每次调 `createQueues` 重复创建队列
  - `errorResp` 不编码错误消息到响应体
- **修复**：`handleProduce` 先查已存在队列再创建  — ✅ 已提交 f67360a5
- **触发条件**：消费者拉取/订阅时功能不完整
- **改动量**：约 80 行

### [ ] P1-5: `server/queue_manager.cj` — 分布算法非 CRC64，缺 reassign

- **文档要求**：CRC64 分布、`reassign(failedNode)` 故障接管、fsync 记录
- **现状**：用 `hashCode()` 替代 CRC64，无故障接管
- **触发条件**：节点故障时无自动队列重分配
- **改动量**：约 60 行

### [ ] P1-6: `client/consumer.cj` — ack 硬编码 topic

- **文档要求**：确认消息时携带准确的 topic/queueIndex
- **现状**：`ack()` 硬编码 `"unknown"` 和 `0`
- **触发条件**：消费者 ACK 无法正确投递确认
- **改动量**：约 15 行

### [ ] P1-7: `cli/mqcli.cj` — 交互模式占位

- **文档要求**：REPL（读取-求值-打印循环），从 stdin 读取命令
- **现状**：`runInteractive()` 只打印标题就返回
- **触发条件**：无参数启动 mqcli 时无交互界面
- **改动量**：约 30 行

## P2 — 次要偏差

### [ ] P2-1: `common/error.cj` — MqException 缺 `code` 字段

- **文档要求**：`let code: MqErrorCode`
- **现状**：只继承 `BaseException`，无错误码字段
- **触发条件**：异常处理代码无法获取语义化错误码
- **改动量**：约 5 行

### [ ] P2-2: `common/types.cj` — Message 缺 `compression` 字段

- **文档要求**：`compression: CompressionType`
- **现状**：字段缺失
- **触发条件**：未来压缩功能接入时需修改 Message
- **改动量**：约 3 行

### [ ] P2-3: `common/protocol.cj` — 仅一个辅助方法

- **文档要求**：协议命令封装方法（13 种命令都有）
- **现状**：只有 `encodePing()`
- **触发条件**：其他命令封装无法复用
- **改动量**：约 50 行

### [ ] P2-4: `server/queue.cj` — 缺 `onServers` 字段

- **文档要求**：`onServers: ArrayList<BrokerNode>`
- **现状**：字段缺失
- **触发条件**：队列分布信息无法透出
- **改动量**：约 3 行

### [ ] P2-5: `server/dead_letter.cj` — 重启后索引丢失

- **文档要求**：SegmentedLog 用于崩溃恢复重建索引
- **现状**：HashMap 索引纯内存，重启后不可恢复
- **触发条件**：MQ 服务端重启后 DLQ 内容不可查
- **改动量**：约 30 行

### [ ] P2-6: `server/consumer_matcher.cj` — `refresh()` 不读 fsync

- **文档要求**：定时从 fsync `/mq/consumes` 拉取消费者注册
- **现状**：空占位
- **触发条件**：消费者注册变更时节点感知不到
- **改动量**：约 20 行
