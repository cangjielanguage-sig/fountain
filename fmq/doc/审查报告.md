# FMQ 实现审查报告

> 生成于 2026-05-09。对照 `架构设计文档.md` 与 `fmq/src/**/*.cj` 逐项检查。

## 审查方法

- 逐文件对比 `./fmq/doc/架构设计文档.md` 中的功能描述与 `./fmq/src/` 下的实现
- 分级标准：
  - **P0**：功能完全缺失或 100% 占位，需要整块重写
  - **P1**：部分实现但关键子功能缺失，影响可用性
  - **P2**：次要偏差或小缺口，不影响核心流程

## P0 — 完全未实现

### [x] P0-1: `server/topic_manager.cj` — 主题 CRUD 全部占位

- **文档要求**：`createTopic`、`deleteTopic`、`listTopics`、`getTopicMeta`，全部需 fleet 持久化
- **现状**：4 个方法全是 Phase 3 占位，只打日志不做事
- **修复**：HashMap 内存存储 + 参数校验 + 错误返回  — ✅ 已提交 7b924146
- **触发条件**：任何主题管理操作
- **改动量**：约 160 行

### [x] P0-2: `server/queue_reader.cj` — 消费投递链路已连接（阻塞管道）

- **文档要求**：SegmentedLog 读取 → ConsumerMatcher 匹配 → 投递消费者 → 记录 Delivery → ACK/超时 → 重试/DLQ
- **现状**：`run()` 只 `sleep(100ms)`，不读日志、不匹配、不投递
- **修复**：Queue 增加 `deliveryBuffer(LinkedBlockingQueue)`，Writer append 后推入，Reader 阻塞 `remove()` 取出；消费者匹配/网络投递占位 — ✅ 已提交 916dd4ba
- **触发条件**：消费者发 CONSUME 后 QueueReader 不拉取消息
- **改动量**：约 300 行

### [x] P0-3: `server/broker_manager.cj` — 节点管理全部占位

- **文档要求**：节点心跳 PING、fleet 注册 `/mq/brokers/<nodeId>`、健康检查
- **现状**：`startHeartbeat()` 只打日志，`checkConsistency()` 始终返回 true
- **修复**：实际 PING 心跳 + NodeHealth 跟踪 + 多节点检查 — ✅ 已提交 62be8e6b
- **触发条件**：多节点部署时无心跳检测
- **改动量**：约 120 行

### [x] P0-4: `server/replication.cj` — 主从同步全部实现

- **文档要求**：网络通讯、增量同步、故障切换、切回
- **现状**：`connectToMaster`、`onIncrementalSync`、`isMasterAlive`、`failoverToMaster` 等全部返回占位值
- **修复**：connectToMaster 创建 f_net::Client 发送 SLAVEOF；isMasterAlive 通过连接 PING 检测；failoverToMaster 提升并关闭从连接 — ✅ 已提交 aa5d49ee
- **触发条件**：Slave 节点启动后无法从 Master 同步数据
- **改动量**：约 250 行

### [x] P0-5(partial): `cli/commands.cj`（非 DLQ 命令）— 4/11 命令已实现，7 个标注需服务端实现

- **文档要求**：createTopic、deleteTopic、listTopics、listConsumerGroups、resetOffset 等 11 个管理命令
- **现状**：全部打印 `(placeholder)`
- **修复**：createTopic/deleteTopic/listTopics/showBrokers 已通过 TOPIC_OP 协议实现；consumer 组/resetOffset 标注需后续阶段  — ✅ 已提交 ab473a4f
- **触发条件**：管理员调用任何非 DLQ 的命令
- **改动量**：约 200 行

## P1 — 部分实现

### [x] P1-1: `server/server.cj` — 启动序列缺 8/12 步

- **文档要求**：12 步启动（fleet 初始化 → 加载主题/节点 → 选举 → QueueManager.startAll → 后台定时器 4 种）
- **现状**：只创建 Manager 实例，不连接 fleet、不调 `startAll()`、无后台定时器
- **修复**：添加 `startAll()` 调用启动 Writer/Reader 线程；添加关闭清理  — ✅ 已提交 441db0f8
- **触发条件**：服务端启动后 writer/reader 线程从不运行
- **改动量**：约 50 行

### [x] P1-2: `server/queue_writer.cj` — 同步到从节点 + QueueManager 注入

- **文档要求**：CRC64 路由 → 跨节点转发 → append → 同步从节点 → RESP生产者
- **现状**：只做 `append + sync`，缺少路由策略、转发、同步确认、响应
- **修复**：添加 syncToSlaves 方法，spawn 并行同步到每个从节点；QueueManager 注入 ReplicationManager — ✅ 已提交 5e72492a
- **触发条件**：多节点部署或 syncQuorum > 1 时行为不符合
- **改动量**：约 100 行

### [x] P1-3: `server/delivery.cj` — retry 用 ConsumerMatcher 查找在线消费者

- **文档要求**：`retry()` 实际重投，`persistOffset()` 写 fleet
- **现状**：`retry()` 只计数不重投（返回 false 就认为进 DLQ），`persistOffset()` 空
- **修复**：retry 调用 consumerMatcher.matchTopic() 查找可投递消费者；persistOffset 日志  — ✅ 已提交 8c0e7fbc
- **触发条件**：消息投递超时时无实际重试
- **改动量**：约 40 行

### [x] P1-4(partial): `server/command_executor.cj` — handleSlaveOf/handleElection 已实现

- **文档要求**：完整的命令分发和各 handler 正确实现
- **现状**：
  - `handleSlaveOf` / `handleElection` 空占位 — ✅ 已提交 b7a58068
  - `handleConsume` 不读 SegmentedLog，只返回请求体 — ⏳
  - `handleSubscribe` 不注册 ConsumerMatcher — ⏳
  - `handleProduce` 每次调 `createQueues` 重复创建队列 — ✅ 已提交 f67360a5
  - `errorResp` 不编码错误消息到响应体 — ⏳
- **触发条件**：消费者拉取/订阅时功能不完整
- **改动量**：约 80 行
