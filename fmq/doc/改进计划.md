# FMQ 改进计划

> 基于当前实现（31 测试通过，全部 9 阶段完成）的下阶段改进方向。不包含 ACL/权限控制和 HTTP 网关。

---

## 1. fleet 元数据集成

**优先级**：P0 — 最高

**状态**：✅ TopicManager / DeliveryManager 已完成。ConsumerMatcher / BrokerManager 待实现。

### 完成情况

| 管理器 | 状态 | fleet 路径 | 提交 |
|--------|------|-----------|------|
| `TopicManager` | ✅ | `/mq/topics/<name>` | 89245700 |
| `DeliveryManager` | ✅ | `/mq/offset/<key>` | 89245700 |
| `ConsumerMatcher` | ⏳ | `/mq/consumes` | |
| `BrokerManager` | ⏳ | `/mq/brokers/<nodeId>` | |

### 实现说明

`TopicManager.restore()` — 启动时通过 `fleet.prefix("/mq/topics/")` 遍历所有主题 key，`decode<TopicMeta>` 重建 HashMap。
`DeliveryManager.restoreOffsets()` — 启动时通过 `fleet.prefix("/mq/offset/")` 遍历所有 offset key，`decode<Int64>` 重建 ConcurrentHashMap。

无 fleet 时静默降级：`tryCreateSyncClient()` 在 `SyncClient.getInstance()` 失败时返回 `None`，各方法中 `if (let Some(fleet) <- syncClient)` 跳过持久化。

```cj
// 每个 Manager 注入 SyncClient
// TopicManager.createTopic:
let meta = TopicMeta(queueCount, ...)
DefaultCodec().encode(meta).finish().copy(to: buf)
syncClient.add("/mq/topics/" + name, buf.toArray())

// TopicManager.getTopicMeta:
if (let Some(bytes) <- syncClient.getBytes("/mq/topics/" + name)) {
    DefaultCodec().decode<TopicMeta>(ByteBuffer(bytes))
}

// 启动时重建索引:
for topic in syncClient.prefix("/mq/topics/") {
    topicManager.topics[topic] = decode(topic)
}
```

**改动量**：每个 Manager 约 30 行 × 4 = ~120 行。

**依赖**：`fountain::fleet.client.SyncClient`（已在 fmq 的 `dependencies` 中）。

### 1.3 注意事项

- fleet 是运行时依赖，服务端启动时先连接 fleet，连接失败应重试（指数退避）
- `/mq/topics/` 下的数据一旦写入，TopicMeta 就全局可见
- `ConsumerRegistration` 在 fleet 中以 `consumerId` 为 key，方便跨节点共享

## 2. 批量协议优化

**优先级**：P1 — 高（吞吐提升 3-5x）

**现状**：`produceBatch` / `ackBatch` 是逐条串行循环，每次循环都有一次 f_net 往返。

### 2.1 当前瓶颈

```
for each message → PUBLISH → wait RESP → PUBLISH → wait RESP
                                                     ↑ N 次网络往返
```

### 2.2 优化方案

在 f_protocol 新增命令：

| 命令 | Code | 说明 |
|------|------|------|
| `BATCH_PUBLISH` | 0x40（slot 4，复用原 RESERVED） | 一次请求编码 N 条消息 |
| `BATCH_ACK` | 0x50（slot 5） | 一次确认 N 个 messageId |

#### 编码格式

```cj
// BATCH_PUBLISH body:
let enc = DefaultCodec()
    .encode(count)           // Int64: 消息数
for each message:
    .encode(topic)
    .encode(labelsCount)
    for each label: .encode(label)
    .encode(payload)

// 响应:
// RESP(SUCCESS) 表示全部成功
// RESP(PARTIAL) + failedIndexes: Array<Int64> 表示部分失败
```

### 2.3 服务端处理

```cj
// command_executor.cj 新增:
private func handleBatchPublish(request: ProtocolMessage): ProtocolMessage {
    let dec = DefaultCodec()
    let count = dec.decode<Int64>(input)
    var results = ArrayList<LogPosition>()
    for (i in 0..count) {
        let (topic, labels, payload) = decodeProduce(dec)
        results.add(queueManager.getQueue(topic).append(payload))
    }
    ProtocolMessage(Command.RESP(0), request.id, MqBody("ok", encodeResults(results)).toData())
}
```

**改动量**：~200 行（f_protocol 50 + command_executor 80 + client 50 + test 20）。

## 3. 消息过期清理后台线程

**优先级**：P1 — 高（防止磁盘打满）

**现状**：SegmentedLog 文件只增不删，磁盘无限增长。

### 3.1 实现

新文件 `fmq/src/server/queue_cleaner.cj`：

```cj
public class QueueCleaner {
    private let config: MqConfig
    private let queueManager: QueueManager
    private var closed: Bool = false

    public func run(): Unit {
        while (!closed) {
            sleep(Duration.minute * 5)  // 每 5 分钟扫描一次
            cleanup()
        }
    }

    private func cleanup(): Unit {
        let cutoff = DateTime.now() - Duration.hour * config.retentionHours
        for each queue in queueManager.queues {
            for oldFile in queue.log.takeOldFiles() {
                let mtime = getFileModTime(oldFile)
                if (mtime < cutoff) {
                    File.delete(oldFile)
                }
            }
        }
    }
}
```

**改动量**：~100 行。

### 3.2 集成

在 `MqCommand.exec()` 启动时：

```cj
let cleaner = QueueCleaner(config, queueManager)
spawn { cleaner.run() }
```

### 3.3 保留策略

- 默认保留 72 小时（`mq_retention_hours`）
- 每个队列至少保留最后 1 个文件（即使已过期）
- 清理仅针对已轮转的旧文件（`takeOldFiles()`），当前活跃文件不删

**现状**：除日志外无监控指标，无法观察系统运行状态。

### 4.1 最小实现：日志输出

```cj
// delivery.cj 增加定期 Lag 报告
private let lagTimer = Timer.repeat(Duration.minute, Duration.minute, {
    => reportLag()
})

private func reportLag(): Unit {
    for each (topic, queues) in queueManager.queues {
        for each queue in queues {
            let size = queue.deliveryBuffer.size
            log.info{"lag: ${topic}[${queue.index}] buffer=${size}"}
        }
    }
}
```

**改动量**：~50 行。

## 5. ConsumerGroupManager 独立模块

**优先级**：P1 — 中（代码整洁性）

**现状**：消费者组管理逻辑散布在 TopicManager / ConsumerMatcher / DeliveryManager 中。

### 5.1 当前分散点

| 功能 | 当前所在 |
|------|---------|
| 创建消费者组 | `TopicManager.addConsumerGroup()` |
| 列出消费者组 | `TopicManager.getConsumerGroups()` |
| 消费者匹配 | `ConsumerMatcher.matchTopic()` |
| Offset 读写 | `DeliveryManager.getOffset()` / `setOffset()` |

### 5.2 统一管理

新文件 `fmq/src/server/consumer_group_manager.cj`：

```cj
public class ConsumerGroupManager {
    private let topicManager: TopicManager
    private let consumerMatcher: ConsumerMatcher
    private let deliveryManager: DeliveryManager

    public func createGroup(topic: String, groupId: String, matchMode: MatchMode): MqErrorCode {
        // 1. 写入 TopicMeta.consumerGroups
        topicManager.addConsumerGroup(topic, groupId)
        // 2. 注册消费者
        let reg = ConsumerRegistration(consumerId: groupId, groupId: groupId, ...)
        consumerMatcher.register(reg)
        // 3. 初始化 offset = 0
        deliveryManager.setOffset(topic, 0, groupId, 0)
        MqErrorCode.SUCCESS
    }

    public func deleteGroup(topic: String, groupId: String): MqErrorCode {
        topicManager.removeConsumerGroup(topic, groupId)
        // 清理 offset
        deliveryManager.setOffset(topic, 0, groupId, 0)
        MqErrorCode.SUCCESS
    }

    public func getGroups(topic: String): ArrayList<String> {
        topicManager.getConsumerGroups(topic)
    }

    public func getOffset(topic: String, queueIndex: Int64, groupId: String): Int64 {
        deliveryManager.getOffset(topic, queueIndex, groupId)
    }

    public func setOffset(topic: String, queueIndex: Int64, groupId: String, offset: Int64): Unit {
        deliveryManager.setOffset(topic, queueIndex, groupId, offset)
    }
}
```

**改动量**：新文件 ~120 行。`MqCommand.exec()` 中创建 `ConsumerGroupManager` 注入 `CommandExecutor`。

### 5.3 收益

- 单一职责：`TopicManager` 不再关心消费者组细节
- CLI 命令 `createConsumerGroup` / `deleteConsumerGroup` 可调用此模块
- 为后续消费者组级别的 pause/resume 预留扩展点
