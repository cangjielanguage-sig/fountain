## 2. 核心数据模型

### 2.1 消息（Message）

```cangjie
public struct Message {
    id: MessageID          // >=16 byte 唯一标识
    topic: String
    labels: ArrayList<String>
    payload: Array<Byte>   // 业务负载
    producerId: String
    timestamp: DateTime
    expireAt: ?DateTime    // None 永不过期
    qos: QoS               // AtMostOnce / AtLeastOnce / ExactlyOnce
    compression: CompressionType  // None / Zstd（暂保留，v1 恒为 None）
}
```

### 2.2 消息 ID

复用 `fountain::f_protocol.MessageID`：

```cangjie
public struct MessageID <: DataFields<MessageID> {
    pid: Int64        // 生产者进程 ID
    tid: Int64        // 线程内递增序号（单调递增）
    time: DateTime    // 生产时间
}
```

消息 ID 保证全局唯一：不同进程 pid 不同，同进程内 `(pid, tid)` 唯一。

## 3. 网络协议设计

### 3.1 协议封装

基于 `fountain::f_protocol.Message` 扩展，各端共用 `common/protocol.cj` 定义的封装方法。

**请求/响应结构：**

```
┌─────────┬──────────┬──────────────┬──────────┐
│ Command │ Flags    │  MessageID   │ Body     │
│  1 byte │  1 byte  │  ~20 bytes   │ 可变长度  │
└─────────┴──────────┴──────────────┴──────────┘
```

- **Command**：指令类型（PUBLISH / RESP / ACK ... 共 13 种）
- **Flags**：QoS（2bit）、DUP（1bit）、RETAIN（1bit）、ACK（1bit），其余保留
- **MessageID**：请求/响应关联标识
- **Body**：DefaultCodec 编码的消息体或结果数据

### 3.2 命令定义

| 命令 | Code | 方向 | body 内容 |
|------|------|------|----------|
| `PUBLISH` | 0x30 | C→S | `Message`（不含 id） |
| `RESP` | 0xB0 | S→C | `ErrorCode` + `MessageID`（生产/ACK 结果） |
| `SUBSCRIBE` | 0x80 | C→S | `ConsumerRegistration` |
| `UNSUBSCRIBE` | 0x90 | C→S | `ConsumerId` + `Topic` |
| `CONSUME` | 0xA0 | C→S | `ConsumerId` + `BatchSize` |
| `ACK` | 0xE0 | C→S | `MessageID` |
| `PING` | 0xC0 | C→S | 空（心跳） |
| `REGISTER` | 0x20 | C→S | `ProducerId` |
| `DEREGISTER` | 0xF0 | C→S | `ProducerId` |
| `SLAVEOF` | 0x10 | S→S | `NodeId` |
| `ELECT` | 0xD0 | S↔S | `NodeId` + `Term` |

### 3.3 CLI 协议

管理端不直接调用 f_net 消息，而是**通过 mq 服务端的 f_net Server 转发管理命令**：

```
mqcli → f_net::Client → 任意 MQ 节点 → 执行管理操作 → 操作 fsync → 返回结果
```

所有管理操作最终转变为对 fsync key 的读写。

## 4. 队列管理（QueueManager）

### 4.1 队列声明周期

```
Topic 创建 → QueueManager.distribute()
  → 按 CRC64 计算每个队列归属的节点
  → 在本节点创建 Queue 实例
  → Queue.init() → 打开/创建 SegmentedLog
  → 启动 QueueWriter 写线程
  → 启动 QueueReader 读线程
  → 记录 /mq/brokers/<nodeId> 到 fsync

节点故障 → 其他节点接管失效队列
  → QueueManager.reassign(failedNode)
  → 在健康节点重建 Queue 实例

Topic 删除 → QueueManager.destroy(topic)
  → 停止所有队列的 Reader/Writer 线程
  → 关闭 SegmentedLog
  → 删除 SegmentedLog 文件和数据目录
  → 清理 fsync 元数据
```

### 4.2 队列分布算法

```
// 输入：主题名 topic，队列总数 queueCount，节点列表 nodes（有序，按 mq_hosts 顺序）
func distribute(topic: String, queueCount: Int64, nodes: ArrayList<BrokerNode>): Int64 {
    // 0 号队列：CRC64 取模确定起始节点
    let startIndex = CRC64(topic + ":0") % nodes.size
    // 后续队列依次向后排列，超出节点数则环绕
    for (i in 0..queueCount) {
        let nodeIndex = (startIndex + i) % nodes.size
        assignQueueToNode(topic, i, nodes[nodeIndex])
    }
}
```

### 4.3 队列文件存储

```
<data_dir>/
  <topic_encoded>/                # topic 路径编码（/ → _）
    <queueIndex>/
      <filePrefix>_<startSeq>.log  # SegmentedLog segment 文件
      dlq/                         # 死信队列
        dlq_<startSeq>.log
```

- `mq_data_dir`：默认 `/var/fmq/data/`
- 每个队列的 SegmentedLog 配置：`LogConfig { dir, filePrefix, maxFileSize, syncInterval, startSeq, fileExt }`

## 5. 写线程（QueueWriter）

### 5.1 写流程

```
生产者 PUBLISH 到达
  ↓
QueueWriter.receive(message)
  ↓
1. CRC64(message.topic + ":" + producerId) % queueCount → 目标队列索引
2. 目标队列在本节点？ → 是：继续；否：转发到目标节点
3. SegmentedLog.append(encode(message))
4. QoS == AtLeastOnce / ExactlyOnce → 记录 DeliveryRecord
5. 向生产者返回 RESP(MessageID, SUCCESS)
```

### 5.2 线程模型

```cangjie
// QueueWriter 是 Queue 的内嵌线程
public class QueueWriter {
    let queue: Queue
    var closed: Bool = false

    public func run(): Unit {
        while (!closed) {
            // 通过 f_net 消息通道接收消息
            let msg = incomingMessages.take()
            processMessage(msg)
        }
    }

    private func processMessage(msg: ProduceRequest): Unit {
        // 1. 写入 SegmentedLog（阻塞式 append）
        let position = queue.log.append(encode(msg.message))
        // 2. 同步到从节点（mq_sync_quorum > 1 时等待）
        syncToSlaves(position)
        // 3. 响应生产者
        sendResp(msg.producerConn, msg.message.id, ErrorCode.SUCCESS)
    }
}
```

### 5.3 同步到从节点

```cangjie
private func syncToSlaves(position: LogPosition): Unit {
    if (mq_sync_quorum == 1) { return }  // 仅主确认，无需等待

    let slaves = getOnlineSlaves()
    if (slaves.size == 0) { return }

    // 并行向所有从节点发送待同步数据
    let futures = ArrayList<Future<Bool>>()
    for (slave in slaves) {
        futures.append(spawn { sendToSlave(slave, position) })
    }

    // 等待至少 quorum - 1 个从节点确认
    var confirmed = 0
    for (f in futures) {
        if (f.get()) { confirmed += 1 }
        if (confirmed >= mq_sync_quorum - 1) { break }
    }
}
```

## 6. 读线程（QueueReader）

### 6.1 读流程

```
队列文件有数据？
  ↓
QueueReader.readNext()
  ↓
1. 从 SegmentedLog 读取下一条未投递消息（记录当前 seq）
2. ConsumerMatcher.match(message) → 获取匹配的消费者（按组分组）
3. 向每组选中的消费者发送消息
4. 记录 DeliveryRecord（messageId, consumerId, groupId, time）
5. 启动 ACK 计时器
6. 等待 ACK 或超时
```

### 6.2 消费者匹配算法

```cangjie
public class ConsumerMatcher {
    // 输入：消息的 topic
    // 输出：map[groupId → consumerId]
    public func match(message: Message): HashMap<String, String> {
        let result = HashMap<String, String>()
        let registrations = getRegistrations()  // 从本地缓存获取

        // 按消费者组分 group
        let groups = HashMap<String, ArrayList<ConsumerRegistration>>()
        for (reg in registrations) {
            if (matchesTopic(reg, message.topic)) {
                groups.getOrPut(reg.groupId) { ArrayList() }.add(reg)
            }
        }

        // 每组的消费者间做 Round-Robin
        for ((groupId, consumers) in groups) {
            let selected = roundRobinSelect(consumers, message)
            result[groupId] = selected.consumerId
        }
        return result
    }

    private func matchesTopic(reg: ConsumerRegistration, topic: String): Bool {
        return match (reg.matchMode) {
            case EXACT =>  reg.topics.contains(topic)
            case GLOB =>   reg.topics.any { globMatch(it, topic) }
            case PREFIX => reg.topics.any { topic.startsWith(it) }
        }
    }
}
```

### 6.3 投递与重试

```
投递消息 → 记录 DeliveryRecord → 等待 ACK
  │
  ├── ✓ 收到 ACK → 推进 offset → 从 DeliveryRecord 中移除 → 读取下一条
  │
  └── ✗ ACK 超时（mq_ack_timeout_ms）
        └── retryCount < mq_max_retry_count
              ├── 原消费者在线 → 重投原消费者
              ├── 原消费者离线 & 组内有其他消费者 → 重投其他消费者
              └── 组内无消费者 → 暂停重试（等消费者上线）
              → retryCount++ → schedule 到 retryBuffer
        └── retryCount ≥ mq_max_retry_count → 死信队列
```

### 6.4 offset 管理

```cangjie
// 读线程内部维护：
var readerOffset: Int64 = loadOffsetFromFsync()
// 每次 ACK 确认后推进 offset
func onAck(messageId: MessageID): Unit {
    let record = deliveryRecords.remove(messageId)
    if (record != None) {
        let Seq = extractSeqFromMessageId(messageId)
        if (Seq > readerOffset) {
            readerOffset = Seq
            persistOffsetToFsync(topic, queueIndex, groupId, readerOffset)
        }
    }
}
```

**关键设计**：offset 按消费者组独立管理。同一队列 N 个消费者组有 N 个独立的 offset 值，互不干扰。

## 7. 主从复制

### 7.1 角色定义

| 角色 | 职责 |
|------|------|
| **Master** | 接收生产/消费请求，管理 SegmentedLog，同步到 Slave |
| **Slave** | 从 Master 同步数据，不对外服务，准备接管 |

### 7.2 数据同步协议

```
Slave → Master: SLAVEOF(SlaveNodeId)
Master → Slave: 全量同步（SegmentedLog 当前文件列表）
                ↓
                增量同步（每次 append 后发送增量数据）
                ↓
Slave 确认已同步的 seq → Master 记录 Slave 同步进度
```

### 7.3 故障切换

```
客户端检测到 Master 心跳超时
  ↓
1. 客户端从 BrokerManager 获取该 Master 对应的 Slave 列表
2. 尝试连接 Slave，发送 NEW_MASTER 候选请求
3. Slave 收到多数派节点的确认后提升为 Master
4. 提升后的 Master 更新 /mq/brokers/<nodeId> 的 isMaster=true
5. 客户端切换到新 Master
6. 旧 Master 恢复后自动降级为 Slave
```

### 7.4 切回

```
旧 Master 恢复 → 作为 Slave 连新 Master → 同步缺失数据
  ↓
新 Master 确认数据一致 → 主动发起切回
  ↓
新 Master → 旧 Master: 通知准备接管
旧 Master 提升为 Master → 更新 fsync
旧 Master → 客户端: Master 已恢复，请切换
客户端 → 旧 Master: 验证连通性
客户端切换回原始 Master
```

## 8. 客户端（MqClient）设计

### 8.1 架构

```cangjie
public class MqClient <: Resource {
    // 单例
    static var instance: ?MqClient = None

    let mqConn: Client<Message, EncodedMessage, Message, ...>  // 连接 MQ 集群
    let syncConn: Client<...>                                   // 连接 fsync 集群
    let sender: Sender
    var subscribers: ConcurrentHashMap<String, Subscription>    // topic → 订阅信息
    var consumers: ConcurrentHashMap<String, ConsumerLoop>     // groupId → 消费循环
    var closed: Bool = false
}
```

### 8.2 连接管理

- **单进程、单实例**：一个进程内只有一个 `MqClient` 实例
- **一个 TCP 连接**：`mqConn` 连接所有 MQ 节点（多路复用，MessageID 分发）
- **一个 fsync 连接**：`syncConn` 连接 fsync 节点

```cangjie
// Sender 封装：生产消息
public class Sender {
    private let client: Client

    public func produce(topic: String, labels: ArrayList<String>,
                        data: Array<Byte>): ProduceResult {
        // 1. 根据 topic 的队列分布，计算目标节点
        let targetNode = routeToNode(topic)
        // 2. 构造 PUBLISH 消息，发送到目标节点
        let messageId = client.send(PUBLISH(topic, labels, data))
        // 3. 等待 RESP
        return waitForResp(messageId)
    }
}
```

### 8.3 消费者订阅

```cangjie
// 订阅 → 注册到 fsync
public func subscribe(groupId: String, topic: String,
                      matchMode: MatchMode,
                      labels: ?ArrayList<String> = None,
                      pathFilter: ?String = None): Bool {
    // 1. 构造 ConsumerRegistration
    // 2. 写入 fsync: /mq/consumes
    // 3. 开始消费循环
    startConsumeLoop(groupId, topic)
}
```

### 8.4 消费循环

```cangjie
// 后台线程：Pull 模式
private func startConsumeLoop(groupId: String, topic: String): Unit {
    spawn {
        while (!closed) {
            // 从服务端拉取消息
            let result = client.send(CONSUME(consumerId, batchSize=1))
            match (result) {
                case Some(msg) =>
                    if (labelsFilter(msg) && pathFilter(msg)) {
                        onMessage(groupId, msg)     // 回调业务层
                        client.send(ACK(msg.id))    // 手动 ACK
                    } else {
                        client.send(ACK(msg.id))    // 不匹配也 ACK
                    }
                case None => sleep(Duration.millisecond(100))  // 无消息时短暂等待
            }
        }
    }
}
```

## 10. 并发模型

### 10.1 线程架构

```
MQ Server 进程
├── f_net::Server acceptor 线程（接收 TCP 连接）
├── f_net::Server 各连接 reader/writer 线程
├── QueueManager 管理线程
├── 每个 Queue
│    ├── QueueWriter 线程（1 个）
│    └── QueueReader 线程（1 个）
├── ConsumerMatcher 定时刷新线程（watch fsync /mq/consumes）
├── DeadLetter 清理线程（1 个，定时扫描过期死信）
├── BrokerManager 心跳线程（1 个）
└── ReplicationManager 同步线程（1 个）

MQ Client 进程
├── f_net::Client reader 线程（1 个，接收所有响应）
├── 每个消费组一个 poll 线程
├── 生产者调用线程（外部线程调用 produce）
└── fsync 注册线程（定期心跳更新注册信息）
```

### 10.2 线程安全设计

| 共享资源 | 保护策略 | 说明 |
|---------|----------|------|
| `Queue.log` (SegmentedLog) | Mutex | append 线程安全，reader 只读 |
| `DeliveryRecord` 表 | ConcurrentHashMap | messageId → record 映射 |
| 消费者注册缓存 | Mutex + 定时刷新 | 读线程只读缓存，Matcher 线程更新 |
| `offset` 持久化 | AtomicInt64 | 每 ConsumerGroup 一个 offset |
| SegmentedLog 文件 | SegmentedLog 内部 Mutex | append 与 rotate 互斥 |

### 10.3 线程协作（Producer-Consumer 模式）

```
Producer 线程                          QueueWriter 线程
┌─────────────────────┐             ┌──────────────────────┐
│ produce()           │  LinkedBlockingQueue  │ run()               │
│ queue.put(msg) ──────────→    │ msg = queue.take()  │
│ wait for RESP(future) │             │ log.append()         │
│                     │             │ future.set(result)   │
└─────────────────────┘             └──────────────────────┘
```

**Reader 与 Writer 之间没有直接的数据通道**。Writer 只写文件，Reader 直接从 SegmentedLog 读取。

## 11. 启动流程

### 11.1 MQ 服务端启动

```
1. loadConfig() → 解析环境变量
2. 初始化 fsync::Client（连接 sync_hosts）
3. 读取 /mq/topics → 获取所有主题列表
4. 读取 /mq/brokers → 获取所有节点信息
5. 检测 mq_hosts 一致性（各节点配置对比）
6. 确定自身角色（根据 mq_hosts 顺序 + ELECTION 结果）
7. QueueManager.init() → 为分配到本节点的队列创建 Queue 实例
8. 启动 QueueWriter 和 QueueReader 线程
9. 启动 f_net::Server（监听 mq_hosts 中本节点的端口）
10. 启动 ConsumerMatcher 刷新线程（watch fsync /mq/consumes）
11. 启动 DeadLetter 清理线程
12. 注册 BrokerMeta 到 fsync: /mq/brokers/<nodeId>
```

### 11.2 MQ 客户端启动

```
1. loadConfig() → 解析环境变量
2. 初始化 f_net::Client，连接 mq_hosts 所有节点
3. 初始化 fsync::Client，连接 sync_hosts
4. MqClient 注册到各 MQ 节点（REGISTER）
5. 等待用户调用 subscribe / produce
```

### 11.3 MQ CLI 启动

```
1. loadConfig() → 解析环境变量
2. 解析命令行参数
3. 创建临时 f_net::Client 连接任意 MQ 节点
4. 发送管理命令
5. 打印结果，退出
```
