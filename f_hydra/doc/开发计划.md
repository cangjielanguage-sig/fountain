## 2. 关键路径与并行策略

### 关键路径 (P0 → P4 → P8 → P9 → P10，共 6 个阶段)

```
P0: T1(系统依赖) → T2(下载模型) → T3(ONNX转换) → T6(Faiss编译)
    ∥ T5(ONNX Runtime) ∥ T7(Tokenizers) → T8(运行环境) → T9(项目骨架)
    → P1 → P2 → P3 → P4 → P8 → P9 → P10
```

**关键路径瓶颈**：T6（Faiss C 库编译）是全量 C++ 编译，预计 5-10 分钟，是 P0 中最耗时的任务。

关键路径上的各阶段必须严格顺序执行，不可跳过。

### 并行策略

Phase 4 (Dense)、Phase 5 (Sparse)、Phase 6 (ColBERT)、Phase 7 (Fusion) 在 Phase 3 完成后可并行开发。如果团队有 3 名开发者，可一人负责一路索引，显著缩短工期。

### 质量门禁机制

每个阶段完成后必须通过质量门禁（测试全部通过）才能进入下一阶段。**不可跳过**，不可"批量实现后批量测试"——错误的 tokenizer 在 Phase 2 修复的代价远小于 Phase 8 才发现。

## 3. Phase 0: BGE-M3 部署 + Faiss 编译 + 环境搭建

**目标**: 部署 BGE-M3 模型（下载→ONNX 转换→验证）、编译安装 Faiss/ONNX Runtime/Tokenizers 三大 C 库、建立项目骨架、生成测试 Golden 文件。

**注意**：BGE-M3 部署和 Faiss 编译是本阶段的**首要任务**，必须在编写任何仓颉代码之前完成。没有正确的模型和运行时可用的 C 库，后续所有 Phase 的测试都无法通过。

### 任务清单

| ID | 任务 | 描述 | 工作量 |
|----|------|------|--------|
| **T1** | **安装系统依赖** | Ubuntu: `build-essential cmake git git-lfs python3 python3-pip libopenblas-dev liblapack-dev wget curl pkg-config`。CentOS: `yum groupinstall "Development Tools"` + cmake/git/python3/openblas-devel。pip 安装 `optimum[exporters] onnx onnxruntime transformers`（模型下载和 ONNX 转换必需）。 | S |
| **T2** | **下载 BGE-M3 模型** | ModelScope 优先（国内 CDN 加速）：`pip install modelscope` → `snapshot_download('BAAI/bge-m3')`。失败时回退 HuggingFace：`git lfs install && git clone https://huggingface.co/BAAI/bge-m3`。产物：`model.safetensors` (~2.2GB)、`tokenizer.json` (~9MB)、`tokenizer_config.json`、`sentencepiece.bpe.model`、`config.json`。 | M |

| **T8** | **配置运行时环境** | 设置 `LD_LIBRARY_PATH=/usr/local/lib`。创建 `.env.example` 文件含所有 `fountain_hydra_*` 环境变量及其默认值。验证：`NativeLibrary.load("onnxruntime")/.load("faiss_c")/.load("tokenizers")` 全部返回 Some。 | XS |

| **T10** | **创建部署脚本** | 将 T1-T8 的步骤固化为可重复执行脚本：`scripts/install_deps.sh`、`scripts/download_model.sh`（含 ModelScope 回退）、`scripts/convert_onnx.sh`、`scripts/verify_model.sh`（SHA256 + L2 norm）。创建 `Dockerfile`（ubuntu:22.04 多阶段构建含所有依赖）和 `docker-compose.yml`。 | S |
| **T11** | **生成 Golden 文件 + 测试目录** | 编写 `scripts/gen_tokenizer_golden.py`（100 条文本：英文/中文/emoji/长文本/空字符串，与 Python `AutoTokenizer("BAAI/bge-m3")` 对比生成 token IDs + attention_mask）。编写 `scripts/gen_inference_golden.py`（7 条文本与 Python ONNX Runtime 对比，输出 dense/sparse/colbert 预期值）。创建测试目录结构：`test/golden/`、`test/unit/`、`test/integration/`、`test/bench/`。**必须在 Phase 2 之前完成**。 | M |

### 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| HuggingFace 国内不可访问 | P0 | ModelScope 优先下载；`download_model.sh` 自动检测网络并切换镜像 |
| ONNX Runtime 版本不匹配 | P0 | 锁定 v1.17.0；验证 `NativeLibrary.load("onnxruntime")` 成功 |
| Faiss 编译失败（CMake/AVX2） | P0 | 编译前检查 GCC ≥ 9 + CMake ≥ 3.18；如果不支持 AVX2，降级为 `FAISS_OPT_LEVEL=generic` |
| HuggingFace Tokenizers C 无预编译包 | P0 | 提供 Rust cargo 编译脚本作为备用方案；Phase 0 验证失败立即处理 |
| ONNX 导出 L2 norm ≠ 1.0 | P1 | 导出时确认 O2 优化未去掉归一化层；Phase 3 warmup 中二次验证 |
| WSL 构建超时 | P3 | 文档记录 Faiss 全量编译预期 5-10 分钟；使用 `-j$(nproc)` 加速 |

## 6. Phase 3: OrtCpuBackend 实现

**目标**: 实现基于 ONNX Runtime CPU 的 BGE-M3 推理后端，包括零拷贝张量、真批量推理、按名称路由输出。

### 任务清单

| ID | 任务 | 文件 | 描述 | 依赖 | 工作量 |
|----|------|------|------|------|--------|
| T18 | 构造器 + 多步初始化 | `src/backend/ort_cpu_backend.cj` | Step 1-10: 创建 OrtEnv → SessionOptions → 设置线程数+图优化 → 创建 OrtSession → 缓存输入名称 → 按输出名建立 outputNameToIndex HashMap → 获取 Allocator+MemoryInfo → 创建 BgeTokenizer → 构建 BackendInfo → warmup()。**关键**：try-finally 异常路径资源清理——如果 session 创建失败，释放 opts；如果 tokenizer 失败，释放 session+env。 | T5, T7, T10, T13, T14 | L |
| T19 | 零拷贝张量工具函数 | `src/backend/ort_cpu_backend.cj` | `createInt64Tensor(data, shape)` — OrtCreateTensorWithDataAsOrtValue + checkOrtStatus + checkNotNull。`readFloatTensor(value, len)` — OrtGetTensorMutableData → Float32 数组。`getCount(fn)`, `getNames(fn, count)` — 输入/输出元数据。 | T18 | M |
| T20 | 单文本 encode() 实现 | `src/backend/ort_cpu_backend.cj` | Tokenize → createInt64Tensor(input_ids/attn_mask) → runInference（按名称路由，不依赖索引顺序）→ parseOutputs（按名称读取 dense_vec/sparse_vec/colbert_vec）→ 过滤特殊 token → 释放 OrtValue → 可选性能日志。`parseSparseOutput`：过滤 CLS/SEP/PAD/UNK，保留 weight>0 的 token。`reshapeColbert`：扁平张量 → Array<Array<Float32>>。 | T19 | M |
| T21 | 批量 encodeBatch() 实现 | `src/backend/ort_cpu_backend.cj` | Tokenize 全部文本 → 找到 maxSeqLen → 创建 [N, maxLen] 输入张量（Pad 用 0）→ 单次 OrtRun → 解析 N 条输出。空数组返回空；单元素委托 encode()。目标：比逐条循环快 2-5x。 | T20 | M |
