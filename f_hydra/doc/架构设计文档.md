## 1. 项目概述

### 1.1 项目定位

`f_hydra` 是基于仓颉编程语言实现的**本地化混合检索引擎库**，内嵌 BAAI/BGE-M3 多语言嵌入模型。BGE-M3 是目前业界领先的多功能嵌入模型，同时支持：

- **稠密向量检索** (Dense Retrieval) — 1024 维语义向量
- **稀疏向量检索** (Sparse/Lexical Retrieval) — 词权重稀疏向量
- **多向量检索** (Multi-Vector/ColBERT Retrieval) — Token 级多向量矩阵

支持超过 100 种语言，最大输入长度 8192 tokens。

### 1.2 第一版范围

| 维度 | 第一版 (v0.1.0) | 后续版本 |
|------|-----------------|---------|
| 目标平台 | Linux x86_64 | Windows, macOS, HarmonyOS |
| 推理后端 | ONNX Runtime CPU | CUDA, ROCm, OpenVINO, MindSpore Lite, HTTP API, CoreML |
| 默认配置 | CPU 推理，4 线程 | 自动探测硬件 |
| BGE-M3 嵌入 | 进程内 FFI 调用 | 进程内 + HTTP 远端可选 |
| 向量索引 | HNSW + 倒排 + IVF/PQ | 分布式分片 |
| Tokenizer | FFI 调用 HuggingFace Tokenizers C 库 | 同上 |

### 1.3 设计目标

| 维度 | 指标 |
|------|------|
| 功能完整性 | 稠密、稀疏、ColBERT 三种向量索引构建与检索 |
| 混合检索 | 三路召回融合排序，可配置融合策略 (RRF / 加权) |
| 接口统一 | 推理后端通过 `BgeBackend` 接口抽象，上层不感知实现 |
| 本地部署 | 推理与索引均本地执行，BGE-M3 嵌入仓颉进程内 |
| 极致性能 | ONNX Runtime 零拷贝推理，HNSW/IVF 用成熟 C 库 |
| 配置驱动 | 通过环境变量动态选择后端和参数（依赖 f_config） |
| 跨平台架构 | 接口层平台无关，后端按平台实现，仅编译启用 |
| 健壮性 | FFI 错误检查全覆盖、异常路径资源清理、并发安全 |
| 可观测性 | 结构化性能指标、健康检查、warmup 机制 |

### 2.2 设计原则

1. **分层解耦**：API 层 → 编排层 → 后端抽象层 → FFI 桥接层 → 系统层，每层独立可测
2. **接口驱动**：推理后端通过 `BgeBackend` 接口统一，工厂模式按配置创建实例
3. **共享组件优于重复实现**：Tokenizer、错误检查框架提取为共享组件，避免 6 个后端各自实现
4. **向量与索引分离**：Embedding 生成与索引构建/检索分别模块化
5. **配置优于代码**：关键参数通过 f_config 环境变量暴露，运行时动态调整
6. **渐进式复杂度**：默认配置开箱即用，高级参数允许调优
7. **极致性能优先**：零拷贝推理、真批量推理、成熟 C 库 FFI、编译期优化
8. **防卫式 FFI**：每个 FFI 调用必须检查返回值，异常路径 try-finally 释放资源

### 2.3 核心设计决策

| 决策维度 | 选择 | 理由 |
|---------|------|------|
| 推理引擎 | ONNX Runtime (C API) | 跨平台 Execution Provider，成熟稳定 |
| BGE-M3 部署 | 进程内 FFI 嵌入 | 零网络开销，安全可控 |
| 推理后端抽象 | BgeBackend Interface | 未来可透明切换 CPU/GPU/NPU/HTTP |
| 第一版后端 | ONNX Runtime CPU | 无硬件依赖，开箱即用 |
| Tokenizer | **HuggingFace Tokenizers C FFI** (唯一方案) | XLM-RoBERTa SentencePiece BPE 需 BPE merge rules 迭代合并，仓颉原生方案无法产生正确分词 |
| 稠密索引 | HNSW (Faiss C API) | 高维空间精度最优，避免维度灾难 |
| 稀疏索引 | 倒排索引 (仓颉原生) | 数据结构简单，无外部依赖 |
| 多向量索引 | IVF+PQ (Faiss C API) | 兼顾检索速度与存储效率 |
| 融合策略 | RRF 默认 | 免校准，不受得分量纲影响 |
| 配置系统 | f_config 环境变量 | 不依赖配置文件，进程启动即确定 |

## 3. 统一推理后端接口设计 (BgeBackend)

### 3.1 设计目标

为各种 CPU / GPU / NPU / TPU / HTTP-API 访问 BGE-M3 提供统一调用接口。上层检索逻辑完全不感知底层推理后端。通过环境变量选择实现，第一版仅提供 CPU 实现（默认）。

### 3.2 统一接口定义

```cj
// f_hydra/src/backend/bge_backend.cj
package fountain::f_hydra

import std.collection.HashMap

// 后端能力描述
public struct BackendCapabilities {
    public let supportsDense: Bool      // 是否支持稠密向量
    public let supportsSparse: Bool     // 是否支持稀疏向量
    public let supportsColBERT: Bool    // 是否支持多向量
    public let supportsBatch: Bool      // 是否支持真批量推理
    public let hardwareName: String     // 硬件名称 (如 "CPU", "NVIDIA RTX 3090")
}

// 后端信息
public struct BackendInfo {
    public let name: String             // 后端实现名称 (如 "OrtCpuBackend")
    public let version: String          // 版本号
    public let capabilities: BackendCapabilities
}

// BGE-M3 模型输出结构体
public struct BgeOutput {
    public let denseVec: Array<Float32>            // 稠密向量 [1024], L2 归一化
    public let sparseVec: HashMap<Int64, Float32>  // 稀疏向量 {tokenID: weight}, 已过滤特殊 token
    public let colbertVecs: Array<Array<Float32>>  // 多向量 [numTokens * 1024], 已过滤特殊 token
}

// 推理后端统一接口
public interface BgeBackend {
    // 对单条文本编码，返回三种向量
    func encode(text: String): BgeOutput

    // 批量编码（应实现真批量推理，利用 ONNX batch 维度加速）
    func encodeBatch(texts: Array<String>): Array<BgeOutput>

    // 预热：执行一次虚拟推理，预热 ONNX Runtime 图优化和 JIT 编译
    // 在初始化时自动调用，避免首次 encode() 的 2-5s 冷启动延迟
    func warmup()

    // 后端是否已就绪（模型加载成功、推理可用）
    func isReady(): Bool

    // 获取后端元信息
    func backendInfo(): BackendInfo

    // 释放后端占用的资源
    func close()
}
```

**接口设计要点**：

| 方法 | 作用 | 动机 |
|------|------|------|
| `warmup()` | 预热 JIT编译/图优化 | 首次 encode() 冷启动延迟 2-5s |
| `isReady()` | 健康检查 | 捕获模型加载失败，避免运行时异常 |
| `backendInfo()` | 后端识别 | 日志输出、故障诊断、自动后端选择 |

### 3.4 工厂函数：环境变量驱动的后端选择

```cj
// f_hydra/src/backend/backend_factory.cj
package fountain::f_hydra

import fountain.f_config.Config

public struct BackendConfig {
    // 通用配置（所有后端共享）
    public let tokenizerPath: String       // Tokenizer 词表文件路径
    public let enablePerfLog: Bool         // 是否启用性能日志

    // 模型路径（后端自行解释路径语义：文件/目录/URL）
    public let modelPath: String

    // 推理线程数
    public let numThreads: Int64

    // 动态库搜索路径（可选，用于指定 ONNX Runtime .so 路径）
    public let onnxLibPath: ?String
}

// 工厂函数：从环境变量读取配置，创建对应后端实例
// 注意：后端类型决定路径语义（modelPath 对 ORT 是 .onnx 文件，对 HTTP 是 endpoint URL）
public func createBgeBackend(): BgeBackend {
    // 读取配置
    let backendType = (Config.getString("hydra_backend") ?? "ort_cpu").lowerAscii()
    let modelPath = Config.getString("hydra_model_path") ?? "./models/bge-m3-onnx/model.onnx"
    let tokenizerPath = Config.getString("hydra_tokenizer_path") ?? "./models/tokenizer.json"
    let numThreads = Config.getValue<Int64>("hydra_num_threads") ?? 4
    let enablePerfLog = Config.getString("hydra_perf_log") == Some("true")

    let config = BackendConfig(
        modelPath = modelPath,
        tokenizerPath = tokenizerPath,
        numThreads = numThreads,
        enablePerfLog = enablePerfLog,
        onnxLibPath = Config.getString("hydra_onnx_lib_path")
    )

    match (backendType) {
        case "ort_cpu"      => OrtCpuBackend(config)
        case "ort_cuda"     => OrtCudaBackend(config)
        case "ort_openvino" => OrtOpenvinoBackend(config)
        case _              => OrtCpuBackend(config)  // 未知类型回退到 CPU
    }
}
```

**关于 BackendConfig 拆分的决策**：
- v1 保持平面 BackendConfig 结构（仅一个后端）
- v2 引入第二个 ONNX 系列后端（OrtCudaBackend）时拆分为 `BackendCommonConfig` + `OrtBackendConfig` / `HttpBackendConfig` 等后端特定配置
- 工厂函数在各后端路径自行解析后端特定配置

## 4. 共享组件：Tokenizer 设计

### 4.1 设计决策：必须使用 HuggingFace Tokenizers C FFI

**结论**：Option B（仓颉原生基于 JSON 词表的简化 Tokenizer）**不可行**。原因：

1. **算法不匹配**：SentencePiece BPE 不是简单的贪心最长匹配。真实算法包含：Unicode NFKC 归一化 → 预分词 (pre-tokenization) → BPE merge rules 迭代合并（非贪心）→ 后处理
2. **正确性风险**：仓颉原生实现对同一文本产生的 token IDs 将与 Python transformers 不同，导致 ONNX 模型输入不匹配，embedding 质量严重退化
3. **XLM-RoBERTa 特殊性**：词表 250,002 tokens，merge ranks 存储在 `tokenizer.json` 中，不是简单的词表映射

**唯一可行方案**：FFI 调用 HuggingFace Tokenizers C 库 (`tokenizers-c`)。

### 4.2 共享设计

Tokenizer 是后端无关的——仅需要 `tokenizer.json` 词表文件。从 OrtCpuBackend 内部提取为全局共享组件，所有后端复用。

```cj
// f_hydra/src/tokenizer/bge_tokenizer.cj
package fountain::f_hydra

import std.ffi.{CPointer, CString}

// HuggingFace Tokenizers C 库不透明句柄
@C
struct TokenizerHandle {}

public struct TokenizeResult {
    public let inputIds: Array<Int64>
    public let attnMask: Array<Int64>
    public let seqLen: Int64
}

public class BgeTokenizer {
    private let handle: CPointer<TokenizerHandle>

    init(tokenizerPath: String) {
        // 1. 加载 tokenizer.json
        // 2. 通过 FFI 调用 HuggingFace Tokenizers C API:
        //    hf_tokenizer_from_file(path) → handle
        // 3. 从 tokenizer_config.json 读取特殊 token ID
        //    (CLS=0, PAD=1, SEP=2, UNK=3 for XLM-RoBERTa)
        this.handle = unsafe { loadTokenizer(tokenizerPath) }
    }

    public func tokenize(text: String): TokenizeResult {
        // 通过 FFI 调用：
        //   hf_tokenizer_encode(handle, text, add_special_tokens=true)
        //   hf_tokenizer_get_ids(handle) → input_ids
        //   hf_tokenizer_get_attention_mask(handle) → attention_mask
    }

    // 特殊 token ID（从 tokenizer_config.json 读取，不硬编码）
    public let clsTokenId: Int64
    public let padTokenId: Int64
    public let sepTokenId: Int64  // 注意：XLM-RoBERTa 的 SEP 不是 EOS
    public let unkTokenId: Int64

    public func close() {
        unsafe { freeTokenizer(this.handle) }
    }
}
```

### 4.3 Tokenizer 初始化配置读取

特殊 token ID 从 `tokenizer_config.json` 读取，不硬编码：

```json
// tokenizer_config.json 关键字段
{
  "cls_token": "<s>",           // token ID = 0
  "pad_token": "<pad>",         // token ID = 1
  "sep_token": "</s>",          // token ID = 2（注意不是 eos）
  "unk_token": "<unk>"          // token ID = 3
}
```

## 5. FFI 错误检查与安全框架

### 5.1 设计目标

所有 FFI 调用（ONNX Runtime C API、Faiss C API、HuggingFace Tokenizers C API）必须经过统一的错误检查。设计稿中大量的 `// 检查状态...` 注释必须变成真实代码。

无错误检查的后果：
- 模型路径错误 → null session → SIGSEGV
- Faiss add 失败 → 静默数据丢失
- OrtRun 失败 → 未初始化输出数据

### 5.2 统一检查框架

```cj
// f_hydra/src/ffi/ffi_check.cj
package fountain::f_hydra

import std.ffi.CPointer
import fountain.f_hydra.ffi.onnx_types.OrtStatus

public class FfiCheck {
    // 检查 ONNX Runtime OrtStatus 返回值
    public static func checkOrtStatus(status: CPointer<OrtStatus>, context: String) {
        if (status.isNull()) { return }  // null = 成功
        let msg = unsafe { OrtGetErrorMessage(status) }
        let desc = unsafe { msg.readCString() }
        unsafe { OrtReleaseStatus(status) }
        throw Exception("FfiError: ${context}: ${desc}")
    }

    // 检查 Faiss API 返回值（返回负值为错误）
    public static func checkFaissReturn(ret: Int32, context: String) {
        if (ret >= 0) { return }
        throw Exception("FfiError: ${context}: Faiss returned error code ${ret}")
    }

    // 检查 CPointer 非空
    public static func checkNotNull<T>(ptr: CPointer<T>, context: String): CPointer<T> {
        if (ptr.isNull()) {
            throw Exception("FfiError: ${context}: unexpected null pointer")
        }
        ptr
    }
}
```

### 5.3 错误检查使用模式

每个 FFI 调用处必须显式调用检查函数：

```cj
// 错误检查模式示例
let status = unsafe { OrtCreateEnv(3, "f_hydra".toCString(), envPtr) }
FfiCheck.checkOrtStatus(status, "OrtCreateEnv")

let rawHandle = unsafe { faiss_IndexHNSWFlat_new(dim, M) }
this.handle = FfiCheck.checkNotNull(rawHandle, "faiss_IndexHNSWFlat_new")
```

## 6. 动态库加载抽象层

### 6.1 设计目标

为跨平台动态库加载提供统一接口，消除 `LD_LIBRARY_PATH` 硬编码依赖。

### 6.2 接口设计

```cj
// f_hydra/src/platform/native_library.cj
package fountain::f_hydra

import std.ffi.CPointer
```

```cj
        // 尝试多个搜索路径

    }
```

## 8. 第一版实现：OrtCpuBackend

### 8.1 架构定位

第一版仅实现 `OrtCpuBackend`，使用 ONNX Runtime CPU Execution Provider 作为默认推理后端。这是整个 `BgeBackend` 接口的参考实现，后续所有后端都遵循相同的接口契约。

### 8.2 完整实现

```cj
// f_hydra/src/backend/ort_cpu_backend.cj
package fountain::f_hydra

import std.ffi.{CPointer, CString}
import std.collection.HashMap
import std.time.DateTime
import std.time.Duration
import fountain.f_config.Config
import fountain.f_hydra.*
import fountain.f_hydra.ffi.onnx_types.*
import fountain.f_hydra.ffi.onnx_bridge.*
import fountain.f_hydra.ffi.FfiCheck

// ONNX Runtime CPU 推理后端 — 第一版默认实现
public class OrtCpuBackend <: BgeBackend {
    // === C 侧资源句柄 ===
    private var env: ?CPointer<OrtEnv>
    private var session: ?CPointer<OrtSession>
    private let allocator: CPointer<OrtAllocator>
    private let memInfo: CPointer<OrtMemoryInfo>

    // === 缓存的元数据 ===
    private let inputNames: Array<CString>
    // 输出名称→索引映射表（不依赖输出顺序）
    private let outputNameToIndex: HashMap<String, Int64>
    private let inputCount: UInt64
    private let outputCount: UInt64
    private let dim: Int64 = 1024

    // === 共享 Tokenizer（初始化一次，所有后端复用） ===
    private let tokenizer: BgeTokenizer

    // === 性能统计 ===
    private let enablePerfLog: Bool

    // === 模型信息 ===
    private let info: BackendInfo

    init(config: BackendConfig) {
        this.enablePerfLog = config.enablePerfLog

        // Step 1: 创建 ONNX Runtime 环境
        this.env = None
        this.session = None

        var envPtr = CPointer<CPointer<OrtEnv>>()
        let envStatus = unsafe {
            OrtCreateEnv(3, "f_hydra".toCString(), envPtr)
        }
        FfiCheck.checkOrtStatus(envStatus, "OrtCreateEnv")
        this.env = Some(envPtr.read())

        // Step 2: 创建会话选项
        var optsPtr = CPointer<CPointer<OrtSessionOptions>>()
        var optsStatus = unsafe { OrtCreateSessionOptions(optsPtr) }
        FfiCheck.checkOrtStatus(optsStatus, "OrtCreateSessionOptions")
        let opts = optsPtr.read()

        try {
            // Step 3: 设置推理线程数
            let threadStatus = unsafe { OrtSetIntraOpNumThreads(opts, config.numThreads) }
            FfiCheck.checkOrtStatus(threadStatus, "OrtSetIntraOpNumThreads")

            // Step 4: 启用全部图优化
            let optStatus = unsafe { OrtSetSessionGraphOptimizationLevel(opts, 99) }
            FfiCheck.checkOrtStatus(optStatus, "OrtSetSessionGraphOptimizationLevel")

            // Step 5: 创建推理会话
            var sessPtr = CPointer<CPointer<OrtSession>>()
            let sessStatus = unsafe {
                OrtCreateSession(envPtr.read(), config.modelPath.toCString(), opts, sessPtr)
            }
            FfiCheck.checkOrtStatus(sessStatus, "OrtCreateSession")
            this.session = Some(sessPtr.read())

            // Step 6: 获取输入/输出元数据（避免每次推理查询）
            this.inputCount = this.getCount(OrtSessionGetInputCount)
            this.outputCount = this.getCount(OrtSessionGetOutputCount)
            this.inputNames = this.getNames(OrtSessionGetInputName, this.inputCount)

            // 按输出名称建立映射表（不使用索引，防止 ONNX 导出顺序变化）
            this.outputNameToIndex = HashMap<String, Int64>()
            for (i in 0..this.outputCount) {
                var namePtr = CPointer<CString>()
                let _ = unsafe { OrtSessionGetOutputName(
                    if (let Some(s) <- this.session) { s } else { throw Exception("session null") },
                    i, this.allocator, namePtr
                )}
                let name = unsafe { namePtr.read().readCString() }
                this.outputNameToIndex[name] = i
            }

            // Step 7: 获取分配器和内存信息
            var allocPtr = CPointer<CPointer<OrtAllocator>>()
            let _ = unsafe { OrtGetAllocatorWithDefaultOptions(allocPtr) }
            this.allocator = allocPtr.read()

            var memPtr = CPointer<CPointer<OrtMemoryInfo>>()
            let memStatus = unsafe { OrtCreateCpuMemoryInfo(1, 0, memPtr) }
            FfiCheck.checkOrtStatus(memStatus, "OrtCreateCpuMemoryInfo")
            this.memInfo = memPtr.read()

            // Step 8: 初始化共享 Tokenizer
            this.tokenizer = BgeTokenizer(config.tokenizerPath)

            // Step 9: 构建后端信息
            this.info = BackendInfo(
                name = "OrtCpuBackend",
                version = "0.1.0",
                capabilities = BackendCapabilities(
                    supportsDense = true,
                    supportsSparse = true,
                    supportsColBERT = true,
                    supportsBatch = true,
                    hardwareName = "CPU (OR-T ${config.numThreads} threads)"
                )
            )

            // Step 10: 预热 + 模型验证
            this.warmup()
        } catch (e: Exception) {
            // 异常路径资源清理
            if (let Some(s) <- this.session) { unsafe { OrtReleaseSession(s) } }
            unsafe { OrtReleaseSessionOptions(opts) }
            throw e  // 重新抛出
        }

        // 释放会话选项（会话创建成功后即可释放）
        unsafe { OrtReleaseSessionOptions(opts) }
    }

    // === BgeBackend 接口实现 ===

    public func encode(text: String): BgeOutput {
        let start = if (enablePerfLog) { DateTime.now() } else { DateTime(0) }

        // 1. Tokenize
        let tokens = tokenizer.tokenize(text)

        // 2. 创建输入 OrtValue（零拷贝）
        let inputIdsValue = createInt64Tensor(tokens.inputIds, [1, tokens.seqLen])
        let attnMaskValue = createInt64Tensor(tokens.attnMask, [1, tokens.seqLen])

        // 3. 执行推理
        let outputValues = runInference([
            (this.inputNames[0], inputIdsValue),
            (this.inputNames[1], attnMaskValue)
        ])

        // 4. 按名称解析输出（不依赖索引顺序）
        let result = parseOutputs(outputValues, tokens)

        if (enablePerfLog) {
            let elapsed = DateTime.now().durationSince(start)
            println("OrtCpuBackend.encode: ${elapsed.toMilliseconds()}ms, tokens=${tokens.seqLen}")
        }

        // 5. 释放 OrtValue
        unsafe {
            OrtReleaseValue(inputIdsValue)
            OrtReleaseValue(attnMaskValue)
            for (v in outputValues) { OrtReleaseValue(v) }
        }
        return result
    }

    public func encodeBatch(texts: Array<String>): Array<BgeOutput> {
        // 真批量推理：构造 [N, max_seq_len] 张量，单次 OrtRun
        // 比逐条 encode 快 3-5x
        if (texts.size == 0) { return Array<BgeOutput>() }
        if (texts.size == 1) { return [this.encode(texts[0])] }

        let start = if (enablePerfLog) { DateTime.now() } else { DateTime(0) }

        // 1. 批量 Tokenize
        var allTokens = ArrayList<TokenizeResult>(texts.size)
        var maxLen: Int64 = 0
        for (text in texts) {
            let t = tokenizer.tokenize(text)
            maxLen = max(maxLen, t.seqLen)
            allTokens.add(t)
        }

        // 2. Pad 到 maxLen，构造 [N, maxLen] input_ids 和 attention_mask
        let N = texts.size
        let flatInputIds = Array<Int64>(N * maxLen, 0)
        let flatAttnMask = Array<Int64>(N * maxLen, 0)
        for (i in 0..N) {
            let t = allTokens[i]
            for (j in 0..t.seqLen) {
                flatInputIds[i * maxLen + j] = t.inputIds[j]
                flatAttnMask[i * maxLen + j] = t.attnMask[j]
            }
            // 剩余位置保持 0 (pad)
        }

        // 3. 零拷贝创建 [N, maxLen] 张量
        let inputIdsValue = createInt64Tensor(flatInputIds, [N, maxLen])
        let attnMaskValue = createInt64Tensor(flatAttnMask, [N, maxLen])

        // 4. 单次推理
        let outputValues = runInference([
            (this.inputNames[0], inputIdsValue),
            (this.inputNames[1], attnMaskValue)
        ])

        // 5. 解析批量输出
        var results = Array<BgeOutput>(N) {_ => BgeOutput(
            denseVec = Array<Float32>(dim, 0.0),
            sparseVec = HashMap<Int64, Float32>(),
            colbertVecs = Array<Array<Float32>>()
        )}

        // dense: [N, dim]
        for (i in 0..N) {
            results[i] = parseOneFromBatch(outputValues, allTokens[i], i, N, maxLen)
        }

        if (enablePerfLog) {
            let elapsed = DateTime.now().durationSince(start)
            println("OrtCpuBackend.encodeBatch: ${elapsed.toMilliseconds()}ms, N=${N}")
        }

        // 释放
        unsafe {
            OrtReleaseValue(inputIdsValue)
            OrtReleaseValue(attnMaskValue)
            for (v in outputValues) { OrtReleaseValue(v) }
        }
        return results
    }

    public func warmup() {
        // 用虚拟输入（最小有效文本）执行一次推理
        // 目的：预热 ONNX Runtime 图优化、JIT 编译、内存分配
        let _ = this.encode("warmup")
    }

    public func isReady(): Bool {
        this.session.isSome()
    }

    public func backendInfo(): BackendInfo {
        this.info
    }

    public func close() {
        // 先释放在用资源（session 依赖 env），顺序不能反
        if (let Some(s) <- this.session) {
            unsafe { OrtReleaseSession(s) }
            this.session = None
        }
        unsafe { OrtReleaseMemoryInfo(this.memInfo) }
        if (let Some(e) <- this.env) {
            unsafe { OrtReleaseEnv(e) }
            this.env = None
        }
        tokenizer.close()
    }

    // === 内部方法 ===

    // 零拷贝创建 Int64 张量
    private func createInt64Tensor(data: Array<Int64>, shape: Array<Int64>): CPointer<OrtValue> {
        var out = CPointer<CPointer<OrtValue>>()
        let status = unsafe {
            OrtCreateTensorWithDataAsOrtValue(
                this.memInfo,
                data.toCPointer() as CPointer<UInt8>,
                (data.size * 8) as UInt64,  // Int64 = 8 bytes
                shape.toCPointer(),
                shape.size as UInt64,
                7,  // 7 = ONNX_TENSOR_ELEMENT_DATA_TYPE_INT64
                out
            )
        }
        FfiCheck.checkOrtStatus(status, "OrtCreateTensorWithDataAsOrtValue")
        let result = out.read()
        FfiCheck.checkNotNull(result, "createInt64Tensor result")
        result
    }

    // 执行推理
    private func runInference(inputs: Array<(CString, CPointer<OrtValue>)>): Array<CPointer<OrtValue>> {
        let inputNameArr = Array<CString>(inputs.size) {i => inputs[i][0]}
        let inputValArr = Array<CPointer<OrtValue>>(inputs.size) {i => inputs[i][1]}
        let outputNameArr = Array<CString>(this.outputNameToIndex.size) {_ => CString()}
        // 按索引排列输出名称
        for ((name, idx) in this.outputNameToIndex) {
            outputNameArr[idx] = name.toCString()
        }

        var outputValArr = Array<CPointer<OrtValue>>(this.outputCount) {_ =>
            CPointer<OrtValue>()
        }

        let session = if (let Some(s) <- this.session) { s } else {
            throw Exception("OrtCpuBackend: session not initialized")
        }

        let status = unsafe {
            OrtRun(
                session,
                CPointer<OrtRunOptions>(),
                inputNameArr.toCPointer(),
                inputValArr.toCPointer(),
                this.inputCount,
                outputNameArr.toCPointer(),
                this.outputCount,
                outputValArr.toCPointer()
            )
        }
        FfiCheck.checkOrtStatus(status, "OrtRun")
        outputValArr
    }

    // 按输出名称解析 BGE-M3 三个输出
    private func parseOutputs(outputValues: Array<CPointer<OrtValue>>,
                              tokens: TokenizeResult): BgeOutput {
        // 按名称访问输出，不依赖索引顺序
        let denseIdx = this.outputNameToIndex["dense_vec"] ?? 0
        let sparseIdx = this.outputNameToIndex["sparse_vec"] ?? 1
        let colbertIdx = this.outputNameToIndex["colbert_vec"] ?? 2

        let denseVec = readFloatTensor(outputValues[denseIdx], this.dim)
        let rawSparse = readFloatTensor(outputValues[sparseIdx], tokens.seqLen)
        let sparseVec = parseSparseOutput(rawSparse, tokens.inputIds)
        let colbertVecs = reshapeColbert(
            readFloatTensor(outputValues[colbertIdx], tokens.seqLen * this.dim),
            tokens.seqLen, this.dim
        )

        BgeOutput(denseVec = denseVec, sparseVec = sparseVec, colbertVecs = colbertVecs)
    }

    // 零拷贝读取 Float32 张量
    private func readFloatTensor(value: CPointer<OrtValue>, len: Int64): Array<Float32> {
        var dataPtr = CPointer<CPointer<UInt8>>()
        let status = unsafe { OrtGetTensorMutableData(value, dataPtr) }
        FfiCheck.checkOrtStatus(status, "OrtGetTensorMutableData")
        let floatPtr = FfiCheck.checkNotNull(
            dataPtr.read() as CPointer<Float32>, "readFloatTensor dataPtr"
        )
        Array<Float32>(len) {i =>
            unsafe { floatPtr[i] }
        }
    }

    // 解析稀疏输出：过滤特殊 token，保留权重大于 0 的 token
    private func parseSparseOutput(rawSparse: Array<Float32>,
                                   inputIds: Array<Int64>): HashMap<Int64, Float32> {
        var result = HashMap<Int64, Float32>()
        for i in 0..inputIds.size {
            let tokenId = inputIds[i]
            let weight = rawSparse[i]
            // 过滤特殊 token（从 tokenizer 读取，不硬编码）
            if (tokenId != tokenizer.clsTokenId &&
                tokenId != tokenizer.sepTokenId &&
                tokenId != tokenizer.padTokenId &&
                tokenId != tokenizer.unkTokenId &&
                weight > 0.0) {
                if (!result.contains(tokenId) || weight > result[tokenId]) {
                    result[tokenId] = weight
                }
            }
        }
        result
    }

    // 重塑 ColBERT 多向量矩阵（同样排除特殊 token）
    private func reshapeColbert(flat: Array<Float32>,
                                seqLen: Int64, dim: Int64): Array<Array<Float32>> {
        // 仅保留非特殊 token 的向量
        var result = ArrayList<Array<Float32>>()
        for i in 0..seqLen {
            // ColBERT 应同样排除特殊 token（与稀疏输出一致）
            // 在上层 HybridSearchEngine 中由 BgeEngine 过滤
            let vec = Array<Float32>(dim) {j => flat[i * dim + j]}
            result.add(vec)
        }
        // 转换为 Array（不可变）
        Array<Array<Float32>>(result.size) {i => result[i]}
    }

    // 辅助：获取计数
    private func getCount(
        fn: (CPointer<OrtSession>, CPointer<UInt64>) -> CPointer<OrtStatus>
    ): UInt64 {
        let session = if (let Some(s) <- this.session) { s } else {
            throw Exception("session null in getCount")
        }
        var out = CPointer<UInt64>()
        let status = unsafe { fn(session, out) }
        FfiCheck.checkOrtStatus(status, "getCount")
        out.read()
    }

    // 辅助：获取名称列表
    private func getNames(
        fn: (CPointer<OrtSession>, UInt64, CPointer<OrtAllocator>, CPointer<CString>) -> CPointer<OrtStatus>,
        count: UInt64
    ): Array<CString> {
        let session = if (let Some(s) <- this.session) { s } else {
            throw Exception("session null in getNames")
        }
        Array<CString>(count) {i =>
            var out = CPointer<CString>()
            let status = unsafe { fn(session, i, this.allocator, out) }
            FfiCheck.checkOrtStatus(status, "getNames")
```

```cj
import std.sync.Mutex
import fountain.f_hydra.ffi.faiss_types.FaissIndex
import fountain.f_hydra.ffi.faiss_bridge.*
import fountain.f_hydra.ffi.FfiCheck

public class DenseIndexer {
    private let handle: CPointer<FaissIndex>
    private let dim: Int64
    // Faiss 索引非线程安全，所有 add/search 需同步保护
    private let lock: Mutex

    init(dim: Int64, M: Int64, efConstruction: Int64) {
        this.dim = dim
        this.lock = Mutex()
        let rawHandle = unsafe { faiss_IndexHNSWFlat_new(dim, M) }
        this.handle = FfiCheck.checkNotNull(rawHandle, "faiss_IndexHNSWFlat_new")

        // 设置 efConstruction（通过 Faiss 参数接口）
        // Faiss C API: faiss_ParameterSpace_set_index_parameter(
        //   paramspace, index, "hnsw.efConstruction", efConstruction)
        // ...
    }

    public func buildIndex(embeddings: Array<Array<Float32>>) {
        synchronized(this.lock) {
            let n = embeddings.size
            let flat = Array<Float32>(n * dim) {i =>
                embeddings[i / dim][i % dim]
            }
            let ret = unsafe { faiss_Index_add(this.handle, n, flat.toCPointer()) }
            FfiCheck.checkFaissReturn(ret, "faiss_Index_add")
        }
    }

    // 分批构建：避免双倍内存
    public func buildIndexBatched(embeddings: Array<Array<Float32>>, batchSize: Int64 = 1000) {
        for (start in 0..embeddings.size:batchSize) {
            let end = min(start + batchSize, embeddings.size)
            let batch = Array<Array<Float32>>(end - start) {i => embeddings[start + i]}
            // 每批创建扁平面量 → add to Faiss → 释放批次内存
            synchronized(this.lock) {
                let flat = Array<Float32>(batch.size * dim) {i =>
                    batch[i / dim][i % dim]
                }
                let ret = unsafe { faiss_Index_add(this.handle, batch.size, flat.toCPointer()) }
                FfiCheck.checkFaissReturn(ret, "faiss_Index_add batched")
            }
        }
    }

    public func search(query: Array<Float32>, k: Int64): Array<(Int64, Float32)> {
        synchronized(this.lock) {
            let distances = Array<Float32>(k, 0.0)
            let labels = Array<Int64>(k, -1)
            let ret = unsafe {
                faiss_Index_search(this.handle, 1, query.toCPointer(), k,
                                   distances.toCPointer(), labels.toCPointer())
            }
            FfiCheck.checkFaissReturn(ret, "faiss_Index_search")
            Array<(Int64, Float32)>(k) {i => (labels[i], distances[i])}
        }
    }

    public func save(path: String) {
        let ret = unsafe { faiss_write_index_fname(this.handle, path.toCString()) }
        FfiCheck.checkFaissReturn(ret, "faiss_write_index_fname")
    }

    public func close() {
        unsafe { faiss_Index_free(this.handle) }
    }
}
```

```cj
// f_hydra/src/engine.cj
package fountain::f_hydra

import std.sync.{Mutex, AtomicBool}
import std.time.Duration

public class HybridSearchEngine {
    private let embedder: BgeBackend
    private let denseIndexer: DenseIndexer
    private let sparseIndexer: SparseIndexer
    private let colbertIndexer: ColBERTIndexer
    private let fusion: FusionLayer

    // 关闭保护
    private var closing: AtomicBool
    private var activeFutures: ArrayList<Future<Unit>>

    public init() {
        // 启动时校验配置
        let errors = HydraConfig.validate()
        if (errors.size > 0) {
            for (err in errors) { eprintln("[f_hydra] Config error: ${err}") }
            throw Exception("Config validation failed: ${errors.size} error(s)")
        }

        // 从环境变量创建推理后端
        this.embedder = createBgeBackend()

        // 日志后端信息
        let info = embedder.backendInfo()
        println("[f_hydra] Backend: ${info.name} v${info.version}, HW: ${info.capabilities.hardwareName}")

        this.denseIndexer = DenseIndexer(
            dim = 1024,
            M = HydraConfig.hnswM(),
            efConstruction = HydraConfig.hnswEfConstruction()
        )
        this.sparseIndexer = SparseIndexer(
            useSkipPointers = HydraConfig.sparseUseSkipPointers()
        )
        this.colbertIndexer = ColBERTIndexer()
        this.fusion = FusionLayer()
        this.closing = AtomicBool(false)
        this.activeFutures = ArrayList<Future<Unit>>()
    }

    public func search(query: String, topK: Int64): HybridSearchResult {
        let start = DateTime.now()
        let timeout = Duration.millisecond * HydraConfig.searchTimeoutMs()

        if (closing.load()) {
            throw Exception("HybridSearchEngine is closing")
        }

        // 1. 编码查询文本
        let queryVec = embedder.encode(query)

        // 2. 并行执行稠密和稀疏检索（粗排）
        let coarseK = HydraConfig.coarseK()
        var denseResultsFuture = spawn { => this.denseIndexer.search(queryVec.denseVec, coarseK) }
        var sparseResultsFuture = spawn { => this.sparseIndexer.search(queryVec.sparseVec, coarseK) }

        // 超时控制
        let denseResults = denseResultsFuture.get(timeout)
        let sparseResults = if (let Some(r) <- sparseResultsFuture.get(timeout)) {
            r
        } else {
            Array<ScoredDocument>()  // 超时：使用空结果，优雅降级
        }

        // 3. ColBERT 精排
        let candidatePool = mergeCandidates(denseResults, sparseResults)
        let colbertResults = colbertIndexer.search(
            queryVec.colbertVecs,
            HydraConfig.rerankDepth(),
            HydraConfig.colbertCentroidSearchWidth()
        )

        // 4. 融合排序
        let finalResults = fusion.fuse(
            sparseResults, denseResults, colbertResults,
            HydraConfig.fusionStrategy(),
            HydraConfig.fusionWeights(),
            topK
        )

        let elapsed = DateTime.now().durationSince(start)
        HybridSearchResult(results = finalResults, latency = elapsed)
    }

    public func close() {
        // Step 1: 设置关闭标志（阻止新操作）
        closing.store(true)

        // Step 2: 等待所有正在运行的检索完成
        for (f in activeFutures) {
            f.get(Duration.millisecond * 5000)
        }

        // Step 3: 释放资源（顺序重要：先关高级资源，再关底层资源）
        embedder.close()
        denseIndexer.close()
        // sparseIndexer 不需要显式关闭（纯仓颉对象 GC 处理）
    }
}
```

## 13. 并发安全设计

### 13.1 Faiss 索引并发保护

**核心问题**：Faiss HNSWIndex 和 IndexIVF **不是线程安全的**。并发 `Index_add` 或 `Index_search` 会导致数据损坏或 SIGSEGV。

**解决方案**：每个 Faiss 索引包装用 `synchronized(lock)` 保护所有 add/search 操作。

### 13.2 关闭顺序设计

```
close() 流程:
  1. AtomicBool closing = true      (阻止新操作)
  2. join 所有 active futures        (等待运行中的 search)
  3. 释放 embedder (OrtCpuBackend)
  4. 释放 Faiss 索引
  5. 释放 tokenizer
```

**注意**：必须先设置标志再 join futures，最后释放资源。不按此顺序会导致：
- 释放资源后 search 仍在运行 → SIGSEGV
- 不等待 futures 就释放 → 竞态条件

### 13.3 稀疏索引无需加锁

仓颉原生稀疏倒排索引是**只读的**（search 不修改索引），无需并发保护。仅在 buildIndex 时有写操作（此时不并发 search）。

## 14. 关键技术要点与风险

### 14.1 Tokenizer 正确性（P0）

**风险**：XLM-RoBERTa SentencePiece BPE 不是简单贪心最长匹配。

**方案**：**必须使用 HuggingFace Tokenizers C FFI**。仓颉原生方案（Option B）无法产生正确分词，会导致 embedding 质量严重退化。这是正确性基础，不可妥协。

### 14.2 FFI 错误检查全覆盖（P0）

**风险**：设计稿中大量 `// 检查状态...` 注释为占位符，无一实现。

**方案**：为所有 FFI 调用添加统一检查框架 `checkOrtStatus()`、`checkFaissReturn()`、`checkNotNull()`。每个 `OrtCreate*`、`OrtRun`、`faiss_Index_*` 调用都必须显式检查返回值。

### 14.3 异常路径资源清理（P0）

**风险**：多步初始化中前面步骤成功后后面步骤失败，已获取资源泄漏。

**方案**：try-finally 包装多步初始化。session 创建失败时释放 opts；env 创建失败时在 catch 中释放 env。

### 14.4 零拷贝内存安全（P0）

**风险**：`OrtCreateTensorWithDataAsOrtValue` 将仓颉数组内存传给 C。如果 GC 在 OrtRun 期间移动该内存 → use-after-free。

**方案**：当前实现中 OrtValue 在 encode() 返回前释放，局部变量在栈上存活着，假设安全。需通过 ASAN/Valgrind 明确验证。在文档中标注假设和边界条件。

### 14.5 ONNX 输出顺序不可假设（P0）

**风险**：`parseOutputs` 依赖 `outputs[0]=dense, outputs[1]=sparse, outputs[2]=colbert` 索引顺序。这个顺序取决于 ONNX 导出配置，不保证。

**方案**：使用 `OrtSessionGetOutputName` 获取名称，按名称路由而非索引。

### 14.6 稠密向量 L2 归一化验证（P1）

**风险**：如果 ONNX 模型未包含归一化层（取决于导出配置），稠密向量距离计算不正确。

**方案**：warmup() 中做一次验证推理，检查 dense L2 norm。如果不在 [0.999, 1.001] 范围内，抛异常告知用户或自动归一化。

### 14.7 ColBERT 索引构建时间（P2）

**风险**：IVF+PQ 需要 K-Means 聚类，在 CPU 上处理百万级 token 池可能耗时数小时。

**方案**：
- 训练与构建分离：训练阶段可离线进行，结果持久化复用
- 添加进度日志：`println("Training K-Means (K=${K}, N=${N} vectors)...")`
- 支持预训练质心导入，避免每次重建训练
- v2 支持分批采样训练

### 14.8 ModelScope vs HuggingFace 下载策略（P2）

**风险**：HuggingFace 在国内可能被屏蔽或速度极慢。

**方案**：提供 ModelScope 下载脚本作为国内用户首选。在 `download_model.sh` 中优先检测 pf/墙，自动选择镜像站。

### 14.9 内存增长边界

**风险报告**：

| 文档数 | 预估内存 | 组成 |
|--------|---------|------|
| 1 万 | ~1 GB | dense 40MB + sparse 200MB + colbert 800MB |
| 10 万 | ~10 GB | dense 400MB + sparse 2GB + colbert 8GB |
| 100 万 | ~100 GB | 超出单机容量 |

**方案**：在文档中标注内存公式。建议 v1 目标数据集 ≤ 10 万文档。v2 引入 mmap + FP16 混合精度。

### 14.10 ColBERT MaxSim 延迟预估

ColBERT MaxSim 对 100 篇候选文档、每篇 100 tokens 的复杂度为 O(candidates × query_tokens × doc_tokens) ≈ 100 × 100 × 100 = 1M 次向量比较。预估 100-300ms。

**方案**：通过 `rerankDepth` 控制候选池大小（推荐 ≤ 50），保持延迟可控。

## 16. 后续平台扩展路线

### 16.1 扩展模式

所有后续平台都遵循相同的扩展模式：

1. 实现 `BgeBackend` 接口（encode/encodeBatch/warmup/isReady/backendInfo/close）
2. 在 `BackendType` 枚举中添加新值
3. 在工厂函数中注册新的匹配分支
4. 通过 `${fountain_hydra_backend}` 环境变量切换

### 16.2 已规划后端

| 平台 | 后端 | 实现方式 | 优先级 |
|------|------|---------|--------|
| Linux x86_64 CPU | `OrtCpuBackend` | ONNX Runtime FFI | **P0（第一版）** |
| Linux x86_64 + NVIDIA GPU | `OrtCudaBackend` | ONNX Runtime + CUDA EP | P1 |
| Linux x86_64 + Intel CPU | `OrtOpenvinoBackend` | ONNX Runtime + OpenVINO EP | P1 |
| Linux + AMD GPU | `OrtRocmBackend` | ONNX Runtime + ROCm EP | P1 |
| macOS (Apple Silicon) | `CoreMlBackend` | Core ML C API FFI | P2 |
| Windows + GPU | `OrtCudaBackend` | ONNX Runtime + CUDA/DirectML | P2 |
| 远程推理服务 | `HttpBgeBackend` | HTTP REST API (TEI/vLLM) | P2 |
| HarmonyOS + 麒麟 NPU | `MindSporeBgeBackend` | MindSpore Lite NAPI FFI | P2 |

### 16.3 HTTP 后端决定

HTTP 后端保持 P2 优先级。v1 核心价值主张是"进程内本地嵌入"（零网络延迟、数据安全），HTTP 后端引入网络依赖和 JSON 序列化开销，背离 local-first 架构定位。当后续版本需要支持多平台同时上线时，HTTP 后端将解锁 Windows/macOS/HarmonyOS 用户。

### 16.4 扩展示例：CUDA GPU 后端（P1）

```cj

    }

        // 与 OrtCpuBackend 完全相同的接口实现
        // 底层 ONNX Runtime 自动将计算调度到 GPU
```

### 16.5 扩展示例：HTTP API 后端（P2）

```cj

    private let endpoint: String

    init(config: BackendConfig) {
        // modelPath 在此后端表示 HTTP endpoint URL
        this.endpoint = config.modelPath
    }

    public func encode(text: String): BgeOutput {
        // 1. 构造 JSON 请求体
        // 2. 发送 HTTP POST 到 /embed 端点
        // 3. 解析 JSON 响应
        // 4. 返回 BgeOutput
    }
```

### 16.6 后端优先级决策

**HTTP 后端不提升到 P1 的理由**：
- v1 核心价值是"进程内本地嵌入"（零网络、零延迟、数据安全）
- 引入 HTTP 后端 = f_net 依赖 + JSON 序列化开销 + 网络错误处理
- 如果用户需要 HTTP 嵌入式服务，说明已有 GPU 服务器，走 CPU v1 不匹配
- HTTP 后端在 v2 与多平台扩展同步上线时价值最大

### 附录 C：设计原则总结

| 原则 | 体现 |
|------|------|
| **极致性能** | 零拷贝推理、真批量推理、成熟 C 库 FFI、并行构建/检索、编译期 LTO |
| **配置驱动** | 所有参数通过 f_config 环境变量控制，启动时 validate() 校验 |
