# Coordinator
# 同步协议
```cj
public class CoordinationData <: ToString & Hashable & Equatable<CoordinationData> {
    public var sha256: String
    public CoordinationData(

```cj
//每个进程节点对应一个ConcurrentHashMap的元素，KEY是节点的IP:PORT
//每条数据都有一个主节点，添加、更新、删除数据都在主节点进行。
//每个节点都保存所有数据，添加/更新数据时，客户端用KEY的一致性哈希确认数据的主节点。
//每个节点把自己的数据同步到其他节点。
//每个节点接收到数据，再次计算KEY的MurmurHash，找到对应节点，并找到CoordinationNode
//如果任意节点失效，从TreeMap移除失效节点，服务端不移除。
private let murmurs: TreeMap<MurmurHash128, String>//MurmurHash128:'${IP}:${PORT}'，每个节点重复160次
private let datas: ConcurrentHashMap<String, CoordinationNode>
```

数据保存到`ConcurrentHashMap<String, CoordinationData>`，键是CoordinationData.key。
用`CoordinationData.toString()`计算SHA256。
更新数据后，将数据推到更新队列，由另外的线程向其他节点发送当前更新。

1. 数据构成
   - 配置
     - 配置项的键和值
   - 服务项
     - ```json
       {//IP:PORT是服务项的键，这个JSON是值，
        //同一个服务节点会有许多服务项，以JsonArray形式保存到CoordinationData.value
           "typeName": "qualifiedNameOfType",
           "function:" "functionName",
           "argTypes": ["qualifiedNameOfArgs"],
           "version": "x.y.z"//服务版本号
       }
     ```
   - 主题
     - 以UNIX路径形式定义主题
       - 不支持路径参数
       - 路径作为主题数据的键
     - ```json
       {//MQ BROKER以一致性哈希自主确认自己为哪些主题提供服务
            "topic": "/topic/path",
            "queues": 1,//队列数
            "consumerNames": ["consumerName1", "consumerName2"]
            //消费者初始化时必须指定消费者组，同一组的消费者不会重复消费同一条消息
       }
     ```
2. 构造MERKLE-TREE
   - 数据的SHA256两两配对计算SHA256
   - 重复这个过程直到只有一个SHA256
   - 按以上过程一层一层向上构造MERKLE-TREE
3. 更新&同步数据（PUBLISH）
   - 版本号+1
   - 时间戳更新为当前时间
   - KEY+数据+版本号+UPDATE计算SHA256
   - 新数据推到更新队列，由另外的线程向其他节点发送当前更新
   - 节点失效后客户端重新确认一致性哈希
     - 节点恢复后，向其他节点索取代理自己接收的数据
       - 从MerkleTree的根开始向其他节点询问数据是否一致
       - 按照不一致的SHA256，继续向下寻找SHA256不一致的节点
       - 当前节点恢复后与其他节点两两之间多次交互重复询问、比较MerkleTree中不一致的节点。
       - 最后找到所有不一致的数据，并同步过来。
   - 只要还有一个节点有效，就可以继续提供服务
     - C：最终一致性
     - A：尽量保持可用性
     - P：万一发生脑裂，每个分片继续提供服务。这是用来注册服务和配置数据的，不会有频繁的更新。

# 启动&保活
1. 启动
   - 启动第一个节点，PING其它节点
     - PING不通，执行RemoteNode启动其他节点
        ```cj
        public interface RemoteNode {
            func startup()
        }
        public struct SSHRemoteNode <: RemoteNode{}//需要这些节点之间可以免密SSH访问
        ```
2. 保活
   - 节点之间随机时间间隔互PING
     - PING不必带消息体
   - 客户端跟coordinator之间也要PING，并且PING的时候要带着客户端能够PING的节点
   - 对于客户端能PING，当前节点不能PING的节点，标记为不能访问
   - 对于客户端和自己都不能PING的节点标记为失效
     - 此时与其他能够访问的节点协商(ELECT)决定由哪个节点尝试重新启动
     - 如果网络不能PING通，一段随机时间后重新尝试
