## §0 总览与设计原则

**需求**：字节码/机器码在执行期**接收**宿主仓颉闭包做实参，并在字节码世界内**调用**它。

**继承**：M1 全部硬不变式（I1–I8）原样生效——ID 形态（冻结决策 ④：宿主闭包对象同样只以整数 ID 进入字节码世界）、fail-fast（错误写槽即终止）、封闭白名单（本次按 §13.3 规则**扩展**白名单：激活 `CALL_HOST` + 新增 H60，构成 M2 的白名单增量）。

**核心设计决策（本文的支点）**：

> **CALL_HOST 在机器码层面 = "目标运行期确定的 helper 调用"。**
> 转发器 H60 是一个**普通仓颉 helper**（@C 薄入口 + 普通 Cangjie 实现），复用 M1 helper 的全套基础设施：trampoline ABI（`rdi=ctx, rsi=&args, rdx=n, ret rax=cell`）、错误转码写槽、窗口登记、自动尾随 `CHECK_ERR`（I3）、GC/异常/重入边界。

由此，M1 §6 议题清单的八项困难中，①③⑤⑦四项被**机制归一**消解（见 §5/§6），剩余项（②④⑥⑧）由显式语义规则覆盖（§6）。**不引入任何新执行机制**——这是本方案"可行"的根本：需要新写的只有 H60 的仓颉实现体与 Marshal 验签逻辑。

**新增概念一览**：

| 概念 | M1 对应 | 增量 |
|---|---|---|
| HostClosure 类型 | 内部闭包值（token 9 / LocalType 12） | token 10 / LocalType 13（句柄型） |
| 验签 | 无（M1 闭包不跨桥，签名是静态知识） | Marshal 运行期签名核对（§4） |
| 错误码 21 | 99 = 实现缺陷 | 21 = 宿主闭包执行期异常（正常程序流，与 99 语义严格区分） |
| CALL_HOST 激活 | M1 汇编期 `ERR_NOT_IMPL` | 0x79 重定义为 `u8 argc` |
| H60 转发器 | helper 白名单 H01–H59 | +H60 `host_call_trampoline` |
| HostObject（v0.3 增篇） | 宿主自定义类一律 19 拒收（M1 §8.2.1） | token 11 / LocalType 14；不透明引用传递（§11） |

## §1 HostClosure 表示

**运行时表示**：句柄表条目 `{tag=10, cb: HostCallback}`；`HostCallback = {fn: 仓颉函数值, sig: SignatureDescriptor}`。

- `fn` 是**宿主仓颉闭包对象本身**（GC 托管）——句柄表条目持强引用，调用期间对象不可能死亡（与 List/Map pin 同一保活模型，M1 §8.1 决策 ④ 的直接复利：**无需任何"函数指针→稳定地址"的运行时 API**）。
- `sig: SignatureDescriptor` = 参数类型序列 + 返回类型（按 §11.7 LocalType 编码）。由 Marshal 验签（§4）一次性产出并缓存于条目——**CALL_HOST 执行期零验签**。
- **LocalType 13 = HostClosure**（句柄型，空安全规则同 §3.2 M1：恒非 0）。可声明为**参数槽与局部槽**，权限与内部闭包值（12）相同：可赋值、可在 `CALL_FUNC` 链内传递（参数槽 13）、链内返回。
- **不可为常量**：常量 kind 不新增 11——闭包不可序列化（M1 §8.4 已冻结），宿主闭包只能经**桥 Marshal（B 路径）**进入，或在字节码世界内经 `CALL_FUNC` 传递。字节码内**没有构造 HostClosure 的指令**（无 `hostclosure_new`）：它的唯一来源是宿主。

**逃逸边界**（与内部闭包值 12 对称，仅方向相反）：

| 通道 | 内部闭包值（12，M1） | HostClosure（13，M2） |
|---|---|---|
| 跨桥实参（call\<T\>） | ✗（Marshal 无行） | **✓（本文核心）** |
| 跨桥返回 | ✗ | **✓（对称）**：解包表 `get` 原样带回仓颉闭包引用——对象本属宿主，零拷贝零转换 |
| 存入容器 | ✗ | ✗（同 M1：窗口重置 → 悬空 ID） |
| CALL_FUNC 链内传递/返回 | ✓ | ✓（参数槽 13 / retType=13） |
| 作常量 | ✗ | ✗ |

> 返回方向一并支持的原因：实现是平凡的（`get` 逆操作），且与实参方向共享全部验签/生命周期机制；只做单向反而造成不对称的认知负担。高阶（闭包的 T/R 又是函数类型）仍禁止，见 §6。

## §2 字节码与格式变更（verMajor 2）

| 项 | M1（verMajor 1，verMinor 7） | M2（verMajor 2，verMinor 0） |
|---|---|---|
| `.fbc` 头 verMajor | 1 | **2**；M1 加载器遇 verMajor 2 → 加载期拒绝（18）；M2 加载器兼容 verMajor 1（按 verMajor 分派校验规则集） |
| LocalType | 0–12 | **+13 = HostClosure、+14 = HostObject**（均句柄型；**15–255** 仍拒绝——12 内部闭包、13 宿主闭包、14 不透明宿主对象均有定义） |
| 类型 token | 1–9 | **+10 = HostClosure、+11 = HostObject**（`IS_TYPE/GUARD_TYPE/H19` 与句柄槽 `tag` 可用） |
| `CALL_HOST`（0x79） | 汇编期 `ERR_NOT_IMPL`（M1 从未产出该 opcode——重定义不破坏任何 M1 产物） | 操作数 **`u8 argc`**（M1 预留的 `u16 fid` 编码废弃——fid 形态属第一档"编译期注册回调"，本文范围外），栈布局 `[h_fn, a1..an]`；`CAT_CALL` |
| 错误码 | 0–20 / -1 / -2 / 99 | **+21 `ERR_HOST_CALLBACK`**：宿主闭包执行期抛出异常且未回译；`cause` 附原始异常描述（与 99 的 cause 通道同构，M1 §8.2.3）；`site` = `CALL_HOST` 指令的字节码偏移（定位到调用点） |
| 19 `ERR_CALL_CONTRACT` | 参数长度/元素类型/返回 T 不符/调用已卸载单元 | **+验签失败**（§4，site=-1） |

**不变项**：ctx 布局（64 B 整数标量）、帧布局（§3.1）、全部 M1 指令语义、fail-fast（I3/I4）、窗口与逃逸机制（§8.1/§9.6）、W^X 与 IBT（§12.3）。

## §3 前端语言面

**类型记法**：参数/局部可声明函数类型 `name: (T1, T2) -> R`——T/R ∈ LocalType 0–8/10–11（9=Regex 与 **12/13 函数类型均不合法**）；**禁高阶**（冻结，沿 M1 §8.6 决策）：T/R 不得为函数类型——高阶链属第三档（§10）。无参形式 `() -> R`。（注意区分：**JIT 函数自身的参数槽**可以是 13——这是本文核心；受禁的是"闭包签名的 T/R 为函数类型"。）

**调用解析**（M1 §8.4 名字解析顺序的扩展）：

```
recursive → user helper（静态 hid，§8.4）→ HostClosure 形参/局部（静态类型驱动）→ 未定义异常
```

HostClosure 分支按**声明类型**静态判定（编译期已知是 13 型 ⇒ 发射 CALL_HOST 而非 CALL_CLOSURE/CALL_FUNC）——无运行期查找。

**边界（沿 M1 形参遮蔽规则）**：HostClosure 形参/局部与已注册 user helper **同名** → **编译错误**（禁止静默择一；M1 T23"形参遮蔽调用 → 拒绝"先例的扩展）；上述解析顺序仅在无名字冲突时生效。

**降低**：`fn(a1, a2)` = 实参表达式从左到右入栈 → `LOADL fn`（句柄压栈底）→ `CALL_HOST 2` + 汇编器自动尾随 `CHECK_ERR`（I3）。与内部闭包调用（`LOADL 0` + `CALL_CLOSURE`）完全平行。

**实参来源封闭**：HostClosure 值只能来自桥 Marshal（宿主传入）或 `CALL_FUNC` 链内传递——字节码内不可构造。因此"闭包从哪来"的答案永远是宿主代码，字节码世界对它是**纯消费者**。

## §4 Marshal 与验签（§8.2.1 的 M2 行）

**Marshal 表新增行**：

| 签名参数类型 | 接受的 `Any` 实际类型 | 转换 | 失败 |
|---|---|---|---|
| `(T1..Tn) -> R`（HostClosure） | 仓颉函数值 | **运行期验签**（下）→ 回调表登记（`pin` 路径 B，tag=10）→ ID | 19 |

**验签流程**（Marshal 时一次性执行，产物缓存）：

1. **函数类型判定**：仓颉函数类型是类型系统一等公民，`is` 对函数类型按 std 语义判定（实现前提 P1，见 §9.1）；不是函数值 → 19。
2. **参数个数**核对（与声明签名逐位一致）→ 不符 → 19。
3. **逐参类型**核对（T1..Tn）→ 不符 → 19。
4. **返回类型**核对（R）→ 不符 → 19。
5. 产出 `SignatureDescriptor` 存入句柄条目；**禁高阶复检**（R 不得为函数类型）→ 违反 → 19。

**解包表新增行（返回方向，对称）**：

| 签名返回类型 | 解包 | T 校验 |
|---|---|---|
| `(T1..Tn) -> R` | `get` → 原样返回仓颉闭包引用 | `T` == 对应函数类型 |

**生命周期**：HostClosure 条目属 **B pin 路径**（M1 §8.1）——调用结束随 try/finally 清理释放（§8.2 M1 既有机制，零新逻辑）；CALL_FUNC 链内传递期间由被调帧窗口存活（同参数槽 12 规则）。**单元卸载（M1 §8.7）无交互**：HostClosure 是 per-call 资产，不挂单元。

## §5 CALL_HOST 执行语义（H60 转发器）

**lowering**：与 `CALL_HELPER` 同款——`call H60` + 自动 `CHECK_ERR`。机器码无任何新模式（I8 自动满足）。

**H60 `host_call_trampoline`**：普通仓颉 helper（@C 薄入口；三引擎共用同一实现 → I7 结构性成立）。执行流程：

```
1. fetch 栈底句柄 → HostCallback{fn, sig}          // tag≠10 → 8（类型不符）
2. 按 sig 逐参 cell → 仓颉值                        // 句柄型 get / 值型原值（解释性 marshal）
3. 调用 fn（普通仓颉调用）
     ├─ 可能触发 GC      → 与 M1 helper 同一边界（§6）
     ├─ 可能抛出仓颉异常 → catch-all → 21 + cause     // fail-fast：写槽返回，CHECK_ERR 短路
     └─ 可能重入 JIT     → 合法，见下
4. 返回值 → cell
     └─ R 为引用型 → 窗口登记新槽（分配型语义；R 编译期已知 ⇒ hwCap 估计含之，§9.6）
     └─ R 为值型   → 原值返回，不登记
```

**与 user helper（§8.4）的关系：并存，按需选择**：

| | user helper | HostClosure + CALL_HOST |
|---|---|---|
| 目标确定时机 | 编译期（注册表静态 hid） | 运行期（每次调用的实参） |
| 验签 | 无（注册时签名即契约） | Marshal 时一次性 |
| 调用开销 | 零间址（静态 trampoline） | fetch + 描述符遍历（§8） |
| 适用 | 目标编译期已知 | 目标按次调用不同（回调/策略注入） |

**重入语义（冻结）**：宿主闭包体内调用 JIT 产物**合法**——走正常 `call` 路径开**新 ctx**（M1 §9.7：ctx 随调用栈分配、各调用窗口 `[hwBase, hwTop)` 互不重叠、句柄表槽追加有同步保护）。嵌套调用是**独立事务**：独立 errCode/site/fnId/窗口，内层 fail-fast 不影响外层错误槽；深度受宿主线程栈限制（同自递归，M1 §8.0）。实现者须知：桥的重入路径 = 既有 `call` 代码本身，无新机制，但**测试必须覆盖**（T31）。

**取消边界**（沿 M1 §8.3）：宿主闭包执行期间不可中断（-2 仅 `LOOP_BACK` 回边产生）；`CALL_HOST` 点不设安全点——取消感知延迟上界 = 闭包剩余执行时长。已在 M1 成文的边界，本文引用不重复论证。

## §6 安全模型（继承 + 增量）

| 机制 | 语义 |
|---|---|
| **deopt** | 含 `CALL_HOST` 的函数 → `FuncEntry.flags.bit0`（被调闭包体静态不可知，黑盒——与 `CALL_CLOSURE`/预定义 helper 同一 §9.15 模式）→ **deopt 源汇编期禁令**；运行期防御性 -1 → 99 不重放。宿主闭包的副作用（若有）绝不会被重放重复执行 |
| **纯度** | 宿主闭包副作用黑盒；"可重复调用结果一致"的前提 = 闭包自身行为确定——**注册者自担**（§8.4 既有原则的延伸：宿主向 JIT 世界提供什么行为，责任在宿主侧） |
| **fail-fast** | 21 写槽即终止本次调用，经 `CHECK_ERR → BAIL` 收敛 epilogue（I3/I4 原样）；宿主闭包异常不穿越机器码（helper 边界"绝不抛出"合同原样适用） |
| **GC** | 转发器是仓颉函数——内部分配可触发 GC、GC 栈扫描穿过 JIT 帧 = **M1 helper 已接受并已文档化的同一边界**（保守扫描 + 窗口强引用保活）；闭包对象由句柄条目持强引用，调用期间恒存活。无新边界，仅需测试覆盖（T32） |
| **W^X / IBT** | H60 是编译期静态布局的机器码入口（单元 code buffer 内），`endbr64` ✓；无运行期代码页修改 ✓ |
| **卸载** | 无交互（§4）；单元资产（含 H60 机器码）按 M1 §8.7 正常回收 |
| **禁高阶** | 双重强制：前端声明处编译期拒绝（§3）+ Marshal 验签复检（§4）；运行期无高阶链 ⇒ 签名描述符深度恒 1 |

**八项困难 × 本文消解方式**（对照 M1 §6 议题清单）：

| # | 困难 | 消解 |
|---|---|---|
| ① 调用通道缺位 | CALL_HOST 激活 + H60 转发器（复用 helper 全套机制） |
| ② 静态性丧失 | 静态性**下沉到类型层**：调用点按声明类型静态发射；运行期只有一次表取值（无需运行期回调注册表——句柄表即回调表） |
| ③ 签名校验/禁高阶 | Marshal 一次性验签 + 缓存；禁高阶双重强制（§4） |
| ④ 输入等价性 | 差分口径改列"转发语义一致"（§7）；纯度责任划归注册者（§8.4 原则） |
| ⑤ 异常语义错位 | 独立错误码 21（业务异常 ≠ 99 实现缺陷）+ cause 通道 |
| ⑥ 重入 | 合法化 + 独立事务语义（§5）；机制零新增（ctx 每调用独立已是 M1 §9.7 现状） |
| ⑦ GC 栈边界 | 归一为 M1 既有 helper 边界（无新边界） |
| ⑧ 序列化 | HostClosure 不入 `.fbc`（不可为常量，§1）——分发世界零交互 |

## §7 三引擎一致性（I7）

- H60 为**共用仓颉实现**；转发序列（取参顺序、逐参转换、错误转码、返回登记）确定且单实现 ⇒ 三引擎行为**结构性一致**（与 M1 helper 的 I7 论证同构）。
- **差分测试口径**：黄金基准由测试用例提供的**确定性宿主闭包**充当（同 M1 T23 对 user helper 的做法）；断言 = 结果/错误码/site 三引擎逐位一致。宿主闭包自身的非确定行为不在 JIT 的证明义务内（注册者自担）。

## §8 性能

- 每次调用成本：句柄 fetch + 描述符遍历逐参转换（解释性）+ 一次仓颉间接调用——估算为 user helper 调用的 1.5–3×（转换参数越多越接近上限）。
- **M2.1 优化展望**（不在本文）：验签后按 `SignatureDescriptor` 缓存 **per-signature 特化 trampoline**（消除描述符遍历）；热路径单态化。正确性优先，特化不得改变可观察语义（差分同 T30–T34）。
- `hwCap` 估计：CALL_HOST 返回引用型时登记 1 槽（R 编译期已知）——汇编器计入，§9.6 扩容兜底照旧。

## §9 实现前提与退化路径

### §9.1 前提 P1：仓颉函数类型的运行期判定

验签第 1 步依赖仓颉 `is` 对函数类型的判定（`any is (Int64) -> Bool`）。仓颉函数类型是类型系统一等公民，预期可用；**若实现环境不可用**，启用退化路径：

- **退化 API**：`call` 增加强类型泛型变体 `callWith<Fn>(args…)`——`Fn` 为具体仓颉函数类型，编译期即持有完整签名 ⇒ 验签退化为编译期，Marshal 零运行期判定。
- 两通道可并存：`Any` 弱类型（依赖 P1）/ 泛型强类型（无 P1 依赖）。

### §9.2 与 M1 加载器的兼容矩阵

| 产物 \ 加载器 | M1（verMajor 1） | M2（verMajor 2） |
|---|---|---|
| verMajor 1 产物 | ✓ 全语义 | ✓（按 M1 规则集校验；CALL_HOST 未启用 ⇒ 不可能出现） |
| verMajor 2 产物 | ✗ 加载期拒绝（18） | ✓ |

## §11 不透明宿主对象通道（HostObject，v0.3 增篇）

**需求与定位**：宿主仓颉 **class** 实例以**不透明载荷**方式进出字节码世界——**仅在仓颉侧声明**、仅含**公共实例成员变量**、**仅用来传递数据**：字节码对它的全部能力 = 持有、转发、返回；**零字段访问、零构造、零方法调用、零比较，从不解引用**。典型用途：宿主把 DTO/上下文对象交给编译函数转发给宿主注册函数（§8.4），或经返回值带回。

**为什么选 class（设计理由）**：① **引用语义** ⇒ 传递零拷贝 O(1)、`Any` 通道免装箱（对照方案：struct 需 copy-on-mutate 应对值语义、每次字段写占 1 槽并撞"窗口只增不减"的 16 压力，且在不透明前提下同样无收益）；② 字节码零解引用 ⇒ 无值语义映射、无成员逃逸规则、无 §9.15 耦合；③ 未来透明化（字段访问）时，class 引用语义使"原地变更"语义自然（变更型 helper/§9.15 模式现成），无值语义障碍——本通道是可持续升级的底座。

**类型与表示**：

- token 11 = HostObject；LocalType 14 = HostObject（句柄型，恒非空，§3.2 空安全规则同）。
- 条目 `{tag=11, obj: 宿主类实例引用}`——与 List/Map 同款"引用保活"模型；pin 语义照 §8.1（同表内同对象复用同 ID——class 有对象身份，本语义自然成立）。
- **宿主纪律（规范要求；桥不机械校验，沿 §8.4"准入责任自担"原则）**：通道所用类须为**纯数据类**（仅公共实例成员变量）——① 未来透明化路径依赖该约定；② 传递共享语义可预测。

**能力面（冻结）**：

| 能力 | 支持 | 说明 |
|---|---|---|
| 推断局部（`let o = hostFn()`，LocalType 14） | ✓ | 类型从预定义调用结果推断（沿 `let fn = {…}` 推断先例） |
| 预定义函数（§8.4）参数 / 返回 | ✓ | 签名编码扩展：14 型槽的具体类 = 注册时提供的 Cangjie 类型（静态知识外置，List 元素类型同款模式） |
| 作为实参转发给另一预定义函数 | ✓ | 本通道核心用途 |
| JIT 函数返回值（retType=14） | ✓ | `call<User>` 交付：解包表 get → 宿主类实例引用；`T` 校验由 call\<T\> 单态化适配器承担（T = 具体类） |
| 字段访问 / 构造 / 方法调用 / `==` | ✗ | 本通道定位"数据胶囊"（永久性约束） |
| 常量化 | ✗ | 宿主类型不可序列化（同 HostClosure，§1） |
| `call<T>` 实参方向（源入口形参） | ✗（本增量） | 需宿主类型注册表；列入 §12 |
| CALL_FUNC 跨函数形参（参数槽 14） | ✗（本增量） | 需源语言 opaque 形参语法；列入 §12 |

**Marshal 与边界校验**：

- 解包表（§8.2.2）新增行：`retType=14 → get → 宿主类实例引用`（引用原样返回，零拷贝）。
- **边界型别校验（本通道唯一新增校验点）**：预定义调用转发前，桥核对 `fetch(id).obj is <注册签名中的声明类>` → 不符 → 19；沿用 §4 验签的"静态知识外置 + 边界一次性核对"模式。
- **null 策略**：pin/交付遇 null → 19（与句柄恒非空不变式一致，§3.2）。
- **实施注记**：M1 §8.2.1"不接受的对象类型（无类型 token，如宿主自定义类）→ 19"行在 M2 实施时更新为——**经本通道接受的宿主类实例例外（token 11）**；其余对象仍 19。

**生命周期与安全（全部继承既有机制，零增量）**：

- 句柄路径：B pin / C 窗口（预定义结果 wrap 为分配型语义）/ D 逃逸——try/finally 清理（§8.2）、保活矩阵与逃逸规则（§8.1）照旧。
- deopt：字节码零解引用、零副作用 ⇒ 重放安全；不触发 flags.bit0（除既有 §6 CALL_HOST 规则）。
- GC：条目强引用保活 ✓；并发：宿主在调用期间不得并发修改被传递的共享对象（§8.3 只读契约精神；字节码侧零风险）。
- 卸载（§8.7）：句柄为 per-call/窗口资产、无常量——无交互。

**性能**：传递 O(1)（引用拷贝）、`Any` 通道零装箱、无任何载荷拷贝；JIT 执行层与既有句柄型零差异。

**测试**：T34（§10）。

## §12 开放问题与后档展望

1. **P1 落地确认**：仓颉 std 对函数类型 `is` 判定的实际支持范围（含捕获环境下的相等语义）——实现前需以最小用例验证；不可用则走 §9.1 退化 API。
2. **第三档（不在本文）**：高阶（HostClosure 的 T/R 为函数类型——签名描述符需支持嵌套 + 深度上限）、异常对象回译（业务异常结构化传递给字节码世界——需异常值入句柄表 + 类型化 catch 语义）。
3. **M2 其余议题**：容器构造（`MAKE_LIST/MAKE_MAP`）、`HW_OPEN/HW_CLOSE` 批量分配、跨进程回调注册协议——各立专项规格。
4. **性能特化**（§8）：per-signature trampoline 缓存的失效条件（与句柄表 gen/卸载的交互）需要单独设计。
5. **HostObject 后续增量**（§11）：① **宿主类型注册表 + 源语言 opaque 形参语法** → 解锁 `call<T>` 实参方向与 CALL_FUNC 跨函数转发（参数槽 14）；② **透明化（字段访问）**：class 引用语义使原地变更语义自然（变更型 helper/§9.15 模式现成），无 struct 方案的值拷贝障碍——§11 即其底座。
