# fleet 分布式键值同步系统 — 架构设计文档

## 1. 系统架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                        fleet 集群节点                            │
│  ┌──────────────────────────────────────────────┐               │
│  │  fountain::f_app（fboot 启动框架）             │               │
│  │  └─ SyncCommand（SubCommand → "sync"）         │               │

│  ├──────────────────────────────────────────────┤               │
│  │  fountain::f_net.server（网络服务端）           │               │

│  ├──────────────────────────────────────────────┤               │
│  │  fountain::fleet.client（客户端 API）           │               │
│  │  └─ f_net.client → 向其他节点发送请求           │              │
│  ├──────────────────────────────────────────────┤               │
│  │  fountain::f_store.Store（LSM-Tree 持久化）     │              │
│  └──────────────────────────────────────────────┘               │

                        │
                        ▼
┌─────────────────────────────────────────────────────────────────┐
│                   通信协议（f_protocol + f_net）                  │
│  REGISTER / DEREGISTER / PUBLISH / ACK / SUBSCRIBE / PING     │

│  │ Message Header  │    │  Message Body   │                    │
│  │ [Command Byte]  │    │  DataFields     │                    │
│  │ [MessageID]     │    │  (f_data 编码)   │                    │
│  └─────────────────┘    └─────────────────┘                    │
│                                                               │
│  ACK 命令双向分发：                                              │
│  • KeyData → GET 处理                                           │
│  • PatternData → 前缀扫描 / Glob 匹配                            │
└─────────────────────────────────────────────────────────────────┘
```

### 1.1 分层架构

| 层 | 模块 | 职责 |
|----|------|------|
| 应用层 | `f_app` / `SyncCommand` | 应用启动、命令行参数解析 |
| 服务层 | `SyncServer` / `SyncHandler` | 请求路由、业务逻辑 |
| 网络层 | `f_net` / `f_protocol` | TCP 网络通信、消息序列化 |
| 数据层 | `f_store` | LSM-Tree 键值存储 |
| 路由层 | `HashRing` | 一致性哈希路由 |

### 1.2 关键设计原则

1. **去中心化**：所有节点平等，无单点故障
2. **写优化**：Owner 节点写入后异步同步，写操作延时 = 本地 f_store 写入延时
3. **版本仲裁**：版本号冲突时取最大值，避免旧数据覆盖
4. **读故障转移**：读取时 Owner 不可达自动切换节点

## 2. 一致性哈希环（HashRing）

### 2.1 设计

```cj
public class HashRing {
    // 虚拟节点 → 物理节点映射
    // key = hash(token), value = physical node index
    private let ring: TreeMap<UInt128, Int64>
    // 物理节点列表
    private let nodes: ArrayList<HostAndPort>
    // 每个物理节点的虚拟节点数
    private let virtualNodes: Int64 = 32
}
```

### 2.2 算法

```
构建 HashRing(keyedHashFunc, physicalNodes, virtualNodeCount):
    for (nodeIndex, physicalNode) in physicalNodes:
        for vnode in 0..virtualNodeCount:
            token = "${physicalNode.host}:${physicalNode.port}:${vnode}"
            hash = murmurHash(token)
            ring[hash] = nodeIndex

查找 Owner 节点(key):
    hash = murmurHash(key)
    entry = ring.findGreaterOrEqual(hash)  // 顺时针查找
    if (entry == None):
        entry = ring.first()  // 回到环起点
    return physicalNodes[entry.value]
```

### 2.3 故障转移

```
查找可用节点(key, failedNodeIndex):
    hash = murmurHash(key)
    // 从 hash 开始顺时针查找，跳过 failedNodeIndex
    entry = ring.findGreaterOrEqual(hash)
    visited = Set<Int64>()
    while (entry != None && visited.size < physicalNodes.size):
        if (entry.value != failedNodeIndex && !visited.contains(entry.value)):
            return physicalNodes[entry.value]
        visited.add(entry.value)
        entry = ring.findGreater(entry.key)  // 继续顺时针
        if (entry == None):
            entry = ring.first()
    return None  // 所有节点都不可用
```

## 3. 消息体数据格式（SyncDataFormat）

每个操作定义独立的 DataFields 结构体，使用 f_codec 编码/解码。

#### REGISTER 请求：`SyncData`

```cj
public struct SyncData <: DataFields<SyncData> {
    let key: String
    let version: Int64
    let value: Array<Byte>
}
```

编码顺序：
```
f_codec: [String key] [Int64 version] [Array<Byte> value]
```

#### GET 响应：`ValueData`

```cj
public struct ValueData <: DataFields<ValueData> {
    let value: ?Array<Byte>  // None 表示不存在或已删除
}
```

#### Watch 通知：`WatchNotifyData`

```cj
public struct WatchNotifyData <: DataFields<WatchNotifyData> {
    let key: String

### 3.2 编解码方式

所有 DataFields 使用 `DefaultCodec` 编码/解码：

```cj
// 编码
let codec = DefaultCodec()
let encoded = codec.encode(data).finish()

// 解码
let decoded = DefaultCodec().decode<SyncData>(ByteBuffer(encoded.toBytes()))

## 4. 服务端设计（SyncServer / SyncHandler）

### 4.1 Server 类型参数

```cj
// f_net.Server 类型参数映射：
// DE = Message         — 解码后的请求消息
// EN = EncodedMessage  — 编码后的消息
// M  = Message         — Protocol<EncodedMessage, Message>
// T  = <sync DataFields impl>  — 消息体数据结构
// ID = MessageID       — 消息 ID
```

### 4.2 线程模型

```
┌─────────────────────────┐
│   f_net.Server.start()  │  — 主线程，accept 连接
│   │                     │
│   ▼                     │
│   Connection Handler    │  — 每个连接一个线程
│   ├─ read → decode      │
│   ├─ dispatch → handle  │
│   └─ encode → write     │
│                         │
│   SyncHandler.handle()  │  — 请求处理（在连接线程中执行）
│   ├─ match command      │
│   ├─ execute operation  │
│   └─ return response    │
└─────────────────────────┘
```

### 4.3 请求处理流程

```
Client → f_net → SyncHandler.handle(request: Message): Message

handle(request):
    switch request.command:
        case Command.REGISTER:
            1. 检查仲裁
            2. 检查自己是 KEY 的 Owner
            3. 从 request 解码 SyncData
            4. version = sequence.incrFetch()
            5. f_store.add(key.getBytes(), value)
            6. f_store.add(key + "_version", version)
            7. 异步 PUBLISH 到其他节点
            8. 返回 RESP(success)

        case Command.DEREGISTER:
            1. 检查仲裁
            2. 检查自己是 KEY 的 Owner
            3. version = sequence.incrFetch()
            4. f_store.remove(key.getBytes())
            5. f_store.add(key + "_version", version)
            6. 异步 PUBLISH 到其他节点
            7. 返回 RESP(success)

        case Command.PUBLISH:
            1. 解码 SyncData
            2. 检查接收版本 > 本地版本
            3. 更新本地存储
            4. 检查并触发 Watch
            5. 返回 RESP(success)

        case Command.SUBSCRIBE:
            1. 解码 WatchData（含 key 和 timeout）
            2. 注册到 WatchManager → WatchFuture
            3. 阻塞等待：
               - timeout=0: future.get() — 永久等待变更
               - timeout>0: future.tryGet(timeout) — 超时返回 None
            4. 返回 RESP(ValueData: ?Array<Byte>)

        case Command.UNSUBSCRIBE:
            1. 从 WatchManager 移除
            2. 返回 RESP(success)

        case Command.ACK:
            1. 尝试解码 KeyData → GET 处理
            2. 否则尝试解码 PatternData → 扫描/glob 处理
               - 含 * ? { 字符 → 走 glob 路径
               - 纯前缀 → 走 store.prefix() 路径
            3. 结果编码为 ValueData(encodeToBytes) 返回

        case Command.PING:
            1. 返回 RESP(empty)
```

### 4.4 节点间同步（PUBLISH）

```
onDataChanged(key, version, value):
    // 异步向所有其他节点发送 PUBLISH
    for each peer in otherNodes:
        spawn {
            try {
                client.transfer(id, publishMessage(key, version, value))
                    .get(timeout)
            } catch (Exception e) {
                // 记录失败，重试最多 3 次
                retryOrFailLog(peer, key, version, value)
            }
        }
```

### 4.5 Glob 匹配扫描

`handleRead` 收到 `ACK(PatternData)` 时，根据 pattern 是否包含 `*`、`?`、`{` 分两条路径：

#### 纯前缀扫描（无 glob 字符）

```cj
let it = store.prefix(pattern.unsafeBytes())  // LSM-Tree 定位到 prefix
for ((k, v) in it) {
    result.add(String.fromUtf8(k), v)          // 直接收集 key+value
}
```

LSM-Tree 的 `prefix()` 利用跳表/树结构做范围迭代，复杂度 O(log n + m)。

#### Glob 模式匹配（含 * ? {）

```cj
let pp = PathPattern()
pp.compile(pattern)              // 编译 glob 模式到 Trie
let all = store.prefix([])        // 空 prefix = 全量扫描
for ((k, v) in all) {
    let keyStr = String.fromUtf8(k)
    if (pp.matches(keyStr)) {     // PathPattern Trie 匹配
        result.add(keyStr, v)     // 匹配的 key+value 加入结果
    }
}
```

`PathPattern` 采用 Trie 树结构，支持以下通配符：

| 通配符 | 含义 | 示例 |
|--------|------|------|
| `*` | 单级路径内任意字符（≥0） | `/app/*/host` → `/app/db/host` |
| `**` | 跨级路径匹配（≥0 级） | `/app/**/*.yaml` → `/app/a/b/c/host.yaml` |
| `?` | 单级路径内单个字符（=1） | `/app/?onfig` → `/app/config` |
| `{name}` | 占位符变量 | `/user/{id}/profile` |
| `{name:regex}` | 带正则约束的占位符 | `/log/{date:\\d{8}}` |
| `{#regex}` | 纯正则匹配 | `/{#regex:\\d+}` |
| `{*var}` | 贪婪变量 | `/{*path}/file` |

**匹配优先级**：精确 > `?`/`*` > `{name}` > `**`

**`**` 零段匹配修复**：
```
遇到 ** 节点时，先尝试 ** 的子节点在 当前段 匹配（** 匹配零段），
失败后再消耗段进入 ** 继续匹配（** 匹配 1+ 段）。
解决 /**/*.yaml 中 /app/.yaml（** 需匹配零段）的匹配问题。
```

**`matches()` 默认保留扩展名**：
`matches(path)` 默认参数 `withExtName` 从 `false` 改为 `true`，避免 `trimExt`
剥离路径中的 `.yaml` 等扩展名。路由模式中扩展名通常无意义，但 glob 匹配时
`.yaml` 是匹配目标的一部分而不可剥离。

**正则转义修正**：
非原声模式的 `RegexPathNode` 生成正则时必须转义 `.` `\` `^` `$` `|` `+` `(` `)` `[` `]` `{` `}` 等元字符，
否则 `*.yaml` 生成 `^(.*.yaml)$` 中 `.` 被解释为正则通配符而非字面量点。
修复后生成 `^(.*\.yaml)$`。

#### 结果编码：ScanResult blob

```cj
// encodeToBytes：将所有条目逐对编码到单 Array<Byte> blob
for (i in 0..entries.size) {
    DefaultCodec().encode(keyBytes).finish()  // key 编码
    DefaultCodec().encode(value).finish()     // value 编码
}
// 通过 ValueData 传输（Array<Byte> 可被 @DataAssist 正确处理）
Message(Command.RESP(0), id, ValueData(blob).toData())

// decodeFromBytes：从 blob 解码重建 ScanResult
let result = ScanResult()
while (true) {
    decode<Array<Byte>>(blob) → keyBytes  // key 解码
    decode<Array<Byte>>(blob) → value     // value 解码
    result.add(String.fromUtf8(keyBytes), value)
}
```

注：`ScanResult` 原始使用 `@DataAssist` 的 `ArrayList<Array<Byte>>` 字段无法正确 roundtrip，
改用 `DefaultCodec` 手动编解码到单 `Array<Byte>` blob，绕过该限制。

## 5. 客户端设计（SyncClient）

### 5.1 架构

```
┌──────────────────────────────────┐
│          SyncClient              │
│  ┌────────────────────────────┐  │
│  │     单例（Singleton）       │  │  — 每个进程一个实例
│  └────────────────────────────┘  │
│  ┌────────────────────────────┐  │
│  │  f_net.Client（单连接）     │  │  — 连接 fleet_hosts 首节点
│  └────────────────────────────┘  │
│  ┌────────────────────────────┐  │
│  │  MessageID → MessageFuture  │  │  — 响应分发 (ConcurrentHashMap)
│  └────────────────────────────┘  │
└──────────────────────────────────┘
```

### 5.2 连接管理

- 单例模式：`SyncClient.getInstance()` 返回全局唯一实例
- 单连接：仅连接 `fleet_hosts` 列表的第一个节点（非全连接池）
- `f_net.Client` 的 `MessageID → MessageFuture` 机制确保多线程并发请求
  的响应正确分发
- 请求超时：默认 10 秒，可通过 `getInstance(requestTimeout!)` 指定

### 5.3 操作流程

#### GET(key) 流程
```
1. 构造 Message(ACK, KeyData(key).toData())
2. 通过 f_net.Client.transfer(id, req, timeout) 发送
3. MessageID → MessageFuture 匹配响应
4. 从 RESP 消息体中解码 ValueData
5. 返回 value（None 表示不存在）
```

#### ADD(key, value) 流程
```
1. SyncData.encodeValue(key, version, value) 编码值
2. 构造 Message(REGISTER, SyncData(key, 0, encoded).toData())
3. 通过 client.transfer() 发送
4. 等待 RESP 响应（超时则抛出 WriteFailedException）
```

#### DELETE(key) 流程
```
1. 构造 Message(DEREGISTER, KeyData(key).toData())
2. 通过 client.transfer() 发送
3. 等待 RESP 响应（超时则抛出异常）
```

#### PREFIX(pattern) 流程
```
1. 构造 Message(ACK, PatternData(pattern).toData())
2. 服务端判断 pattern 不含 glob 字符 → 走 store.prefix(prefix) 路径
3. 解码 RESP 中的 ValueData blob
4. ScanResult.decodeFromBytes(blob) → ScanResult
```

#### GLOB(pattern) 流程
```
1. 构造 Message(ACK, PatternData(pattern).toData())  — 与 prefix 相同
2. 服务端判断 pattern 含 *?{ 字符 → 走 PathPattern + 全量扫描路径
3. 解码 RESP 中的 ValueData blob
4. ScanResult.decodeFromBytes(blob) → ScanResult

#### WATCH(key, timeout) 流程
```
1. 向 Owner 发送 Message(SUBSCRIBE, WatchData(key, timeout))
2. Owner 端在 handleSubscribe 中：
   - registerExact(key, timeout) → 返回 WatchFuture
   - 阻塞等待 future.get()（永久）或 future.tryGet(timeout)（超时模式）
3. 当 KEY 变更时（REGISTER/PUBLISH/DEREGISTER），watchManager.notify()
   会向对应的 WatchFuture 发送数据
4. future 被 set 后 handleSubscribe 返回 RESP(ValueData)
5. 客户端解码 RESP 获取变更值
6. 超时后返回 None

客户端是阻塞的：client.transfer(id, req, requestTimeout)
→ f_net 的 MessageID → MessageFuture 匹配机制确保响应正确分发。
```

## 6. Watch 管理（WatchManager）

### 6.1 核心设计：WatchFuture（自实现 Promise）

使用 `Mutex` + `Condition` 自实现 Promise 模式，替代 `f_net.MessageFuture`（其 `set()` 为 internal）。

```cj
public class WatchFuture {
    private let mutex = Mutex()
    private let cond = Condition()
    private var done = false
    private var data: ?Array<Byte> = None

    /** 阻塞等待直到被 set（无限等待） */
    public func get(): ?Array<Byte> {
        synchronized(mutex) {
            while (!done) { cond.wait(mutex) }
        }
        data
    }

    /** 带超时的等待 */
    public func tryGet(timeout: Duration): ?Array<Byte> {
        let deadline = DateTime.now() + timeout
        synchronized(mutex) {
            while (!done) {
                let remaining = deadline - DateTime.now()
                if (remaining <= Duration.Zero) { return None }
                cond.wait(mutex, remaining)
            }
        }
        data
    }

    /** 通知等待者 */
    public func set(data: Array<Byte>): Unit {
        synchronized(mutex) {
            done = true
            this.data = data
            cond.notifyAll()
        }
    }
}
```

### 6.2 注册表结构

```cj
public class WatchManager {
    // 精确匹配: key → Watcher 列表
    private let exactMap: HashMap<String, ArrayList<WatchEntry>>
    // 前缀匹配: prefix → Watcher 列表
    private let prefixMap: HashMap<String, ArrayList<WatchEntry>>
    // 通配符匹配: glob → Watcher 列表
    private let globMap: HashMap<String, ArrayList<WatchEntry>>
}
```

### 6.3 WatchEntry

```cj
private struct WatchEntry {
    let future: WatchFuture       // 通知通道（Promise）
    let expiry: ?DateTime         // 过期时间（None=永不超时）
}
```

### 6.4 服务端订阅处理（handleSubscribe）

```
SUBSCRIBE(key, timeout):
    1. 解析 WatchData.key
    2. 判断 key 类型：
       - 含 * 或 ? → registerGlob(key)  // 通配符注册
       - 含 * 模式 → registerPrefix(key) // 前缀注册
       - 否则 → registerExact(key)       // 精确注册
    3. 返回 WatchFuture
    4. 阻塞等待：
       - timeout=0: 永久阻塞直到被 notify 触发
       - timeout>0: tryGet(timeout)，超时返回 RESP(ValueData(None))
```

### 6.5 notify 流程

当 REGISTER/PUBLISH/DEREGISTER 操作导致 key 变更时，handler 调用
`watchManager.notify(key, value)`，遍历三张注册表：

```
notify(changedKey, newValue):
    1. 精确匹配：exactMap[changedKey] 存在 → set 所有 Watcher
    2. 前缀匹配：遍历 prefixMap，key.startsWith(prefix) → set
    3. 通配符匹配：遍历 globMap，keyMatchesGlob(pattern, changedKey) → set
```

`keyMatchesGlob` 的 `*` 通配符实现：
```cj
private static func keyMatchesGlob(key: String, glob: String): Bool {
    if (glob == '*') { return true }
    if (!glob.contains('*')) { return glob == key }
    let parts = glob.split('*')
    var pos = 0i64
    for (part in parts) {
        if (let Some(idx) <- key.indexOf(part, pos)) { pos = idx + part.size }
        else { return false }
    }
    true
}
```

### 6.6 过期清理

后台线程每 1 秒扫描一次注册表，移除 `expiry < now()` 的 Watcher。被清理的
Watcher 对应的 WatchFuture 不会被 set，等待线程将因超时而返回 None。

## 7. 节点管理（NodeManager）

### 7.1 节点状态

```cj
public class NodeManager {
    private let nodes: ArrayList<HostAndPort>     // 所有节点
    private let alive: AtomicInteger              // 活跃节点计数
    private let localIndex: Int64                 // 本地节点索引
    private let others: ArrayList<HostAndPort>    // 其他节点

```

### 7.2 健康检查

- 每隔 5 秒向所有其他节点发送 PING
- 成功响应 → 标记为活跃
- 连续 3 次失败 → 标记为不可用
- 节点恢复后重新加入 ring

### 7.3 仲裁检查

```cj
public func canServeWrites(): Bool {
    alive.get() > nodes.size / 2
}
```

## 8. 性能优化策略

| 优化点 | 策略 | 预期收益 |
|--------|------|----------|
| 消息体编解码 | 使用 f_codec 顺序编码，减少内存分配 | 降低序列化开销 |
| 连接复用 | f_net 连接池，避免重复建连 | 减少握手开销 |
| 异步同步 | 写入本地后异步 PUBLISH 到其他节点 | 降低写入延迟 |
| Watch 通知 | 使用 Channel 模式，避免轮询 | 减少 CPU 空转 |
| 版本号本地存储 | f_store 额外的 version key | 避免全量扫描 |

## 9. 错误处理与恢复

| 场景 | 处理方式 |
|------|----------|
| 节点启动时配置缺失 | 抛出异常，终止启动 |
| 端口被占用 | 抛出异常，终止启动 |
| 数据目录不可写 | 抛出异常，终止启动 |
| 仲裁不足写失败 | 返回 RESP 错误码 |
| 读取节点不可达 | 故障转移到下一节点 |
| 同步 PUBLISH 失败 | 重试 3 次，最终记录日志 |
| 数据版本冲突 | 取较大版本号 |
