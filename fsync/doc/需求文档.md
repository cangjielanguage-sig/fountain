# fsync 分布式键值同步系统 — 需求文档

## 1. 概述

fsync 是一个去中心化的键值同步系统，各节点绝对平等，通过一致性哈希分片存储数据，通过互相同步实现数据最终一致性。

---

## 2. 核心概念

### 2.1 一致性哈希与数据分片

- 使用 `fountain::f_util.murmurHash(String)` 计算 KEY 的哈希值
- 所有节点构成一致性哈希环（**ring**），每个节点在 ring 上占据多个虚拟节点（virtual nodes）以实现负载均衡
- 默认每个物理节点映射 32 个虚拟节点
- KEY 归属：哈希值在 ring 上顺时针第一个虚拟节点所属的物理节点
- 只有 KEY 归属节点可写（add/delete），其他节点对该 KEY 只读

### 2.2 节点角色

所有节点绝对平等，没有主节点。但针对每个 KEY：
- **Owner 节点**：一致性哈希决定该 KEY 的写入者
- **Replica 节点**：集群中除 Owner 外的所有其他节点，只读该 KEY

### 2.3 数据版本

- 每条键值对关联一个单调递增的版本号（`Int64`）
- 版本号由 Owner 节点的 `sequence: AtomicInt64` 生成
- 写入时版本号递增，同步时携带版本号
- 接收同步时，仅当收到的版本号 > 本地版本号才更新（防止旧数据覆盖新数据）

### 2.4 仲裁与可用性

- 活跃节点数超过总节点数的一半，集群才能接受写操作
- 读操作不要求仲裁，任何节点都可提供读服务
- 写操作只需 Owner 节点写入本地存储即可返回，同步异步进行

## 4. 配置定义

### 4.1 配置键

| 配置键 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `sync_hosts` | `String` | 无（必填） | 集群节点列表，逗号分隔，格式 `ip1:port1,ip2:port2` |
| `sync_dataPath` | `String` | `/tmp/fsync` | 数据存储目录 |

### 4.2 SyncConfig 定义

```cj
package fountain::fsync.config

import fountain::f_config.*

public class SyncConfig {
    public static const sync = 'sync'
    public static const hosts = sync + '_hosts'
    public static const dataPath = sync + '_dataPath'

    public static func getHosts(): Array<HostAndPort> {
        let hosts = Config.getString(hosts).split(',')
        Array<HostAndPort>(hosts.size) { i => HostAndPort(hosts[i]) }
    }

    public static func getDataPath(): String {
        Config.getString(dataPath) ?? '/tmp/fsync'
    }
}

public struct HostAndPort {
    public let host: String
    public let port: UInt16

    public init(host: String) {
        let idx = host.indexOf(':') ?? -1
        this.host = host[0..idx]
        this.port = idx == -1 ? 1203 : UInt16.parse(host[idx+1..])
    }
}
```

## 5. 通信协议

### 5.1 基础协议层（f_protocol）

使用 `fountain::f_protocol` 定义的消息格式：
- **消息头**：Command 字节（标识消息类型）
- **消息ID**：`MessageID`（PID + TID + 时间戳）
- **消息体**：`Data`（具体业务数据，使用 `f_codec` 编码）

### 5.2 命令映射

| f_protocol Command | 方向 | 用途 |
|--------------------|------|------|
| `REGISTER` | Client → Server | 客户端写入键值对 |
| `DEREGISTER` | Client → Server | 客户端删除键值对 |
| `PUBLISH` | Server → Server | 节点间数据同步 |
| `RESP` | Server → Client | 操作响应 |
| `PING` | 双向 | 健康检查（Watch 超时心跳） |
| `SUBSCRIBE` | Client → Server | Watch 注册 |
| `UNSUBSCRIBE` | Client → Server | Watch 取消 |

### 5.3 消息体编码格式（f_codec 顺序编码）

#### REGISTER 请求体
| 字段 | 类型 | 说明 |
|------|------|------|
| key | `String` | 键，UNIX 风格路径 |
| version | `Int64` | 数据版本号 |
| value | `Array<Byte>` | 值 |

#### DEREGISTER 请求体
| 字段 | 类型 | 说明 |
|------|------|------|
| key | `String` | 键 |

#### PUBLISH 同步体
| 字段 | 类型 | 说明 |
|------|------|------|
| key | `String` | 键 |
| version | `Int64` | 数据版本号 |
| value | `Array<Byte>` | 值 |

#### GET 请求体
| 字段 | 类型 | 说明 |
|------|------|------|
| key | `String` | 键 |

#### GET 响应体
| 字段 | 类型 | 说明 |
|------|------|------|
| value | `Array<Byte>` | 值；删除/不存在时编码为 `None` |

#### PREFIX / GLOB 请求体
| 字段 | 类型 | 说明 |
|------|------|------|
| pattern | `String` | 前缀或通配符模式 |

#### WATCH / UNWATCH 请求体
| 字段 | 类型 | 说明 |
|------|------|------|
| key | `String` | 被监听的键 |

#### WATCH 通知体
| 字段 | 类型 | 说明 |
|------|------|------|
| key | `String` | 发生变更的键 |
| value | `Array<Byte>` | 变更后的值；删除时为 `None` |

### 5.4 WatchedValue 枚举

```cj
public enum WatchedValue {
    | Value(Array<Byte>)
    | Deleted
}
```

## 6. 功能需求

### 6.1 服务端（fountain::fsync.server）

#### 6.1.1 启动与注册
- 实现 `fountain::f_app.SubCommand` 接口
- 子命令名 `"sync"`
- 在 `static init()` 中注册到 `SubCommandMediator`
- 启动命令：`fboot sync --sync_hosts=ip1:port,ip2:port --sync_dataPath=/path/to/data`

#### 6.1.2 仲裁
- 启动时检查集群活跃节点数
- 处理请求前检查当前活跃节点数 > 总数/2
- 不满足仲裁时返回错误，拒绝写入

#### 6.1.3 数据持久化
- 使用 `fountain::f_store.Store` 存储键值数据
- KEY 使用 `Array<Byte>` 格式（String.toUtf8() 转换）
- VALUE 使用 `Array<Byte>` 格式
- 额外存储 `{key}_version` 用于版本追踪

#### 6.1.4 对外网络服务（开放端口）

| 操作 | 描述 |
|------|------|
| `add(key, value)` | 添加键值对（仅 Owner 节点可写） |
| `remove(key)` | 删除键值对（仅 Owner 节点可写） |
| `get(key)` | 获取键对应的值（所有节点可读） |
| `prefix(prefix)` | KEY 前缀遍历 |
| `glob(glob)` | KEY 通配符遍历 |
| `watch(key, timeout)` | 监听指定 KEY 的变化 |
| `unwatch(key)` | 取消监听 |
| `watchPrefix(prefix, timeout)` | 监听所有符合前缀的 KEY |
| `unwatchPrefix(prefix)` | 取消前缀监听 |
| `watchGlob(glob, timeout)` | 监听所有符合通配符的 KEY |
| `unwatchGlob(glob)` | 取消通配符监听 |

#### 6.1.5 监听机制（Watch）

- 服务端维护 **Watch 注册表**：`HashMap<String, ArrayList<WatchEntry>>`
- 每个 `WatchEntry` 包含：客户端连接 ID、超时时间、模式类型（exact/prefix/glob）
- 数据变更时（add/remove），扫描注册表匹配的条目
- 向匹配的客户端发送 `RESP` 消息，体为变更后的值
- 超时后自动从注册表移除
- `timeout: Duration.Zero` 表示永不超时

### 6.2 客户端（fountain::fsync.client）

#### 6.2.1 一致性哈希路由
- 使用 `fountain::f_util.murmurHash(String)` 计算 KEY 的哈希
- 在 HashRing 上找到 Owner 节点

#### 6.2.2 读故障转移
- 读取时如果 Owner 节点不可达，按 ring 顺时针找下一个可用节点
- 继续尝试直到遍历所有节点
- 所有节点均不可达时返回错误

#### 6.2.3 写故障处理
- 写入时如果 Owner 节点不可达，立即失败
- 不向其他节点转发写操作

#### 6.2.4 公共 API

```cj
public class SyncClient {
    public func get(key: String): ?Array<Byte>
    public func add(key: String, value: Array<Byte>): Unit
    public func delete(key: String): Unit
    public func prefix(prefix: String): Iterator<(String, Array<Byte>)>
    public func glob(glob: String): Iterator<(String, Array<Byte>)>
    public func watch(key: String, timeout!: Duration = Duration.Zero): ?Array<Byte>
    public func unwatch(key: String): Unit
    public func watchPrefix(prefix: String, timeout!: Duration = Duration.Zero): Iterator<(String, WatchedValue)>
    public func unwatchPrefix(prefix: String): Unit
    public func watchGlob(glob: String, timeout!: Duration = Duration.Zero): Iterator<(String, WatchedValue)>
    public func unwatchGlob(glob: String): Unit
}
```

### 6.3 节点间数据同步

- Owner 节点收到 `add`/`delete` 后，将变更 `PUBLISH` 给所有其他节点
- 同步异步进行：Owner 先写入本地存储，再发起同步
- 接收节点检查版本号，仅当接收版本 > 本地版本时更新
- 新节点加入时，从现有节点同步全部数据（全量同步）
- 同步失败自动重试，最多 3 次

## 7. 性能目标

- 以极致性能为第一目标
- 使用 `f_net` + `f_protocol` 实现通讯协议，避免额外封装开销
- 使用 `f_codec` 编解码，顺序编码/解码
- 数据存储使用 `f_store`（LSM-Tree，写优化）

## 8. 边界与异常处理

### 8.1 启动阶段
- 配置缺失（`sync_hosts` 未设置）→ 启动失败
- 数据目录不可写 → 启动失败
- 端口被占用 → 启动失败
- 活跃节点不足半数 → 可启动但拒绝写操作，仅提供读服务

### 8.2 运行阶段
- 节点宕机 → 剩余节点自动调整，读请求故障转移
- 网络分区 → 各分区独立判断仲裁，小分区拒绝写
- 写入超时 → 返回错误，不自动重试（幂等性由客户端保证）
- 读取超时 → 故障转移到下一节点

### 8.3 关闭阶段
- 关闭前完成正在处理的请求
- 关闭网络服务
- 关闭数据存储
