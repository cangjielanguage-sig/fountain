## Step 2：消息体 DataFields 定义

### 内容
创建 `src/server/SyncDataFormat.cj`，定义所有业务消息体的 DataFields 结构体。

### 需要定义的结构

| 结构体 | 字段 | 用途 |
|--------|------|------|
| `SyncData` | key: String, version: Int64, value: Array<Byte> | REGISTER / PUBLISH 请求体 |
| `ValueData` | value: ?Array<Byte> | GET 响应体 |
| `WatchData` | key: String | WATCH 注册 |
| `WatchNotifyData` | key: String, value: ?Array<Byte> | Watch 变更通知 |
| `PatternData` | pattern: String | PREFIX / GLOB 请求 |
| `KeyData` | key: String | DEREGISTER / GET 请求 |

### DataFields 实现模式

每个结构体需要实现：
- `public func encodeTo<D>(data: D): D where D <: DataFields<D>` — 将字段编码到 DataFields 中
- `public static func decodeFrom<E>(data: E): This where E <: DataFields<E>` — 从 DataFields 解码

### 要点
- 参考现有项目中 DataFields 的实现模式（如 f_protocol 的 Message）
- `?Array<Byte>`（None 表示删除/不存在）的编码方式：f_codec 支持 None（type tag = 0）
- 所有结构体声明为 `struct` 而非 `class`（值类型，无 GC 压力）

### 注意
- ⚠️ DataFields 的泛型约束和实现方式需先阅读 f_codec 源码确认接口签名
- ⚠️ `encodeTo` 和 `decodeFrom` 的实现必须保持一致，顺序编码/解码

## Step 3：一致性哈希环（HashRing）

### 内容
创建 `src/server/HashRing.cj`，实现一致性哈希环。

### 核心实现

```cj
public class HashRing {
    private let ring: TreeMap<UInt128, Int64>
    private let nodes: ArrayList<HostAndPort>
    private let virtualNodes: Int64 = 32

    public init(nodes: ArrayList<HostAndPort>) {
        this.nodes = nodes
        for (i in 0..nodes.size) {
            for (j in 0..virtualNodes) {
                let token = "${nodes[i].host}:${nodes[i].port}:${j}"
                ring[murmurHash(token)] = i
            }
        }
    }

    public func getNode(key: String): HostAndPort
    public func getNode(key: Array<Byte>): HostAndPort
    public func getNextNode(key: String, exclude: Int64): ?HostAndPort
    public func nodeCount(): Int64
    public func isOwner(key: String, localIndex: Int64): Bool
}
```

### 要点
- `TreeMap.findGreaterOrEqual(hash)` 是仓颉标准库 API，用于顺时针查找
- `virtualNodes` 设为 32 可减少数据倾斜
- `isOwner` 用于服务端判断当前节点是否为 KEY 的 Owner

### 注意
- ⚠️ `TreeMap<UInt128, Int64>` 需要 UInt128 实现 `Comparable<UInt128>`（需确认）
- ⚠️ 空 ring 时需要防御性检查
- ⚠️ murmurHash 返回的 UInt128 是 `fountain::f_util.UInt128` 类型

## Step 4：节点管理（NodeManager）

### 内容
创建 `src/server/NodeManager.cj`，管理集群节点信息和健康检查。

### 核心实现

```cj
public class NodeManager {
    private let nodes: ArrayList<HostAndPort>       // 所有节点
    private let alive: AtomicInt64                   // 活跃节点数
    private let localIndex: Int64                    // 本地节点在列表中的索引
    private let others: ArrayList<HostAndPort>       // 其他节点
    private let hashRing: HashRing                   // 一致性哈希环
}
```

### 方法

| 方法 | 说明 |
|------|------|
| `init(nodes, localIndex)` | 初始化节点列表和哈希环 |
| `markAlive(index)` | 标记节点为活跃 |
| `markDead(index)` | 标记节点为不可用 |
| `canServeWrites()` | 检查仲裁：`alive > nodes.size / 2` |
| `isOwner(key)` | 检查本地节点是否为 KEY 的 Owner |
| `getOwner(key)` | 获取 KEY 的 Owner 节点 |
| `getReadNode(key)` | 获取可读节点（含故障转移） |
| `healthCheck()` | 后台线程定期 PING 各节点 |
| `allOthers()` | 返回除本地外的所有节点 |

### 要点
- 健康检查线程使用 `spawn` 创建，每秒 PING 所有对端
- `canServeWrites` 为热点路径，`alive` 使用 `AtomicInt64` 避免锁竞争

### 注意
- ⚠️ 健康检查不要使用阻塞 I/O 导致线程卡死，设合理的 PING 超时
- ⚠️ `getReadNode` 的故障转移逻辑需要正确实现（跳过不可用节点 + 跳过自身）

## Step 5：Watch 管理（WatchManager）

### 内容
创建 `src/server/WatchManager.cj`，管理客户端的 Watch 注册和通知。

### 核心实现

```cj
public class WatchManager {
    private let exactWatchers: HashMap<String, ArrayList<WatchEntry>>
    private let prefixWatchers: HashMap<String, ArrayList<WatchEntry>>
    private let globWatchers: HashMap<String, ArrayList<WatchEntry>>
}
```

### WatchEntry

```cj
public struct WatchEntry {
    let pattern: String
    let expiry: DateTime       // DateTime.Max 表示永不超时
    let notify: (Array<Byte>) -> Unit  // 通知回调
}
```

### 方法

| 方法 | 说明 |
|------|------|
| `registerExact(key, timeout, callback)` | 注册精确匹配 Watch |
| `registerPrefix(prefix, timeout, callback)` | 注册前缀匹配 Watch |
| `registerGlob(glob, timeout, callback)` | 注册通配符匹配 Watch |
| `unwatch(key)` | 取消指定 KEY 的所有 Watch |
| `unwatchPrefix(prefix)` | 取消前缀 Watch |
| `unwatchGlob(glob)` | 取消通配符 Watch |
| `notify(key, newValue)` | 通知所有匹配的 Watcher |
| `cleanupExpired()` | 后台线程定期清理超时 Watch |

### 要点
- `notify` 在数据变更时（add/remove）被 SyncHandler 调用，是 Watch 的核心
- WatchEntry 使用回调而非 Channel，避免额外线程开销
- 超时清理使用后台线程，每 1 秒扫描一次

### 注意
- ⚠️ 并发安全：`HashMap` 不是线程安全的，操作 WatchManager 需加锁
- ⚠️ `notify` 调用时不应持有锁，防止回调中死锁
- ⚠️ 同一个 KEY 的多个 Watcher 需排队通知
- ⚠️ 通配符匹配逻辑可复用已有的 glob 实现或使用 std.regex

## Step 6：服务端请求处理（SyncHandler）

### 内容
创建 `src/server/SyncHandler.cj`，实现所有请求的处理逻辑。

### 核心实现

```cj
public class SyncHandler {
    private let store: Store
    private let nodeManager: NodeManager
    private let watchManager: WatchManager
    private let sequence: AtomicInt64

    public func handle(request: Message): Message {
        return match (request.command) {
            case Command.REGISTER => handleRegister(request)
            case Command.DEREGISTER => handleDeregister(request)
            case Command.PUBLISH => handlePublish(request)
            case Command.SUBSCRIBE => handleSubscribe(request)
            case Command.UNSUBSCRIBE => handleUnsubscribe(request)
            case Command.PING => handlePing(request)
            case _ => Message(Command.RESP(...))
        }
    }
}
```

### 处理逻辑

#### handleRegister
1. 检查仲裁 → 不满足返回错误
2. 提取 `SyncData`
3. 生成新版本号 `sequence.incrFetch()`
4. 写入 f_store：`store.add(keyBytes, value)`
5. 写入版本：`store.add(keyBytes + "_version", versionBytes)`
6. 同步到其他节点（异步）
7. 通知 WatchManager
8. 返回 RESP

#### handleDeregister
1. 检查仲裁
2. 提取 KeyData
3. 生成新版本号
4. 删除 f_store：`store.remove(keyBytes)`
5. 写入版本
6. 同步到其他节点（异步）
7. 通知 WatchManager
8. 返回 RESP

#### handlePublish（接收同步）
1. 提取 SyncData
2. 读取本地版本，检查是否为更新
3. 若是新版本 → 更新 f_store
4. 通知 WatchManager
5. 返回 RESP

#### handleSubscribe
1. 提取 WatchData
2. 注册到 WatchManager
3. 在回调中构建 RESP 消息通过 f_net 连接发送
4. 阻塞等待变更或超时

### 要点
- version key 使用 `key.toUtf8() + "_version".toUtf8()` 作为 f_store 的 key
- 同步使用 `spawn` 异步执行，不阻塞主请求处理流程
- 版本号比较：接收版本 > 本地版本才更新

### 难度
这里的难点在于 **Watch 订阅的处理方式**。f_net.Server 的 `executor` 接收一个请求返回一个响应，但 Watch 需要保持连接不立即返回。有两个方案：
1. **方案 A**：在 executor 中阻塞等待，超时或变更后返回
2. **方案 B**：不在 executor 中处理 Watch，手动管理长连接

**推荐方案 A**，因为 f_net 的连接处理线程可以阻塞等待。超时通过 `timeout` 参数控制。

### 注意
- ⚠️ f_store 的 key 和 value 都是 `Array<Byte>`，String 需先 `.toUtf8()`
- ⚠️ 版本号使用 `Int64`，需通过 `std.binary` 编码为 8 字节数组存储
- ⚠️ 同步失败不应影响主请求的返回，错误仅记录日志
- ⚠️ 同步时的版本检查可以避免"写覆盖"问题

## Step 7：服务端网络层（SyncServer）

### 内容
创建 `src/server/SyncServer.cj`，封装 f_net.Server，管理网络服务的启动和关闭。

### 核心实现

```cj
public class SyncServer <: Resource {
    private let server: Server<Message, EncodedMessage, Message, ???, MessageID>
    private let serverThread: Thread

    public init(params: SyncServerParams, handler: SyncHandler) {
        // 创建 f_net.Server
        this.server = Server.build(
            bindAt: params.bindPort,
            checkDuration: ..., checker: ...
        ).build()
    }

    public func start(): Unit {
        this.serverThread = spawn {
            server.start(executor: { msg => handler.handle(msg) },
                        idGetter: { msg => msg.id })
        }
    }

    public func close(): Unit {
        if (!server.isClosed()) {
            server.close()
        }
    }

    public func isClosed(): Bool {
        server.isClosed()
    }
}
```

### SyncServerParams

```cj
public struct SyncServerParams {
    let bindPort: UInt16
    let queueSize: Int64 = 1024
}
```

### 要点
- `f_net.Server` 的泛型参数需要准确映射
- 服务端在 `spawn` 中启动，不阻塞主线程

### 注意
- ⚠️ f_net.Server 的泛型参数较多，需逐一确认类型匹配
- ⚠️ `executor` 的类型签名是 `(DE) -> M`，即 `(Message) -> Message`
- ⚠️ `checker` 是 `(SocketBuffer) -> Bool` 类型的函数，需要正确定义

### 内部辅助方法


## Step 9：SyncCommand（SubCommand 注册）

### 内容
创建 `src/client/SyncCommand.cj`，实现 `f_app.SubCommand` 接口，注册到 `SubCommandMediator`。

### 核心实现

```cj
public class SyncCommand <: SubCommand {
    static init() {
        SubCommandMediator.register(SyncCommand())
    }
    private init() {}

    public prop command: String { get() { 'sync' } }

    public func exec(args: Array<String>): Int64 {
        // 1. 读取配置
        let hosts = SyncConfig.getHosts()
        let dataPath = SyncConfig.getDataPath()
        
        // 2. 解析本地节点索引（从 args 或 host 列表确定）
        let localIndex = parseLocalIndex(args, hosts)
        
        // 3. 初始化 NodeManager
        let nodeManager = NodeManager(hosts, localIndex)
        
        // 4. 初始化 Store
        let store = Store(dataPath)
        
        // 5. 初始化 Handler 和 Server
        let handler = SyncHandler(store, nodeManager, ...)
        let server = SyncServer(SyncServerParams(bindPort: localPort), handler)
        
        // 6. 启动服务
        server.start()
        
        // 7. 等待（阻塞主线程）
        while (true) {
            sleep(Duration.second * 60)
        }
        
        return 0
    }
}
```

### 要点
- 参照 `fountain::f_app.PublishCommand` 的实现模式
- `exec` 函数启动服务后不应退出，使用无限 sleep 阻塞
- 配置通过 `--sync_hosts=...` 和 `--sync_dataPath=...` 传入

### 注意
- ⚠️ `static init()` 在类加载时执行，确保在 `boot()` 调用前注册
- ⚠️ 构造器为 `private`，防止外部误创建
- ⚠️ 启动顺序：先初始化依赖组件，最后启动网络服务
