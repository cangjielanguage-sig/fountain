# 仓颉 SDK / STDX BUG 的处理协议

**适用**：工作流 F / G / H / I / J 的开发过程中（TDD 任一阶段），遇到疑似仓颉 SDK（编译器 / 运行时 / 标准库）或 STDX 的缺陷——而不是自己代码或 API 用法的问题。

## 1. 先确认「是 SDK / STDX 的 BUG」（不确认不生成复现用例）

按顺序排除，全部通过才按 SDK bug 处理：

1. **查文档**：加载 `cangjie-doc-lookup`，查该 API 的签名、约束、版本；确认用法与当前 SDK 版本（`cjc --version`）一致。
2. **查既有用法**：`fountain_lookup.py` / 仓库内同 API 能编译的写法，照它的用法对齐。
3. **缩到最小**：把触发条件缩到 ≤ 30 行单文件——仍失败才是强证据。
4. **排除环境**：同一段代码在融合环境（linux-aarch64/glibc）与鸿蒙侧（ohos-aarch64/musl）表现是否一致？只在一侧失败 → 记下差异（这是重要线索，不等于不是 BUG）。
5. **排除自己代码**：注释掉业务逻辑后复现仍在。

任何一步证明「用法错了」，就改自己的代码，**不走本协议**。

编译器内部错误（`Internal error` / panic / SIGSEGV）、文档承诺与实测行为不一致、同版本同写法在两平台结果不同——按 SDK bug 处理。

## 2. 最小复现用例（repro）

**要求**：

- 能独立运行、不依赖项目代码：优先单文件（`repro-<slug>.cj`，`cjc` 直接编译）；必须依赖包时用最小 cjpm 项目（`repro-<slug>/cjpm.toml` + `src/main.cj`）。
- 代码 ≤ 30 行，只留触发 BUG 的最小语句；文件头注释写清：现象、期望、实际、SDK 版本、平台。
- 附运行命令与完整输出（错误码 / panic / 断言失败）到同目录 `README.md` 或文件头注释。
- 命名：`sdk-bug-<简短英文现象>-<yyyymmdd>`（如 `sdk-bug-generic-overload-20261018`）；单文件加 `.cj`。

**保存路径：先问用户**（AskUserQuestion），给出候选：`~/cangjie-bugs/`、`<项目>/doc/sdk-bugs/`、用户自定义。同一任务内已确认过的路径可直接复用。**不擅自**建在项目 `src/` 或 `openspec/` 里。

**生成后立即显示文件名 / 项目名与完整路径**（一行），作为上报与追溯的锚点；后续 workaround 注释、交付说明都引用这个名字。

## 3. 绕过（workaround）——先继续开发

在不改变设计意图的前提下，按序尝试：

1. 换等价 API / 写法（同语义、不同实现路径）。
2. 规避触发条件（边界值、类型显式化、泛型写法、避免触发编译器的特定模式）。
3. 隔离封装：在适配层加 shim，标记 `// WORKAROUND(<repro 名>)`，注明「SDK 修复后删除」。
4. 版本调整：换 SDK / STDX 版本——**需用户同意**，且不得违反项目既定的版本约定。

绕过必须记录：绕在哪、原写法、替代写法、复现用例名、清理条件。**绕过不等于修好**——verify 报告与交付说明里保留这条记录。

## 4. 绕不过：报告进度并暂停

输出阻塞报告，然后**停**（不继续猜、不跳步、不伪造进度）：

```
【SDK/STDX BUG 阻塞 · 暂停】
复现用例：sdk-bug-<slug>-<yyyymmdd>（<完整路径>）
现象：<一句话>；期望：<…>；实际：<…>
OpenSpec 进度：变更 <变更名>，当前步骤 <①–⑥>；tasks <x/y>
TDD 进度：当前任务「<任务名>」——<测试已红 / 实现中 / 待回归>；已完成并转绿的任务 <n> 个
已尝试的绕过：<列表与结果>
需要你决定：<换方案 / 等 SDK 修复 / 调整范围 / 其他>
```

暂停期间保持复现用例与现状，不改代码；用户给出方向后才继续。

## 5. 红旗

| 你正想做 | 现实 |
| --- | --- |
| 报错就当 SDK bug，直接写复现用例 | 先查文档 / 既有用法 / 缩最小 / 排除环境；用法错就改自己代码 |
| 复现用例塞进项目 `src/` 或 `openspec/` | 先问用户保存路径；复现用例是独立资产，不是项目产物 |
| 生成了复现用例但不告诉用户名字 | 必须显示文件名 / 项目名与路径（上报与追溯的锚点） |
| 绕过后不留记录 | `WORKAROUND(<repro 名>)` 必须写清；verify 与交付说明保留 |
| 绕不过就静默跳过 / 伪造进度 | 报告 OpenSpec + TDD 进度并暂停，等用户决定 |
